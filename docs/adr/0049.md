# ADR 0049: the ABI check at host start (P24-5d)

Status: Proposed (decided in the P24-5 session; confirm at the next design review).
Design: Rev 3.45 is frozen (section 11.2, firmware design note 4: "fw_version and the ABI version are reported and checked against abi.json at host start (sessions.fw_version exists)"; 14.5 start-up failure policy: exit 2 for a configuration failure). Nothing in the frame, the migration, `constants.json`, the settings keys or the serial JSON changes.

- **What is checked.** The host parses every frame and beacon with `host/ppe_host/abi.py`, which `tools/gen_abi.py` writes from `shared/abi.json`. At start-up step 1 the host rebuilds the values of `abi.py` from `abi.json` and compares them: the frame and beacon sizes, the beacon `abi_ver`, the CRC-8 polynomial, start value and ranges, every field's offset, size and sign, every named bit, the reserved-bit masks and the enums. A difference means a stale or hand-edited `abi.py`, or a folder mixed from two builds, and the host would read safety bits (man-down, fault, SCBA) from the wrong place without any error.
- **Refusal (decision).** Any difference refuses the start with exit 2 and a message that names each differing value (`ABI mismatch: host/ppe_host/abi.py differs from shared/abi.json in BEACON_ABI_VER (abi.py 3, abi.json 4); run python tools/gen_abi.py or use the files of one build`). A `shared/abi.json` that cannot be read or does not have the layout of design 12.1 also refuses with exit 2 (`ABI check failed: ...`): the host does not run on an ABI it cannot check. The check runs in all three modes, because the parser is the same in SIMULATOR and REPLAY.
- **Where.** `services/abi_check.py` (`expected`, `load`, `mismatches`, `AbiError`), called in `startup()` straight after the settings and the CMAC key and before the lockfile, so a refused start leaves no lockfile, no database file and no session row. The rules of `expected()` repeat those of `tools/gen_abi.py render_py`, because `tools/` is not in a release folder; `test_abi_check.py` fails when `abi.py` gains a value that `expected()` does not cover or when the committed files stop agreeing. `test_gen_abi.py::test_generated_files_are_current` already catches a stale `abi.py` in the repository and in CI; this check is the one that runs on the deployed machine, where `tools/` and pytest are absent.
- **Why only exit 2.** The supervisor counts exit 2 toward the crash-loop guard (ADR 0046), so a bad build stops after a few restarts instead of running. A banner or a log row alone was rejected for this check: the dashboard would show a normal page while frames are mis-parsed.
- **OPEN: the firmware side and `fw_version`.** The design says the firmware's version and ABI are "reported", but nothing carries them to the host. The frozen serial JSON (`hb`, `frame`, `host_tick`) has no version field, the node frame has no ABI byte (only the beacon the host sends has `abi_ver`), the settings table has no `fw_version` key and `build_manifest.json` holds `esp_idf_version` but no firmware build tag. So a firmware mismatch cannot be detected today, and `sessions.fw_version` stays NULL (ADR 0029). It is not built here, because every source would change a frozen part of the design. Options, for a design review: (a) the base adds `fw` and `abi` to its heartbeat (firmware and serial JSON change; the host then compares and records the value); (b) a new settings key `fw_version`, recorded in `sessions.fw_version`, with no check (settings table change; the key must also go into `HASH_EXCLUDED`, or the hash changes and the open session is closed); (c) leave it out of the product. My suggestion is (a), with the rule: a different `abi` refuses to start, a different `fw` only writes a system_events row and shows a banner. Please confirm.
- **Not here.** A row for the ABI in `cli doctor` (the doctor test fixes eleven rows; the start-up refusal already reports it) and a check of `firmware/components/abi/abi.h` and `dashboard/src/gen/abi.ts` (`test_gen_abi.py` and CI compare all three generated files with `abi.json`).
