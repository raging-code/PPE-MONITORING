# ADR 0006: REST shell decisions for P19 (P19-1)

Status: Proposed (decided in the P19-1 session; confirm at the next design review).
Design: Rev 3.45 is frozen. Nothing in the frame, the migration or `constants.json` changes.

- **Split:** P19 was about 480 lines against the 350 limit. P19-1 is the shell, login and `GET /api/events`. P19-2 is session start and end, Acknowledge and Resolve. P19b (security) and P19c (the rest of the frozen list) are unchanged.
- **Port seam:** `api_rest.py` talks to the host through a `Port` (`authenticate`, `audit`, `session_id`). The engine, the writer and the one `event_seq` counter stay with the host process, so audit rows get their `event_seq` from it (P24 implements the port). P19b supplies the real `authenticate`.
- **Deferred to P19b:** the failed-login backoff (a failed login answers `retry_after_s` null until then), the Origin and Host check (`ORIGIN_REJECTED`) and token hashing.
- **No `/docs`, `/redoc` or `/openapi.json` routes:** the endpoint list is frozen and a test counts routes in P19c. `shared/openapi.json` is exported from `app.openapi()`, which works without the route, once P19c has every endpoint.
- **Envelope mapping:** a route that does not exist is 404 `NOT_FOUND`; a wrong method (405) uses `BAD_REQUEST`, because the 3.8 list has no 405 code; any unhandled error is 500 `INTERNAL_ERROR` with a fixed text and no exception text. A 422 names only the field and the rule, never the submitted value.
- **Events paging:** after reading `limit` rows, if the last `event_seq` may continue, that `event_seq` is read again in full, so a page can hold more than `limit` rows and never splits a seq. `last_seq` is the last row's `event_seq`, or `after_seq` when there are none.
