# ADR 0019: NO LIVE DATA watchdog, Silence 60 s and the browser siren (P22c-1)

Status: Proposed (decided in the P22c-1 session; confirm at the next design review).
Design: Rev 3.45 is frozen. Nothing in the frame, the migration, constants.json, alert_catalog.json, hotspots.json or ws.schema.json changes.

- **P22c is split into five stages (proposed):** P22c-1 worker watchdog, siren and outage report (this one); P22c-2 Test sound and Start monitoring gate (wake lock, Web Lock owner, SIREN OFF, Screen may sleep, hidden-tab banner); P22c-3 system banners, TEST or REPLAY bar, empty states and NOT READY; P22c-4 Resolve dialog (replaces the inline form of P22-3), Sessions list, End shift summary; P22c-5 CO chart and layout at 1366x768 and 150% zoom. Playwright rows stay in the e2e stage.
- **The worker judges both sockets (3.7):** it opens its own authenticated `/ws/tick` socket (reusing `LiveSocket`, with the new `noHb` option because only `/ws` takes a heartbeat) and the main thread posts `DATA_ALIVE` for every message on `/ws`. NO LIVE DATA shows when either socket delivered nothing for `dashboard_stale_s` (4 s, from `constants.json`). A worker timer runs every 250 ms and is not throttled like a hidden tab's page timers.
- **Server timestamps:** a tick whose `srv_ts` jumped by 4 s or more since the previous tick proves the host stalled and does not count as a sign of life. After a real outage the first tick is such a jump, so the screen clears one tick (about 1 s) after the host is back. Proposed; the design says only "judges from server timestamps".
- **Arming:** the 4 s count starts at `INIT_AUTH` (login or reload), so a host that never answers also shows NO LIVE DATA. `STOP` (the Login or Forbidden page) and a rejected tick token disarm it, so Login never shows a red screen.
- **Silence 60 s (3.3):** the worker owns the timer. Silence is ignored unless NO LIVE DATA is showing; it re-arms by itself at 60 s while the host is still down, and recovery drops it. The 60 s is a module constant (`SILENCE_MS`) because `constants.json` has no key for it (same approach as ADR 0001).
- **Overlay:** the red screen goes over the live screen when the page still looks connected (a blocked data socket), and replaces the "Connecting" page as before. The P21b main-thread 4 s placeholder stays as the fallback when no worker runs.
- **Siren:** one looping 1 s buffer (700 to 1100 Hz wail) on the Web Audio clock; no page timer repeats it. It plays only when the worker says so and `audioStore.unlocked` is true. Nothing sets `unlocked` until the Start monitoring click of P22c-2, so until then the red screen says "Browser siren off: click Start monitoring". The host alarm does not depend on this (3.12).
- **Outage report (3.8):** when the worker sees NO LIVE DATA end, it posts `OUTAGE {started_ts, ended_ts, duration_s}` in UTC ms; the main thread sends `POST /api/dashboard-outage`. A network failure or 5xx is retried every 1000 ms (60 tries); any other answer ends it. `started_ts` is the oldest last-good mark, clamped so the duration is at most 86400 s. A report not yet sent is kept in memory only: a reload loses it. Proposed.
- **Worker threshold:** the worker reads `dashboard_stale_s` from the generated constants, not from the snapshot, because it has no snapshot.
- **Not done here:** the Start monitoring button, Test sound, wake lock, Web Lock and SIREN OFF banner (P22c-2); Playwright rows (NO LIVE DATA at 4 s with the tab hidden, only the data socket blocked) need a real browser.
