# ADR 0055: the host serves the built dashboard (P24-6)

Status: Proposed (implements design 1 and 1.5; confirm at the next design review).
Design: Rev 3.45 stays frozen. No wire message, endpoint, setting, migration or constants.json change.

- **Gap.** Design 1 says the host serves the prebuilt dashboard and the API from one origin, and `cli doctor` checks that `dashboard/dist/index.html` exists, but no code in `host/ppe_host` served it (found in P24-5g, ADR 0047). Without it the operator has no page at http://127.0.0.1:8420.
- **Module.** `host/ppe_host/api/static_site.py` is a plain ASGI app, not Starlette's StaticFiles: the rules below are ours, and a small file is easier to test with hostile paths. `serve.build_app` mounts it at '/' after `create_app` and `install(app, hub)`, so every API route and the /ws sockets are matched first. The directory is `<PPE_HOME>/dashboard/dist`.
- **What is served.** GET and HEAD. '/' is `index.html`. Every other case is the usual 404 NOT_FOUND envelope with the same three fields as the API: a missing file, a directory, a path whose first segment is `api` or `ws`, a segment that starts with '.' (this covers '..', `.gitkeep` and `.env`), is empty, ends with '.' or ' ', contains ':' or a backslash or a control character, a symlink that resolves outside dist, and every other method (404, not 405).
- **Content type** comes from a fixed table (html, js, mjs, css, json, map, svg, png, jpg, gif, webp, ico, woff, woff2, txt, webmanifest); anything else is application/octet-stream. Python's `mimetypes` is not used, because on Windows it reads the registry and a machine that maps .js to text/plain makes the browser refuse the module.
- **Headers** on every answer, the 404 included: the Content-Security-Policy of design 1 (with `bind_port` in the two ws:// sources), `X-Content-Type-Options: nosniff` and `Referrer-Policy: no-referrer`. `index.html` is `Cache-Control: no-store`; other files are `no-cache`, so a new build is picked up at once (hashed assets could be cached for longer; that is left for later).
- **Origin and Host** still apply: the mount sits inside the app, so the P19b middleware rejects a wrong Host or Origin on a page request before any file is read.
- **Missing dist** is one warning at start-up and not a stop. The API and the audio keep running, the page 404s, and a build made later is served without a restart.
- **Checked here (development sandbox, Linux).** `host/tests/test_static_site.py` (66 tests, all ran, real FastAPI and Starlette) covers headers, types, HEAD, 21 hostile paths, a symlink out of and inside dist, encoded traversal through the real app, the origin check, API routes winning over the mount, the /ws path, and `build_app` mounting last. The full host suite gave 1525 passed and 1 failed: `test_open_state.py::test_both_queries_use_their_indexes` fails on the unmodified zip too (the SQLite 3.45.1 plan reads `SCAN episodes`). Ruff is clean. A real Uvicorn on a real port served the real vite build file by file (index no-store, assets no-cache, `.gitkeep` and unknown paths 404) and a WebSocket opened on /ws.
- **Not here.** A browser run: the CSP is design 1's text and no blocked resource was seen in the bundle (one module worker, one WebSocket, same-origin fonts), but only a browser console can confirm it. A Windows run. Serving over TLS (Tier 2).
- **Open, please confirm.** (1) After `just build`, open http://127.0.0.1:8420 once with the browser console open and report any CSP line. (2) Whether hashed assets should get a long `Cache-Control` (not needed on a local host).
