# ADR 0053: two ABI rows in cli doctor (P24-5h)

Status: Proposed (the `cli doctor` row that ADR 0050 and ADR 0051 left open).
Design: Rev 3.45 design 1 (Release bundle and doctor) lists no ABI row, so both rows are extra to the design's list, like the sound files and settings rows of ADR 0047. No frozen contract changes: no wire field, no migration, no setting, no new exit code.

- **Row `host ABI`.** `services/abi_check.mismatches()` on the `shared/abi.json` of the folder doctor runs in, against the `abi.py` that is installed. It is the check the host makes at start (ADR 0049), so a folder mixed from two builds is found before the shift instead of as exit 2 at the start. FAIL names up to three differing values, or says that `abi.json` cannot be read or has the wrong layout. It needs no settings, so it is a normal row when the settings are unreadable.
- **Row `base ABI`.** doctor never opens the serial port (ADR 0047), so it cannot ask the base. It reads what the host recorded: the newest `ABI_MISMATCH` or `ABI_OK` row of the newest session. `ABI_MISMATCH` last is a FAIL with the session number and the detail the host wrote (both numbers); anything else is a PASS "no ABI mismatch recorded". No database, no session, or a database that cannot be read is a SKIP, which never fails the command. The database is opened with the same read-only rule as the quick_check row, so nothing changes, also on a WAL database.
- **What the PASS does not say.** A match is not logged (the first agreeing heartbeat is silent, ADR 0050) and old firmware sends no `abi`. A PASS therefore means "no mismatch recorded", not "the base reports its ABI and it is right". The only live check is the ABI_MISMATCH banner while the host runs (ADR 0051).
- **The FAIL can be out of date.** After the base is reflashed, the row stays FAIL until a session whose heartbeat does not report a mismatch has run, because only the newest session is read and a matching heartbeat writes nothing. The FAIL text says so. Reading the newest session only (not the newest ABI row of all sessions) is what lets one clean session clear it.
- **Order.** `host ABI` follows `release version`; `base ABI` follows `database quick_check`. A good machine with one earlier session passes 13 rows.
- **Open for the operator.** (1) A FAIL from the last shift stays until the next shift has run; the alternative is a SKIP "reflash, then run a short session" and no FAIL. (2) A machine with no session yet shows a SKIP, not a PASS. (3) The two rows are not in design 1's list.
- **Not here.** The firmware change (`fw` and `abi` on the `hb` line) [BENCH]; the missing 3.4 row for `abi_mismatch` and `audio_fault` (design change).
