# ADR 0025: Event log and CSV (P22d-2)

Status: Proposed (decided in the P22d-2 session; confirm at the next design review).
Design: Rev 3.45 is frozen. Nothing in the frame, the migration, constants.json, alert_catalog.json, hotspots.json or ws.schema.json changes.

- **Fill and follow (3.11):** `store/eventlog.ts` asks `GET /api/events` from the last sequence number it holds (0 after a reload), page by page (the host's maximum, 1000), until a short page. `components/EventLog.tsx` asks again `REFRESH_MS` (500 ms) after any live alert, episode, system or advisory message changed the store, so a burst is one request. The host's rows are the only source: the dashboard does not build log rows from live messages (they carry no `event_seq`, so they could not be merged without duplicates). A failed call keeps the rows already shown and offers "Reload event log".
- **No "tail" call (Proposed, needs the host):** `GET /api/events` only reads forward from `after_seq`, so a reload on a 24 h database pages through every row (the 500 newest are kept). A `before` or `tail` parameter would make this one call. Not added: the endpoint list is frozen.
- **Numbers that are mine, not the design's:** 500 rows kept in memory, 100 rows drawn, 500 ms refresh wait, 20 pages at most per run. They limit memory and request rate only; no threshold is involved.
- **Rows (3.10, 3.11):** newest first, Manila 24-hour clock time only. Text is built from the row's code (underscores to spaces), level and the alias; the operator shows as "operator N" because v_events carries only the id. The frame measurement columns and `raw_hex` are never in this view (the endpoint does not return them).
- **Rejected frames (3.11, H7):** one line "N frames rejected (authentication): check key", from the system message's `rejected_frames`, shown only when N is above 0. The count is not a log row.
- **Diagnostics (Proposed):** the design gives no content for the "optional diagnostics view". Built as a toggle, off by default, that adds the record type, code and event_seq columns. **Please say what else it should show** (per-reason counts of bad length, CRC and MAC need a host field that the frozen system message does not carry).
- **CSV (3.8):** an authenticated `fetch` of `/api/export.csv?session_id=<current session>`, then a blob and an object URL (`downloadCsv`, from P22c-4). The route itself is P26, so until then the button reports "The CSV could not be downloaded. Try again." The CSV is of the current session; the all-sessions file (no `session_id`) is not offered here.
- **Layout:** the log is the last block of the scrolling readings area, with its own error boundary ("Event log unavailable"). It does not scroll inside itself. All its buttons are 44 px high.
- **Not here:** hotspot and 3D parts, the Model status panel (Tier 2).
