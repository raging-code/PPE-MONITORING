# ADR 0068: AlertCard heading button and the accessibility lint rules

Status: Proposed (decided in the design-review preparation of 2026-11-28; builds the decision recorded in ADR 0043; confirm at the next design review).

Design: Rev 3.45 stays frozen. Design 8 asks for keyboard operation. No host, wire, endpoint, setting, migration or constants change.

- **Problem (ADR 0043).** `AlertCard.tsx` selected the node of a card through a click handler on the `<section>`, which a keyboard user cannot reach. Biome's accessibility rule `useKeyWithClickEvents` flags it, but the rule was not in the rule set, so the lint stayed green.
- **Honest scope.** The node cards in the node list are already buttons with `aria-pressed`, so a keyboard user could already select a responder from there. The fix adds a direct path from the alert card itself; it does not close a hole that left the keyboard with no way to select a node.
- **Decision.** For a responder card with a node, the heading (level icon, level word, alias) is one real `<button type="button">` that calls `onSelect`, with `stopPropagation` so the card click does not fire a second time. The card-wide click stays for the mouse. The `<section>` gets no `role` and no `tabindex`, so Acknowledge, Resolve, Minimize and Dismiss are not nested inside another interactive element. A card without a node id keeps a plain heading. The button keeps the 44 px minimum height of the other card buttons. Slim and unverified cards have no heading and no change.
- **Lint rules.** `a11y.useKeyWithClickEvents`, `a11y.useButtonType` and `a11y.useAltText` can be turned on with `--with-a11y-rules`, together with one `biome-ignore` comment on the card section that says why the card-wide click stays. They are a second step because Biome could not be run when the patch was written; if the lint lists new errors, fix them or leave the rules out. `AlertCard.tsx` was the only element in `src` with a click handler on a non-interactive tag when this was written.
- **Tests.** `tests/alert_card_keyboard.test.tsx` (4 tests): the heading holds a real, focusable button; pressing it selects the responder; the card has no role and no tabindex; a non-responder card has no heading button. jsdom does not turn the Enter key into a click, so the key press itself is left to a browser check.
- **Not covered.** A real keyboard walk in a browser (Tab to the heading button, Enter, the selected node card highlights).
