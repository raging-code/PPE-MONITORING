# ADR 0047: cli doctor, the pre-shift check (P24-5b)

Status: Proposed (decided in the P24-5 session; confirm at the next design review).
Design: Rev 3.45 is frozen (section 1, "Release bundle and doctor", Rev 3.43: `python -m ppe_host.cli doctor` prints pass or fail for the release version, the base serial device, the audio device, free disk (`host_disk_min_gb`), port 8420, the prebuilt dashboard, `secrets.json`, `PRAGMA quick_check` and the lockfile, and changes nothing). No host behaviour, frame, migration, constant, setting or REST route changes. P24-5 is split in three: P24-5a (ADR 0046, the supervisor), this part, P24-5c (`cli ack --node N`, and the `fw_version` / ABI check).

- **Where.** `host/ppe_host/services/doctor.py` holds the checks and `cli.py` one command, `doctor`, with the usual `--home` and `--db`. Every check is a function; `run_checks()` takes the serial list, the port probe, the sound backend and the platform as parameters, so the tests need no device.
- **Output.** One line per check, `doctor: PASS|FAIL|SKIP <name>: <detail>`, then `doctor: N passed, N failed, N skipped`. Exit 0 when nothing failed (a SKIP never fails), exit 1 when a check failed. Secrets are never printed: a bad key is named, not shown.
- **The eleven rows.** release version; settings (not in the design's list, but every path and limit comes from it; when the settings cannot be read it is one FAIL and the six checks that need them are SKIP); base serial device; sound files (the manifest check of 3.12); audio device; free disk; port; prebuilt dashboard; `secrets.json`; database quick_check; lockfile.
- **Release version.** `build_manifest.json` in the release folder (or `dist/` in the repository) must exist, hold a `rev_tag`, and its `constants_sha256` must equal the hash of this folder's `shared/constants.json`, so a folder mixed from two builds fails. In a repository checkout without `just build` this row is a FAIL by design: doctor is a release check.
- **Base serial device.** The configured port must be in the system's list of serial ports (pyserial `list_ports`, names compared without case on every system). The port is **not opened**: opening would pulse DTR or RTS and reset an ESP32, and would fail while the host holds the port. `serial_port: "auto"` is a FAIL with the way out, because auto-detection (USB vendor and product ID, Rev 3.43) is **not built** (OPEN, below).
- **Audio device.** On Windows the 100 ms silent `probe.wav` is played synchronously through the same backend the host uses; a RuntimeError is a FAIL. Elsewhere the row is SKIP, because the host alarm uses `winsound`. The sound files row is separate and runs everywhere.
- **Free disk.** On the disk that holds `db_path` (the nearest existing folder), against `host_disk_min_gb`.
- **Port.** A connect to `bind_host:bind_port`, never a bind, so nothing is taken. Free and no live lockfile: PASS. In use and no live lockfile: FAIL (another program). Live lockfile and something listens: PASS (the host). Live lockfile and nothing listens: FAIL.
- **Database.** A missing file is PASS (the first start creates it). Otherwise `PRAGMA quick_check` on a connection that creates nothing: a read-only connection to a WAL database would still create empty `-wal` and `-shm` files, so while neither exists the file is opened `immutable`, and while one exists (the host is running or stopped without closing) the normal read-only connection is used. A test checks that a WAL database leaves the folder byte-for-byte as it was.
- **secrets.json.** Missing or a bad `cmac_key` is a FAIL. A missing `server_salt` is a FAIL only when operators exist (the host then exits with code 2, 14.5 (d)); with no operator yet it is a PASS that says `create-operator` makes it.
- **Lockfile.** Informational: none, the host is running (PID), or stale and replaced at the next start. It does not fail, because the design's start-up rules already handle all three.
- **Checked here (development sandbox, Linux).** `host/tests/test_doctor.py` (20 tests) ran under a minimal stand-in for pytest (no network): all eleven rows pass together; each FAIL path; `auto`; case-insensitive port names; the probe played synchronously and the Linux SKIP; the port rows with a real lockfile of the test process and a real listening socket; the key never printed; the WAL cases above; the settings failure with its SKIP rows; the command's exit codes. The command also ran on an empty folder (4 FAIL, as expected). **Not run:** the full pytest suite, ruff, Windows (real COM list, real sound card, a real running host).
- **Not here.** `serial_port: auto` itself; the second-PC test of the release folder and `doctor` (the guide's section 6); checking the free space of `backup_dir` or `second_drive_dir`.
- **Open, please confirm.** (1) `serial_port: auto` is a FAIL until a part builds it. (2) The release row fails in a repository checkout. (3) The lockfile row never fails. (4) The sound files row is extra to the design's list, as is the settings row. (5) The doctor tests carry no requirement id, because design 8 has no row for doctor; say if one should be added to `requirements.yaml`.
- **Found while reading the code (not changed here).** `host/ppe_host` has no code that serves `dashboard/dist` (no static files route), although design 1 says the host serves the prebuilt dashboard. `doctor` only checks that `dashboard/dist/index.html` exists. If the dashboard is meant to be reached at `http://localhost:8420` in the release, a part must add it.

- **Note (ADR 0055, P24-6).** The finding that no code in the host served `dashboard/dist` is resolved: `api/static_site.py` serves it from the API origin.
