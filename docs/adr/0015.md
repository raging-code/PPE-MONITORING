# ADR 0015: alert catalog loader, badge rule and tray order (P22-1)

Status: Proposed (decided in the P22-1 session; confirm at the next design review).
Design: Rev 3.45 is frozen. Nothing in the frame, the migration, constants.json, alert_catalog.json or ws.schema.json changes.

- **Catalog source:** the dashboard imports shared/alert_catalog.json directly (tsconfig resolveJsonModule, vite server.fs.allow for the parent folder) and validates it in loadCatalog. There is no generated copy, so the host, the dashboard and the test read one file. A bad catalog throws at start-up and fails the test.
- **Badge rule (3.2):** a node's badges are its uncleared alerts except the hotspot-and-log-only types (wrist_open, wrist_close), sorted by (level_rank DESC, badge_order ASC, alert_id ASC), at most 2. An early-warning estimate counts, because the 3.2 order list names it.
- **Tray rule (3.3):** a card exists for show = card, card_or_notice (only at WARNING; a fall-only check-in at NONE is a notice), dashed_card and slim_card. A safety or security alert stays until it has cleared and been acknowledged, so a cleared one shows as "cleared". An estimate leaves when it clears. Order is danger before warning, then oldest first, then alert_id. Slim cards are returned apart, to sit under the safety cards.
- **Close rule:** every tray card can be minimized. Only the advisory class (estimate) can be dismissed; a safety or unauth_alert card cannot, even if its id is in the dismissed set.
- **Unknown type:** a type the catalog lacks is shown as a safety card and a badge, never dropped.
- **Missing value in text:** renderText shows "?" for a placeholder with no value, never a raw "{co_ppm}" and never a guessed number.
- **Design gap, proposal:** table 3.4 of Rev 3.45 has no row for the audio_fault banner, although its own completeness rule and 3.12 (d) need one. The test for it is marked it.fails and reports as passing while the row is missing. Proposed row: AUDIO FAULT (system) [audio_fault] | The host audio self-check fails: a playback call raises, or (optional) the endpoint is muted or below host_volume_min_pct (3.12) | AUDIO FAULT: host alarm sound cannot play, check the speakers | None (visual only, 3.3) | Banner (system_events only; never in alerts table). When it is added to the design, Vitest reports the unexpected pass and ".fails" is removed.
- **Text differences (no action):** the 3.4 examples read "CO SENSOR FAULT: reading unknown" and "NODE REPORTS DANGER: cause not identified by host"; the catalog reads "SENSOR FAULT: reading unknown" (the type also covers IMU and temperature faults) and "...cause not identified". The catalog wins, and the test checks sound and Shows-as, not the example wording.
- **Not done here:** card and chip components, repeat counts, the selected-jacket rule (P22-2); Acknowledge and Resolve calls and persistence (P22-3).
