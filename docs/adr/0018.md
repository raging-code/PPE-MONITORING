# ADR 0018: flat component grid, fault map and error boundary (P22b)

Status: Proposed (decided in the P22b session; confirm at the next design review).
Design: Rev 3.45 is frozen. Nothing in the frame, the migration, constants.json, alert_catalog.json, hotspots.json or ws.schema.json changes.

- **Flat grid is the Tier 1 jacket view (3.1, 3.13):** one row per component of the selected responder, with its value and state, in the order of `shared/hotspots.json`. No 3D, no .stl. The grid follows the selected jacket (node card click or alert card click).
- **Fault map (3.10):** `jacket/hotspots.ts` holds the map as code and as data. `LISTED` is table 3.10 column 2 (the bits each hotspot may react to). The test flips every bit of id_mode, flags, status2, status3 and status4 against a quiet baseline and fails if a hotspot changes on a bit it does not list. Bits no hotspot lists (node id, posture, restored, reset cause, still_now, latch restored, MAYDAY, reserved) change nothing.
- **Colour only for a real state (3.6):** grey for an unreliable or unknown reading, yellow for WARNING, red for DANGER, white for normal. Every coloured row also has an icon and a word.
- **Open, please check against the ABI header (3.10 itself asks for this):** the CO row lists status2 bit 5 (IMU fault), but design 14.2 makes CO unreliable on bit 4 (CO fault) and bit 6 (SHT40 fault) only. The grid follows 14.2: bits 4 and 6 grey the CO row, bit 5 greys the IMU row. The host's `co_validity` UNRELIABLE also greys the CO row, because it covers the cases with no bit (CO timeout, co_range). Bit 5 stays on the CO list, so nothing reacts outside the table.
- **Man-down wins over an IMU fault (Proposed):** a latched man-down shows red "MAN-DOWN" on the IMU row even when the IMU fault bit is set, so a fault never hides a latch. 3.10 does not rank the two.
- **Wrist:** an open connector (status4 bit 0) is a quiet "disconnected". "wrist lost" (WARNING) shows only when the connector is mated and status2 bit 1 is 0.
- **Heat:** the SHT40 row takes the level of an uncleared heat alert of that node; a temperature fault (grey) wins over it. This is the only alert-driven colour, because it is the only one 3.10 lists.
- **Battery:** WARNING at `bat_warn_pct` or less (from the snapshot constants, falling back to the generated ones); status2 bit 2 alone is a quiet "low" word.
- **Wording (Proposed, no design text):** "CO unknown", "IMU unknown", "temperature unknown", "wrist lost", "disconnected", "link OK, base not heard" (id_mode link_ok = 0), "MISSED EVENT", "ready", "off" and "invalid" for the buzzer row. "500+ ppm" uses `co_clamp_max_ppm`.
- **Error boundary (3.7):** `JacketView` wraps the grid in a React error boundary, keyed by node id. A failing grid is replaced by the line "Jacket view unavailable" and nothing else on the screen changes: node cards, alert cards, Acknowledge and Resolve sit outside it. A failure on one responder does not hide the grid of the next. The `webglcontextlost` listener belongs to the 3D view (S7) and is not built.
- **Not done here:** hover or click on a row highlighting a side panel row, last seen on the radio row, and the side panel itself (P22d); the 3D view and the hotspot placement mode (S7).
