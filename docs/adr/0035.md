# ADR 0035: Start-up step 10, the 1 Hz driver, the thread bridge and the AudioThread in the host (P24-3c-3)

Status: Proposed (decided in the P24-3c-3 sessions; confirm at the next design review).
Design: Rev 3.45 is frozen (14.5 start-up step 10, thread map, 3.12). Nothing in the frame, the migration, `constants.json`, the settings keys or `api/models.py` changes.

- **Split of P24-3c-3 (done).** Part 0 check of the zip; Part 1 code (`serve.py`, `LoopHub` and `Runtime.tick()` in `runtime.py`, step 10 in `main.py`); Part 2 `host/tests/test_serve.py` (22 tests) and the two old `main()` tests given a no-op `serve`; Part 3 the AudioThread wiring and `host/tests/test_audio_wiring.py` (18 tests); Part 4 this ADR and the patch. The OS watchdog (`OSWatchdogThread`, `Hub.on_tick`, `LIVENESS_RESTART`, `TICK_STALL`) and the host health events stay with P24b.
- **Step 10 (`serve.py`).** `build_app(rt, loop)` builds `HostPort`, `Hub` (bind port, queue and timeout settings), the FastAPI app (`create_app` plus `install`) and a `Wire`, turns the Tier 1 advisory on (`advisory_heartbeat_s`, as ADR 0033 said 3c-3 would) and sets `rt.port` and `rt.wire`. `run_server(rt, host, port)` starts Uvicorn (`bind_host`, `bind_port`), waits until it accepts connections, and only then starts the 1 Hz driver, so no tick runs before the API is up. On shutdown the driver stops first, then Uvicorn closes the sockets. `main()` takes `serve` as an argument so tests do not start a server.
- **Exit codes (decision, operator: "you design in the exit code").** Uvicorn cannot bind its port: `ServeError`, `main()` prints "step 10 failed: ..." to stderr and exits with code 2, because the cause does not go away on an immediate retry and 2 counts toward the crash-loop guard (5 non-zero exits within 60 s). Any other failure in step 10 exits with code 1, as before. Both paths stop the runtime, close the database and release the lockfile. Uvicorn's own `sys.exit(1)` after a failed bind is turned into `ServeError`.
- **The 1 Hz driver.** `tick_driver` calls `Runtime.tick()` on a fixed 1 s grid in a worker thread (`asyncio.to_thread`), because `Wire.tick` waits up to `commit_wait_ms` for the writer and must never block the event loop. A tick that overruns does not shift the grid and is not made up by a burst. `Runtime.tick()` runs host_tick to the base, `Health.tick`, the audio feed, then `Wire.tick`, each guarded: one failure is logged and the others still run. `Hub.tick_loop` is unchanged; `Hub.on_tick` stays unset until P24b uses it for the liveness stamp.
- **Thread bridge (`LoopHub`).** The Hub and its queues belong to the event loop, but `Wire.on_frame` runs on the SerialReader thread and `Wire.tick` on a worker thread. Wire gets a `LoopHub` that hands every `publish_*(body)` to the loop with `call_soon_threadsafe`, in call order; a missing method stays missing (so `Wire._pub` still works); after the loop has closed a publish is dropped. To confirm: a message queued this way can reach a client after a snapshot that already contains it. Readings, alerts and episodes carry ids or are replaced whole by the client, so this is expected to be harmless, but the dashboard rule for a message older than the snapshot should be checked in P22.
- **AudioThread in the host.** `AudioThread` (P23b, ADR 0027) was complete; this part only wires it. `Runtime(..., audio_backend=...)` builds it (None means no thread, as in most tests), step 8 starts it after the serial threads, and `Runtime.stop()` ends it first. `main()` passes `WinsoundBackend()` through `make_audio_backend()`; `tests/conftest.py` replaces that function with a silent fake, so no test touches the sound card. On a machine without `winsound` or a sound device the thread raises AUDIO_FAULT, as 3.12 says.
- **What the host sounds (`Runtime.audio_items()`).** Every open alert of the engine state with its level and `acknowledged_ts`, plus BASE OFFLINE (the Health flag, never acknowledgeable), LOGGING FAULT and HOST GAP (acknowledgeable through `banner_state`). It reads only immutable engine state and flags, so any thread may call it.
- **When it is fed.** `Wire.on_change` is called first in `on_effects` (before the database reads of `_send`, and also while a unit is held for a slow commit), on every `Wire.tick`, and when a banner is acknowledged. `Runtime.load_open()` feeds it once after step 9, so an open alert restored from the database sounds from the start, and the 1 Hz tick feeds it again as a safety net. The alarm therefore follows the engine, not the commit: it can start up to `commit_wait_ms` earlier than the dashboard message. The 300 ms test of 3.12 passes through the real `Wire` hook.
- **Fault events and flag.** The thread's `on_event` writes AUDIO_FAULT once per fault and AUDIO_OK once when the last cause clears, as system events (`Ingest.system_event`). `Wire` reads `audio_fault` from the thread, so the AUDIO FAULT banner flag reaches the next system message within one second.
- **Zero-socket inputs.** `sockets_fn` and `monitoring_fn` are connected in `build_app`, so the warning of ADR 0026 is armed only once the hub exists. `tab_counter(hub)` wraps `Hub.connected_tabs` for the AudioThread: the loop changes the socket set while the thread counts it, so a `RuntimeError` is retried three times and then counted as one connected tab, because a wrong count must not raise a false warning.
- **Not here yet (decisions, please confirm).**
  1. RECOVERING (rank 7, one beep every 10 s) is not in the item list. Nothing ends recovery before P25, so the host would beep forever. P25 adds the item when it sets `recovering` false.
  2. HOST BATTERY (rank 5) comes with P24b, which owns the battery check.
  3. Advisory estimates (chime, rank 8) are not alerts in the engine state, so they are not in the feed. A small feed from the advisory rows can be added if the operator wants the chime.
  4. The sound starts in every mode (LIVE, SIMULATOR, REPLAY), as ADR 0027 says the host sounds from host start. If REPLAY should be silent, change `make_audio_backend`.
  5. `dashboard/dist` is not served by `create_app`; whether the host should serve it is not decided here.
- **Still OPEN (unchanged from ADR 0032 and 0033): `unpersisted`.** The wire still has no `unpersisted` field, and the interim rule (hold the message until the commit, send none for a rejected row) stays. The host alarm does not depend on it.
- **Tests.** `test_serve.py`: `LoopHub` order and thread, tick order and fault isolation, the fixed grid and no burst, the driver start and stop, `ServeError` for a failed bind and an early stop, the exit codes 0, 1 and 2 with cleanup, `build_app`, and a real Uvicorn start and stop on a free port. `test_audio_wiring.py`: the item list, start and stop of the thread, the `Wire` feed order and error containment, the siren within 300 ms and its stop on Acknowledge, AUDIO_FAULT once and the banner flag, the tab counter, and `main()` with the silent backend.
