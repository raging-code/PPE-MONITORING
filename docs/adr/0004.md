# ADR 0004: nvs_latch (P16b), values and readings the constants file does not hold

Status: Proposed (decided in the P16b session; confirm at the next design review).
Design: Rev 3.45 is frozen and `shared/constants.json` has no key for these values; the Technical Summary (section 7 and the frame table) gives them in prose.

Values, as `#define`s in `firmware/components/nvs_latch/nvs_latch.h` (same approach as ADR 0002 and 0003): `NVSL_REBOOT_HINT_MS` 30000 (status2 bit 3, "first 30 s"), `NVSL_RESTORED_MS` 60000 (status3 bit 4, "set for 60 s after an unclean reset"), `NVSL_BOOT_TRIES` 3 (synchronous attempts to commit boot_ctr at boot; the Technical Summary gives no number). If the owner prefers real keys, add them to `constants.json`, regenerate, and delete the defines.

Readings the tests pin:
- The reboot hint is set on every boot, power-on included (boot_ctr rises on every boot). status3 bit 4 and the cause in bits 5 to 6 are set only for an unclean reset (brown-out, watchdog, software), never after power-on. The latch is restored on every boot including power-on (status4 bit 1, until the latch is cleared).
- SCBA ON is restored after brown-out, watchdog and software reset only; cold power-on is OFF (Technical Summary). An unreadable or invalid SCBA record means OFF, the safe side for CO suppression. The contacts must also be closed (scba.c).
- A latch record that is present but invalid, or whose read fails, is MAN_DOWN and logs `nvs_fault`; the service task then rewrites a valid record. A missing key is unlatched and is not a fault.
- `nvsl_observe()` is RAM only; `nvsl_service()` writes after the alarm has started (set, commit, read back, compare) and retries on the next call, logging `nvs_fault` for each failed attempt. A boot_ctr that cannot be read is a random byte, stored and logged; one that cannot be committed after 3 tries is used from RAM and the next boot may repeat it.
- Posture calibration is not stored here: the Technical Summary lists it with the latch, but the P16 row and the HANDOFF name only the latch cause, SCBA mode and boot_ctr.

Not proven here: the real timing of an NVS erase against the 10 Hz loop and a real brown-out. Those are the D2 bench tests (P17).

## Review decision (2026-11-28)

The values are **kept as taken from the Technical Summary** for now; changing them without hardware evidence would be guesswork. The sign-off is the bench run on built hardware, with the result recorded. Not confirmable from software.
