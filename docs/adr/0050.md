# ADR 0050: the firmware tag and ABI in the base heartbeat, host side (P24-5e)

Status: Proposed (decided in the P24-5 session; resolves the OPEN item of ADR 0049 with its option (a)).
Design: Rev 3.45 firmware note 4 ("fw_version and the ABI version are reported and checked"). This is the first change to the serial JSON and the first migration after 0001; both were confirmed by Carlo in the session. The firmware side is [BENCH] and is not built here.

- **Wire format (to implement in the base firmware).** Two optional keys on the existing `hb` line: `"fw"`, a printable-ASCII tag of 1 to 32 characters (a version or a short git hash), and `"abi"`, a non-negative integer with the meaning of `BEACON_ABI_VER`. Old firmware sends neither and parses exactly as before (`HB_FIELDS` is unchanged). A malformed value reads as absent: an optional field must never cost a liveness heartbeat.
- **Host.** `Heartbeat` gains `fw` and `abi` (default None). `services/fw_check.py` `FwState.update()` is edge-triggered: `FW_REPORTED` when the first tag of a session arrives and whenever it changes (the host also writes it to `sessions.fw_version`); `ABI_MISMATCH` once when the reported abi differs from the host's `BEACON_ABI_VER`; `ABI_OK` once when it agrees again. The first agreeing heartbeat is silent. `Ingest.heartbeat()` writes the rows; a new session reports again.
- **No fw mismatch.** The host has no expected fw tag (no settings key, no manifest field), so a fw difference cannot be called a mismatch; it is recorded, never judged. The kinds are therefore named for what is checked.
- **Runtime, not exit.** A start-up ABI disagreement still exits 2 (ADR 0049). A disagreement the base reports at run time is a row, not an exit (14.5: exit codes are for start-up).
- **Migration 0002.** `system_events.kind` has a foreign key into `system_event_types`, seeded in 0001. `host/migrations/0002.sql` adds the three kinds (seed 29 to 32). 0001 is untouched. Without it every new row is rejected by the key.
- **Not here.** The banner for `ABI_MISMATCH` (Wire, the snapshot and the dashboard catalog) is a follow-on stage; the firmware change; `cli doctor` rows.
