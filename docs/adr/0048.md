# ADR 0048: cli ack --node N, the CLI stop test (P24-5c)

Status: Proposed (decided in the P24-5 session; confirm at the next design review).
Design: Rev 3.45 is frozen (section 8, "Host sound files and CLI stop test", Rev 3.28: with zero browser tabs open a man-down sounds on the mocked host sink, `python -m ppe_host.cli ack --node N` stops it for that card and writes `ACK_ALERT`, and a removed operator's token is refused (D8)). ADR 0009 moved this command to P24 because it needs the running host. No host behaviour, frame, migration, constant, setting or REST route changes. P24-5 was split in three: P24-5a (ADR 0046, the supervisor), P24-5b (ADR 0047, `cli doctor`), this part. The `fw_version` / ABI check is **not** in this part (OPEN, below).

- **Where.** `host/ppe_host/services/ack_node.py` holds the logic and `cli.py` one command, `ack`, with `--node N` (required), `--mode`, and the usual `--home` and `--db`.
- **How it works.** The command does not touch the engine or the audio thread. It reads the ids of the node's alerts that are open (`cleared_ts IS NULL`) and not yet acknowledged from the database, then calls `POST /api/alerts/{id}/ack` on the running host for each one, oldest first, with the operator token as the bearer token. That is the route the dashboard uses, so the host does everything the design asks of an acknowledgement: the engine, `acknowledged_by` with the operator, the `ACK_ALERT` audit row (written by the route, with the operator and the node), and the AudioThread feed that stops the siren. No new route and no new local control path were needed, so the "local control path" ADR 0009 expected is not built.
- **Token.** Read from the `PPE_TOKEN` environment variable. There is no `--token` flag, so the token never lands in the shell history or the process list. It is sent only in the `Authorization` header and is never printed or logged, also not in an error. An empty or missing variable is exit 1 and nothing is sent. The operator token comes from `create-operator` or `rotate-token` (ADR 0009).
- **Which alerts.** All open, unacknowledged alerts of the node, not only the man-down: the design says "stops it for that card". A node with nothing open is exit 0 with a line saying so (a second run is therefore harmless). A node that is not in the roster is exit 1.
- **Which database.** The host writes `db_path` in `LIVE` mode and `test_db_path` in every other mode, and the lockfile does not record the mode. So the command has `--mode` (`LIVE`, `SIMULATOR`, `REPLAY`; default `LIVE`, as in `ppe_host.main`) and reads the matching file; `--db` still overrides. A test checks that the choices equal `main.MODES`. Without the right `--mode` the command would look in the wrong database and say "no open alert" while the siren sounds; the command's help names this.
- **The database is read read-only.** The same connection rule as doctor (`_ro`): while the host runs the normal read-only connection is used, and nothing is created next to the database (a test checks the folder).
- **The host address.** `bind_host` and `bind_port` of the settings, with a wildcard bind address (`0.0.0.0`, `::`, empty) replaced by `127.0.0.1`. The standard library (`urllib`) is used, not `httpx`, so the command has no new dependency; environment proxies are switched off for it (the host is on this machine). The timeout is 5 s per call.
- **Exit codes.** 0 all acknowledged, or nothing open. 1 nothing could be acknowledged: no token, no database, unknown node, host not reachable (the message says so and points to doctor), token refused (a wrong token, or the token of a removed or disabled operator: `authenticate` answers 401, as 4 requires), or every alert refused. 2 some were acknowledged and some were not. A refused token or an unreachable host stops at the first alert (one failed login is audited as `LOGIN_REJECTED`, not one per alert); any other answer for one alert (for example 404 for an id the host does not know) is reported and the loop goes on.
- **Race.** The alerts are read from committed rows. An alert the engine raised in the last moments may not be committed yet, so the command can say "no open alert" while the siren has just started. Run it again. It never acknowledges an alert it did not list.
- **Checked here (development sandbox, Linux, with network this time).** `ruff check host tools`: clean. The full `pytest host/tests` run and `tools/check_requirements.py`: see PROGRESS.md for the numbers. `host/tests/test_cli_ack.py` (17 tests) runs the command against a real Uvicorn server and the real `create_app` (so the Host and Origin rule and the bearer check are the real ones), with the real `create-operator` / `disable-operator` commands and the real `Authenticator`. `host/tests/test_cli_ack_host.py` (2 tests) is the design's pass condition on the real host: the real `Runtime`, `AudioThread` (a `FakeBackend` is the sink), `HostPort` and REST app: a man-down sounds on the looped siren with zero sockets, it keeps sounding, `ack --node 1` with an operator's token stops it, the alert row names the operator, and one `ACK_ALERT` row (operator, node, `alert_id 500`) exists; and a disabled operator's token is refused, nothing is acknowledged and the siren is not stopped. Both files carry REQ-AUD-004 and REQ-SEC-004. Mutation checks: reading cleared alerts as open, and not treating 401 as fatal, each fail tests.
- **Not here.** The man-down in the host test is put into the engine state and the `alerts` table as the engine holds it after a verified frame; a signed radio frame is not built, so the path radio to siren is covered by the other parts' tests, not by this one. The real `winsound` sink and Windows are not run (the sink is the `FakeBackend`). The command was not run against a real host on the field laptop.
- **Open, please confirm.** (1) The command acknowledges every open alert of the node, not only man-down and mayday. (2) Nothing open is exit 0. (3) `--mode` is needed for a host not started in LIVE mode. (4) No `--token` flag, `PPE_TOKEN` only. (5) The tests carry REQ-AUD-004 and REQ-SEC-004, whose status in `requirements.yaml` stays Proposed.
- **OPEN: the `fw_version` / ABI check.** Design 1 says the `fw_version` and the ABI version are reported and checked against `abi.json` at host start, but it does not say what a mismatch does. It is not built here, and the guide says to ask rather than guess. The options are: refuse to start with exit 2; start and show a banner; or only write a log row. Suggestion for a later part: an ABI mismatch refuses to start (exit 2), because a different frame layout could mis-parse safety alerts without any error; a `fw_version` mismatch alone writes a row and shows a banner.
