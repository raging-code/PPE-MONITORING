# ADR 0003: SCBA machine and IMU-degraded mode, values and readings the constants file does not hold

Status: Proposed (decided in the P16a session; confirm at the next design review).
Design: Rev 3.45 is frozen and `shared/constants.json` has no key for these values; the Technical Summary (section 7) gives them in prose.

Values, as `#define`s in `firmware/components/rules_fw/degraded.h` (same approach as ADR 0002): `DG_GRACE_MS` 5000 (IMU fault to the first prompt), `DG_PERIOD_MS` 30000 (prompt period, restarted by a clean CANCEL), `DG_RESUME_MS` 5000 (valid IMU samples before normal mode returns). The 15 s unanswered-prompt latch is the existing `PPE_IMU_DEGRADED_TIMEOUT_S`; the SCBA 300, 120 and 20 s are the existing `PPE_SCBA_*`.

Readings of the SCBA text that the scenarios and tests pin (the rules are in `scba.c`):
- The prompt opens when the confirmation clock runs out even if a check-in or degraded prompt holds the slot; the clock is never deferred, only the prompt UI.
- Unlatched, the 20 s response window grows by the time the slot was held (so a short check-in only defers; the design's "about 15 s" ceiling is the check-in and degraded latch timeouts, not a separate constant). Latched, the window is a plain 20 s from the prompt (FW-07, FW-08).
- If the clock runs out while a man-down or MAYDAY is latched there is no prompt and no response window: `scba_expired` is set at once, silently (FW-09, expiry at 300 s after SCBA ON).
- A CANCEL is an SCBA answer only when the slot is free and the node is not latched, so the latch-clear press and a check-in answer never restore or renew SCBA.
- Expired with the coupling mated: one clean CANCEL restores ON. Coupling open: only an OFF to ON cycle (an ON edge) clears it.

Vector check: FW-07 to FW-10 match the rules as read above; no vector or rule was edited. The FW-07 and FW-08 "deferral <= 15 s" checks measure exactly 15000 ms because the scenarios tick at 315200 and 320050; a 10 Hz loop latches the fall check-in earlier.
