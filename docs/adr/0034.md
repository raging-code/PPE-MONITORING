# ADR 0034: Start-up step 9, loading the open alerts and episodes (P24-3c-2)

Status: Proposed (decided in the P24-3c-2 sessions; confirm at the next design review).
Design: Rev 3.45 is frozen (14.5, section 1 step b). Nothing in the frame, the migration, `constants.json`, the settings keys or `api/models.py` changes.

- **Split of P24-3c-2 (done).** Part 1 code (`load_open_state()` and `Ingest.load_open()` in `io/ingest.py`, `Runtime.load_open()`, the call in `main.py`); Part 2 `host/tests/test_open_state.py` (15 tests); Part 3 this ADR and the doc touch-ups. P24-3c-3 (step 10: Uvicorn, the 1 Hz driver, OS watchdog, AudioThread) is unchanged.
- **What it does.** Two indexed reads on the start-up connection: open alerts (`cleared_ts IS NULL`, every session) and open episodes (`state` OPEN or ACKNOWLEDGED). They become engine values and are merged into `Ingest.st` before Uvicorn starts, so the first snapshot and the first frame agree. It is a read only: no row is written, no `event_seq` is used, no effect is produced.
- **Existing state wins.** An alert, an episode or a node's unauth fields that the engine already holds are left alone. A second call adds nothing and returns zeros. Only an alert that this call adds can set that node's `unauth_count` and `unauth_last_seen_ts`.
- **Four things the database does not store (decisions, please confirm).**
  1. `unauth_count` is not stored. An open `unauth_alert` comes back with count 1 (a lower bound) and `unauth_last_seen_ts` = its `raised_ts`.
  2. `Episode.opened_event_seq` is not stored. It is the `event_seq` of the episode's oldest open `man_down` or `mayday` row minus 1 (`EpisodeOpened` is allocated just before that `RaiseAlert`), or 0 when no such row is open. Nothing looks an episode up by it; the writer uses the node.
  3. `motion_state` is not stored. MAN_DOWN comes back as `no_response` (the safe label; it changes to `movement_detected` only after fresh frames show movement), MAYDAY as `None`. The move and still timers start empty.
  4. A row that cannot be an engine value is skipped, listed in `OpenReport.skipped` and logged as a warning; it is never loaded and never fatal: `node_id` NULL or not an int, unknown type, unknown level, unknown episode kind, a second open row for the same node and type (the lowest `event_seq` stays), a second active episode for a node.
- **What is not restored.** Only alerts and episodes. Everything else in the engine state (node readings, CO and heat timers, the shadow estimator, advisory state, sequence state) starts empty and fills from fresh frames. An open alert is therefore held until a fresh frame clears it by the normal rules.
- **Query plans.** The alerts query uses `idx_alerts_open`. The episodes query uses `idx_episodes_one_active` only once SQLite has statistics (`ANALYZE`); on a database with none, the planner scans by rowid because that avoids a sort. One row per episode keeps either cheap. If a forced index is wanted, `INDEXED BY idx_episodes_one_active` on that query is a one-line change.
- **Tests.** `test_open_state.py` covers the load, the merge, a second call changing nothing, no write and no `event_seq`, each skip case, both plans, and Acknowledge and Resolve after a restart.
