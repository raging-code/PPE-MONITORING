# ADR 0046: the user-session supervisor (P24-5a)

Status: Proposed (decided in the P24-5 session; confirm at the next design review).
Design: Rev 3.45 is frozen (section 1, "Windows packaging, user-session supervisor"; 14.5 thread map item 1 and the start-up failure policy; 8, Start-up failure test). No host code, frame, migration, constant, setting or REST route changes. P24-5 is split in three: P24-5a (this: the supervisor), P24-5b (`cli doctor`), P24-5c (`cli ack --node N`, and the `fw_version` / ABI check at start-up once the mismatch rule is decided).

- **What it is.** `scripts/run_supervisor.py`, standard library only (the host package is read only to find `log_dir`, and a broken settings file does not stop the supervisor). It runs `python -m ppe_host.main` with the `host` folder on `PYTHONPATH` and `PPE_HOME` set, from the release folder or the repository root (`scripts/` is already copied by `tools/package_release.py`). Options: `--home`, `--mode`, `--python`.
- **Respawn.** A non-zero exit starts the host again at once, with no sleep: the gap is only the supervisor's own loop, logged as `last_gap_ms` and tested against the 500 ms of the design with a real short-lived child process. Exit code 0 (clean shutdown, or another host holds the lockfile) is never respawned, and the supervisor exits with 0. A host that cannot be started at all (OSError) counts as exit code 127.
- **Crash-loop guard.** The times of non-zero exits are kept for 60 s. When 5 are inside the window the supervisor waits 5 s before each respawn, plays the local alarm on each respawn, and shows the error window once per crash loop. The guard ends by itself: after a run longer than 60 s the old exits fall out of the window and the next crash is respawned at once. Exit code 2 and signal-style negative codes count like any other non-zero code (design 14.5 (d)).
- **Error window.** On Windows a `MessageBoxW` (error icon, topmost) in a daemon thread, so respawning continues while it is open; elsewhere the text goes to standard error (development and CI). The text names the number of exits, the last exit code with a plain reason, and the last crash marker (`kind`, `ts`, `stalled`, `age_ms`, `limit_ms`) read from `crash_marker.json` or, when the next start already moved it, `crash_marker.last.json`; a damaged file is reported as damaged. Exit code 2 has no marker (the host did not stall), and the text says so.
- **Local alarm.** The 1 kHz 400 ms pulse (`winsound.Beep`), the same fallback as 3.12, so a missing or altered WAV cannot silence the supervisor. Outside Windows it writes a bell character.
- **Log.** Each line goes to standard output and to `<log_dir>/supervisor.log`; a failed write is ignored.
- **Stopping.** Ctrl+C terminates the child and exits with 0. Two supervisors cannot run two hosts: the second host finds the live lockfile and exits with 0, so its supervisor stops too.
- **Checked here (development sandbox, Linux).** `host/tests/test_supervisor.py` (18 tests) ran under a minimal stand-in for pytest (no network): exit 0, respawn without waiting, 4 exits no guard, the 5th waits 5 s with one window and one alarm, repeated waits, exit 2, negative codes, exits more than 60 s apart, the guard ending after a long run, a second crash loop, window text with and without marker, spawn failure, Ctrl+C, marker file choice, a real child respawned within 500 ms, the spawn command and environment, standard-library-only imports. A smoke run of the real script against the real host with an empty PPE_HOME gave exit 2 five times, then the window, the alarm and 5 s waits. **Not run:** the full pytest suite, ruff, Windows (`MessageBoxW`, `winsound`), the launcher, a stall exit on a real host.
- **Not here.** The launcher `.bat` and the Startup-folder shortcut (design: added by hand to the release folder); OS sleep, power plan and lid-close settings (the Windows host checklist); the D8 timing check of `supervisor_restart_target_s` (5 s from stall to a running host) on the field laptop, which includes the host's own start-up time and is not the 500 ms respawn of the supervisor.
- **Open, please confirm.** (1) The alarm on every guarded respawn (every 5 s) and the window only once per crash loop. (2) Exit code 127 for a host that cannot be started. (3) Ctrl+C exits with 0. (4) That the supervisor passes `--home` and `--mode` to the host and sets `PPE_HOME`.
