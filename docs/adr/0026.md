# ADR 0026: host sound files, priority and the zero-socket warning (P23a)

Status: Proposed (decided in the P23 session; confirm at the next design review).
Design: Rev 3.45 is frozen. Nothing in the frame, the migration or `constants.json` changes.

- **Zero-socket warning: BUILD (operator decision, P23 session).** The design contradicts itself: Section 1 (packaging) and the D8 row "Browser freeze and headless alarm" keep a laptop warning when no authenticated `/ws` socket has been connected for more than 10 s while `monitoring_active=true`; 3.12 removed the older "zero tabs report audio_unlocked" rule (a different test) and says the host alarm "plays regardless"; and `zero_socket_alarm_s` was deleted in Rev 3.30. The operator chose to build it. It is built in P23b as a fixed 10 s in `audio_watchdog.py`, not a settings key, because the settings keys are frozen and the key was deleted. Whether 9.1 wants a stop rule for it stays open: P23b gives it none (it stops when a tab reconnects or monitoring ends), because Acknowledge is for alerts and this warning has no alert.
- **Sound files:** `tools/gen_sounds.py` (standard library only, deterministic) writes `siren.wav`, `beep.wav`, `one_beep.wav`, `chime.wav`, `host_chime.wav` and `probe.wav` (100 ms of silence for the 60 s self-check) plus `host/sounds/manifest.json` (SHA-256 of each file) into `host/sounds/`. `--check` proves the committed files are the generator's output. A patch writes text only, so run `python tools/gen_sounds.py` once and commit the files (`.gitattributes` already marks `*.wav` binary).
- **Volumes (proposals, sound design and not safety thresholds):** peak as a fraction of full scale: siren 0.90, beep 0.50, one_beep 0.50, chime 0.125 (a quarter of beep, as 3.4 says), host_chime 0.125. 3.4 gives only the ratios; `host_chime` has no stated level, so it uses the chime level. The operator must hear the 15 minute chime (3.9), so check it on the real speakers at the bench and raise it here if it is too quiet.
- **Start-up check:** `check_sounds()` compares every file with the manifest and returns `(file, reason)` pairs: `missing`, `altered`, `not in manifest` (a catalog sound the manifest lacks), or a `manifest.json` that is missing or unreadable. P23b raises `AUDIO_FAULT` for a non-empty list.
- **Priority (3.3, Rev 3.17 complete list):** `host_rank()` returns 2 MAYDAY and man-down, 3 BASE OFFLINE, 4 other DANGER (siren), 5 WARNING and the LOGGING FAULT and HOST BATTERY banners (beep), 6 UNAUTHENTICATED ALERT (beep), 7 RECOVERING and HOST_GAP (one beep), 8 estimate (chime). Rank 1, NO LIVE DATA, is the browser siren and the host stays silent for it, as it does for AUDIO FAULT (visual only), notices and unknown types.
- **Cleared but not acknowledged (to confirm):** `pick()` keeps sounding an alert that has cleared but is not acknowledged, following 3.3 ("sound continues while any safety card is unacknowledged") and the Section 1 text ("any unacknowledged DANGER/WARNING alert"). 3.3 also says such a card stays so a short spike is never missed, which could mean only "seen". If the operator wants the sound to stop at clearing, change one condition in `pick()`.
- **CLI:** `cli ack --node N` stays with P24 as ADR 0009 says (it needs the running host). P23b adds the offline `test-alarm` command for the shift speaker check.
