# ADR 0041: build manifest, release folder, CI and the import rule (P27-1, P27-2)

Status: Proposed (decided in the P27 sessions; confirm at the next design review).
Design: Rev 3.45 is frozen (12.1 CI check, 13 canonical `build_manifest.json`, 14.5 repo layout and the Rev 3.43 import rule, section 1 release bundle). No frame, migration, constant, setting or REST route changes.

- **Split of P27.** 27-1: `tools/build_manifest.py`, `tools/package_release.py`, the justfile `build` and `package`. 27-2: `tools/check_imports.py`, `.github/workflows/ci.yml`, the justfile `lint`. 27-3 (next): the Playwright tests of design 8 under `e2e/`. Delivered together as one patch because 27-2 is small.
- **Manifest.** The 11 keys of 13 in the contract's order, `schema_version` 1. A key whose source does not exist is `null` and named on stderr: it is never given a made-up value, and `--strict` (for the release) exits 1 for any null except `stl_sha256`. `rev_tag` is read from the title line of the newest `docs/PPE_Software_Design_Compact_Rev*.docx` (`Software Design (Compact - Rev 3.45)`), so it cannot go stale; a missing or unreadable document is an error. `constants_sha256` and `alert_catalog_sha256` use the canonical serialisation (sorted keys, compact, UTF-8), identical to the host's `constants_hash`; the lock files and `openapi.json` are hashed as text with CRLF read as LF, so a Windows checkout and a Linux CI agree; the `.stl` is hashed as bytes. Output is `dist/build_manifest.json` (`dist/` is ignored by git, so the timestamp never makes a diff).
- **Sources not there yet.** `python_lock_sha256`: `requirements.lock` is P27b. `esp_idf_version`: no file in the repository says which IDF tag and patch sha the firmware uses; the build reads `$ESP_IDF_VERSION` or the first line of `firmware/esp_idf_version.txt` (for example `v5.3.2 <patch sha>`), and the value must come from the firmware lead. `stl_sha256` stays null until the optional model exists (13 item 1). `git_commit` is filled from `$GITHUB_SHA` or `git rev-parse HEAD` (null only in a zip without `.git`).
- **Release folder.** `tools/package_release.py` writes `dist/release/`: `host/ppe_host`, `host/migrations`, `host/config`, `shared/`, `scripts/`, the prebuilt `dashboard/dist`, `requirements.lock` and `pyproject.toml` when present, and a fresh `build_manifest.json`. Never copied: tests, `node_modules`, databases, backups, logs, exports, `secrets.json`, `settings.local.json`, the test vectors. It refuses without `dashboard/dist/index.html` (`just build` first). The pinned embedded Python 3.12 runtime and the launcher `.bat` of the design (section 1, Release bundle) are not made here: the runtime cannot be fetched by a script in this setting, and the release on a second PC is a manual pre-trial step (CODING_GUIDE, "not given a Part on purpose").
- **Import rule.** `tools/check_imports.py` reads every `.py` under `host/ppe_host/core/` as a syntax tree (nothing is imported or run), including imports inside functions. A violation is: an import that resolves to `ppe_host.io`, `ppe_host.services` or `ppe_host.api` in any form (`from ..io import x`, `from .. import services`, `import ppe_host.api...`); an import of a module that does I/O (files and paths, sockets and HTTP, serial, SQLite, processes, audio, `importlib`, `asyncio`); a call of `open()`, `input()` or `__import__()`. The design's wording ("no file, serial, network or audio I/O") has no module list, so the list is mine; `core/` today imports only `dataclasses`, `typing`, `hmac`, `cryptography`, `constants`, `abi` and its own modules. A missing `core/` folder fails, so the rule cannot pass by checking nothing.
- **CI.** Three jobs on `ubuntu-latest`, no secrets. `host`: install, run all six generators in the order of `just gen`, fail if `git status --porcelain` is not empty (this also catches a new untracked generated file, which a plain `git diff` would miss), then `doc_lint`, the import rule, pytest, the frame vectors. `firmware`: the gcc runner as in `just test-fw`. `dashboard`: `npm ci` from the lock file, typecheck, Vitest, build. Actions are pinned to a major tag, not a commit SHA. `tests/test_ci_config.py` checks that the file parses, the order of the steps, that the generators and the gcc steps equal the justfile recipes, and that every file a command names exists. It needs `pyyaml` (added to the dev extras; P27b needs it too) and skips the YAML tests without it.
- **Checked here (development sandbox, Linux).** All six generators leave the delivered tree unchanged; the gcc tests, Vitest (267) and `npm run build` pass; the manifest and `dist/release` are produced from the real tree. **Not checked:** the workflow has not run on GitHub (no Actions runner here); the first push is the test.
- **Open, please confirm.** (1) Where `esp_idf_version` comes from (file in `firmware/`, or a repository variable). (2) The I/O module list of the import rule, and that `asyncio` is on it. (3) CI regenerates `ws.schema.json` and `openapi.json` from the Pydantic models with the newest dependency versions until P27b pins them: a Pydantic release that changes the schema text would fail the diff check, which is the intended signal and the reason `requirements.lock` is next. (4) The release folder without the embedded runtime.
