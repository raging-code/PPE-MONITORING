# ADR 0008: security of the REST layer (P19b-1)

Status: Proposed (decided in the P19b-1 session; confirm at the next design review).
Design: Rev 3.45 is frozen. Nothing in the frame, the migration or `constants.json` changes.

- **Split:** P19b is P19b-1 (`api/security.py`, the Origin/Host rule, the login delay, the wiring into `api_rest.py`) and P19b-2 (the CLI commands `create-operator`, `rotate-token`, `disable-operator`, `ack --node`). WebSocket authentication and the close of an open socket for a disabled operator belong to P20, which reuses `origin_ok` and `authenticate`.
- **Tokens:** `secrets.token_urlsafe(24)`; only the hex HMAC-SHA256 keyed with `server_salt` is stored; `authenticate` reads `operators` on every call and compares every row with `hmac.compare_digest`, so rotation and disabling act on the next request and there is no expiry. It runs on the event loop (one small read-only query), because the dependency of P19-1 does.
- **server_salt:** `load_or_create_salt` creates it once in `config/secrets.json`, keeps the other keys, writes through a temporary file and `os.replace`, and refuses (never replaces) a missing salt while operators exist or a malformed one.
- **Failed-login delay (Proposed numbers):** the design gives the cap (`login_backoff_cap_s` = 5) and the word "exponential" but not the first step. The first failure waits 1 s and each further failure in a row doubles it up to the cap (1, 2, 4, 5, 5). The 401 carries that value as `retry_after_s` and the route waits that long before it answers, which slows guessing. The counter is global (one laptop) and a success resets it; a valid token is never refused because of earlier failures (design 4: no lockout).
- **Origin and Host:** a middleware checks every HTTP call before the token. Host must equal `localhost:<bind_port>` or `127.0.0.1:<bind_port>`; Origin, when present, must equal `http://localhost:<bind_port>` or `http://127.0.0.1:<bind_port>`. A missing Origin passes, because a browser omits it on a same-origin GET (a cross-site POST always carries one), and `null` is rejected. A rejection is 403 `ORIGIN_REJECTED` and one `ORIGIN_REJECTED` audit row. `create_app` takes `bind_port` (default 8420).
- **Token channels:** only the `Authorization: Bearer` header is read; a cookie or a query parameter is never a token.
- **Audit:** every 401 from the bearer dependency writes `LOGIN_REJECTED` (design 8: a disabled operator's next REST call is logged). A flood of unauthenticated calls therefore writes a row each; rate-limiting that is not designed and is left open.
- **Tests touched:** `test_api_rest.py` and `test_api_actions.py` build their client with `base_url='http://127.0.0.1:8420'` (the Host check), `test_api_rest.py`'s fake port gains `login_failed` and `login_ok`, and one assertion of `test_api_actions.py` now allows `LOGIN_REJECTED` rows after a refused token.
