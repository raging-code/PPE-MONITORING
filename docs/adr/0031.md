# ADR 0031: The host Port (P24-3b-1) and the split of P24-3b

Status: Proposed (decided in the P24-3b session; confirm at the next design review).
Design: Rev 3.45 is frozen. Nothing in the frame, the migration, `constants.json` or the settings keys changes.

- **Split of P24-3b (decision).** P24-3b is two stages: **P24-3b-1** (this one) the Port behind the REST routes and the audit and drop hooks of the WebSocket Source: `authenticate`, `login_failed`, `login_ok`, `audit`, `session_id`, `recovering_retry_s`, `start_monitoring`, `ack_alert`, `ack_episode`, `resolve_episode`, `set_scba_correction`, `ack_banner`, `client_dropped`, with a `publish(effects, unit, committed)` hook; **P24-3b-2** the snapshot and the WebSocket messages built from the effects and the committed ids (`unpersisted` included). P24-3c (steps 8 to 10) is unchanged.
- **`end_session` is not here.** The Port method needs `close_session('ENDED')` and the backup, which are P25 (design 2.11, Coding Guide P25). It raises `NotImplementedError` until then, so the route answers 500 INTERNAL_ERROR and never half-closes a session.
- **Where (decision, please confirm).** Design 14.5 lists no module for the host's side of the Port. It is `host/ppe_host/host_port.py`, a top-level module next to `main.py`, `settings.py` and `clock.py`. No folder is added. The alternative is to grow `main.py` (about 220 lines already).
- **Writes.** The Port never writes on its own connection. `Ingest.audit()` and `Ingest.write()` take the next `event_seq` and submit one ordered unit, so audit rows and session updates stay in `event_seq` order with frames and effects. An audit row with an operator, and every Acknowledge, Resolve and session update, is a durable unit (synchronous=FULL). The reads are single indexed look-ups on a read-only connection.
- **Acknowledge and Resolve** go through `step()` (`Ingest.operator`), so the engine and the rows agree. An alert the engine no longer holds (cleared, or not loaded yet) gets a direct row update, so a cleared unacknowledged alert can still be acknowledged (design 3.8: 200 also for a cleared alert). A repeat returns the first acknowledgement.
- **Episodes the engine does not hold** (a restart before P24-3c loads them) answer 409 STATE_CONFLICT, not a crash. This disappears when step 9 fills the engine.
- **SCBA correction** is live display state in the Port (`scba`), loaded at start from `load_scba_corrections`. **Banners:** `host_gap` is active while a gap is recorded, `logging_fault` while the writer is in fault; an acknowledgement ends with its condition, and a new gap is a new banner. `gap_s` of a restored database is 0.0 until P25 measures the gap and calls `set_host_gap`.
- **Audit rows stay as P19 built them.** The routes still write ACK_ALERT, ACK_EPISODE, RESOLVE_EPISODE, START_MONITORING, SCBA_CORRECTION and BANNER_ACK through `port.audit` (ADR 0030, item 3).
