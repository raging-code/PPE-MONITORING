# ADR 0017: Acknowledge, Resolve and ack pending (P22-3)

Status: Proposed (decided in the P22-3 session; confirm at the next design review).
Design: Rev 3.45 is frozen. Nothing in the frame, the migration, constants.json, alert_catalog.json or ws.schema.json changes. No new endpoint: the three calls are the frozen ones of 3.8.

- **Acknowledge button (3.3):** on every safety card and every unverified card that has an unacknowledged line. An estimate card has Dismiss only. One click acknowledges the whole card: a line with an episode goes through `POST /api/episodes/{id}/ack` (which acknowledges its linked alerts), every other line through `POST /api/alerts/{id}/ack`. A cleared line is included, because the host accepts it.
- **Silent at once, "ack pending":** the click is shown on screen before the host answers (store/actions.ts keeps the entry, alerts/ack.ts overlays it on the alert list, so the flash, the repeat rule and the button all treat the alert as acknowledged). The line shows "ack pending" until the host confirms. A failed call never removes the entry, so it never un-silences the card.
- **Retry:** a network failure or a 5xx is tried again after `retryMs`. The design gives no retry time, so it is a constant 1000 ms with no backoff (same status as ADR 0013's reconnect time). A 401 or 403 stops the retries and the card stays silenced. A 404 counts as done. A 409 on an episode (already resolved) falls back to acknowledging its alerts one by one.
- **Persistence:** the host stores the Acknowledge, and the snapshot and the `alert` messages carry it, so a reload, a second tab or a host restart shows the card acknowledged with no new code. The entry is dropped once the host's own alert shows the acknowledgement, or the alert is gone.
- **Resolve (3.3):** offered only for an episode the host has confirmed as ACKNOWLEDGED, so the two steps stay apart. The inline form names the node and the episode ID, and Confirm stays disabled until one of the three reasons is chosen. Resolve is sent once and is not retried; the outcome is shown as text. After a successful Resolve the card says that the jacket latch is still set when `latch_still_set` is true: only the jacket CANCEL clears it.
- **Proposed:** an unacknowledged call that has not reached the host is kept in memory only. If the page reloads before the host has answered, the card sounds again and the operator acknowledges again. Storing unsent acknowledgements across a reload is not in the design and is not built.
- **Not done here:** the Resolve dialog styling and the focus handling of P22c (the form here is inline in the card), the top strip, the side panel and the advisory slim card (P22d), the browser siren and the message-to-pop-up latency measurement (P22c Playwright).
