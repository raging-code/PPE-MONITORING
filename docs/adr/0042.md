# ADR 0042: browser tests under e2e/ (P27-3)

Status: Proposed (decided in the P27 sessions; confirm at the next design review).
Design: Rev 3.45 is frozen (8 and 3.12: the Playwright tests; 3.7 and 3.9: NO LIVE DATA at `dashboard_stale_s`; 3.7: Test sound and Start monitoring). No host code, frame, migration, constant, setting or REST route changes.

- **What runs.** Chromium (Playwright) opens the built dashboard (`dashboard/dist`), signs in, and the tests check what a browser must prove and Vitest cannot: the worker and its `/ws/tick` socket, the real AudioContext and the Web Lock. Four tests of NO LIVE DATA: it shows 4 s after the last tick (measured from the mock host's last send; not before 3.8 s, not after 5.5 s), it clears when ticks come back, a host that never answers after login also gives it at 4 s, and before Start monitoring the red screen says the browser siren is off. Two tests of Start monitoring: the button stays disabled until Test sound played, then the audio bar shows Siren ON (it shows that only while this tab owns the siren and the audio clock really runs) and `POST /api/session/start` reaches the host; after that, the red screen offers Silence 60 s and no longer says the siren is off.
- **A mock host, not the real host.** `e2e/mock_host.mjs` serves `dashboard/dist` and speaks the design 3.8 messages the tests need (login, session start, the `/ws` snapshot and ticks, `/ws/tick`). The reason: in the code read for this part the real host serves no static files (no static route in `serve.py` or `api_rest.py`), a started host needs a serial port or the simulator plus an operator token, and a test that must make the host go quiet at an exact moment needs control of the sockets. The real host and the wire are covered by pytest. A pytest test (`test_e2e_config.py`) runs `node e2e/mock_host.mjs --print-messages` and validates both messages with the host's own Pydantic models, so the mock cannot drift from the wire without a failing test. The control endpoint `/__ctl` is not a design interface and exists only in the mock.
- **No fixed sleeps, no retries.** Every wait is for something to appear. One worker and `retries: 0`: the tests share one mock host and measure time, and a retry would hide a real timing failure. A pytest test fails if a spec contains `waitForTimeout`, `setTimeout`, `test.skip` or `test.fixme`.
- **Dependencies.** `e2e/` is its own npm package with a lock file. Exact pins: `@playwright/test` 1.64.1 (released 2026-10-14), `ws` 8.23.0 (2026-11-12, the fix for the two advisories on 8.0.0 to 8.20.1; `npm audit` is clean), `@types/ws` 8.18.1, `typescript` ~5.8.3. Every pin is at least 14 days old. `ws` is used only by the mock host.
- **Wiring.** `just test-e2e`. A fourth CI job `e2e`: dashboard `npm ci` and `npm run build`, e2e `npm ci`, `npx playwright install --with-deps chromium`, `npx playwright test`, and the HTML report as a workflow artifact on failure (`actions/upload-artifact@v4`, 7 days). `test_ci_config.py` now expects four jobs.
- **Checked here (development sandbox, Linux).** The specs typecheck (`tsc --noEmit`), the mock host was driven by a protocol client (auth, 4401 on a bad token, snapshot then ticks on `/ws`, ticks on `/ws/tick`, silence in the muted mode, 401 without a bearer token, path traversal refused), both server messages validate against the Pydantic models, and the full pytest suite passes. **Not checked:** the browser run itself. The sandbox cannot download Chromium, so no spec has run in a browser. The first `just test-e2e` on your machine and the first CI run are the first real runs; timing bounds and the Siren ON step are the likeliest to need a change. **Update (P27b-2):** the operator ran `npx playwright test` on Windows in the P27b-1 session and all 6 tests passed (as reported in that session's log); the browser run is therefore done. The first GitHub Actions run of the `e2e` job has not been reported.
- **Left out.** The 500 ms dashboard share of the man-down path (design 5, "Proposed, provisional", measured with browser performance marks over at least 100 events) needs a man-down message, a pop-up and performance marks in the dashboard code, which do not exist yet; it is a separate part. Tests for the ALARMS SILENT banner and the audio_unlocked heartbeat are not written because Rev 3.45 removed them (3.12).
- **Open, please confirm.** (1) A mock host instead of the real host in the browser tests. (2) The timing bounds (4 s minus 0.2 s to 4 s plus 1.5 s). (3) Whether the 500 ms performance-mark test should be its own part before the trial.

## Review decision (2026-11-28)

The 500 ms dashboard share of the man-down path stays **provisional**. Confirming it is a bench measurement, not a review decision: browser performance marks over at least 100 events. Owner: the project owner, during the camera-timed bench session; the result is recorded as an ADR in the style of ADR 0066 and ADR 0067. No number is invented before then.
