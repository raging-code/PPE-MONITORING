# ADR 0057: SIMULATOR makes seeded traffic (S7-1)

Status: Proposed (implements design 3.10 and design 1, Operating mode isolation; confirm at the next design review).
Design: Rev 3.45 stays frozen. No wire message, endpoint, setting, migration or constants.json change. `LIVE_FRAME_IN_TEST_MODE` is already in migration 0001 and is not used yet (S7-2).

- **Split of S7.** S7-1 (this ADR): the simulator. S7-2: the serial drain and `LIVE_FRAME_IN_TEST_MODE`; today SIMULATOR and REPLAY open no serial port, so nothing can detect live hardware traffic. S7-3: REPLAY. Each part has its own patch.
- **Module.** `host/ppe_host/services/simulator.py`. `encode_frame` builds a real 23-byte frame from field values (layout from `abi.FRAME_FIELDS`, CRC-8, AES-128-CMAC with the sys_id first) and is the inverse of `crypto_abi.decode_frame`; a value that does not fit its field raises ValueError. `Schedule` says what is due at a given time. `SimulatorThread` polls a Schedule against the injected Clock (`mono_ms`) every 0.1 s and gives each item to the callback the SerialReader uses, `Runtime.gate.on_item`. Nothing in the module opens a port or a database.
- **Same path as live traffic.** A simulated frame is handed to the pre-replay gate, so it waits for RECOVERING_EXIT like a live frame, then goes through Ingest: verification, seq classifier, rules, writer. The rows land in `test_db_path` (Rev 3.40); `db_path` is never opened.
- **Schedule rules.** Each node sends one frame every `routine_period_s` (2 s) at its own seeded place in the period. `seq` is the slot number from a seeded start, so a slot that is not sent leaves a gap in `seq`. A node script may return None for a slot (silence). A poll that finds several slots due (a paused thread, a clock jump) hands out only the newest slot of each node and one heartbeat, never a burst of old ones; the skipped slots are the seq gap. The bytes of a slot depend only on scenario, seed, node and slot, not on how often the schedule is polled. The base heartbeat is 1 Hz (`rx_ok` is the count of frames made so far; no `fw` and no `abi`, as old firmware sends none, so no FW_REPORTED row). A time that goes backwards is treated as the last time.
- **Scenarios** (seconds from the first poll; the engine's own timers add 1 to 2 s). The node ids are the seeded roster, 1 to 3; a node a scenario does not name is quiet (CO 0.5 to 3 ppm, upright, active, a heart rate, the battery falling slowly).
  - `quiet`: no alert in ten minutes.
  - `co_ramp` (node 1): 5 ppm until 10 s, 60 ppm at 40 s, 230 ppm at 70 s, held to 100 s, 10 ppm at 130 s. The node level follows the thresholds (35 and 200 ppm going up, 31.5 and 180 going down). Observed in the engine: `co_threshold` WARNING near 28 s, DANGER near 66 s, back to WARNING near 118 s, cleared near 138 s.
  - `man_down` (node 2): a fall at 20 s, lying still, the man-down latch (flags bit 2, node level DANGER) after `mandown_still_s` at 52 s, upright again at 110 s. Observed: one `man_down` DANGER alert near 54 s and nothing else. The alert stays open until an operator resolves the episode, as for a real one.
  - `link_loss` (node 3): the signal fades from 10 s, the base hears nothing from 20 s to 95 s, then the node is heard again with a seq gap of about 37. Observed: `sensor_fault` WARNING near 26 s (the CO silence timer, the engine's own rule), `signal_lost` near 35 s, `link_lost` near 80 s, both cleared near 96 s.
  - `rehearsal`: `co_ramp` as is, `man_down` shifted by 60 s, `link_loss` shifted by 120 s, so the three events come one after the other on three nodes: CO warning near 28 s, man-down near 114 s, signal lost near 155 s, link lost near 200 s, all back by about 216 s.
- **Runtime.** `Runtime(st, simulator=(scenario, seed))`. A simulator on any mode but SIMULATOR raises ValueError before anything is built. The thread starts after the writer and stops before CLEAN_SHUTDOWN and the writer, so no simulated frame is queued after the last row. It stamps the `serial` liveness of the OS watchdog, so a stalled simulator is a stall like a stalled reader. Without the argument nothing changes: no thread, no frames.
- **main.** `--scenario quiet|co_ramp|man_down|link_loss|rehearsal` and `--seed N` are accepted only with `--mode SIMULATOR` (exit 2 and a message otherwise; an unknown scenario or a seed that is not a number is argparse's exit 2). `--mode SIMULATOR` without them runs `rehearsal` with seed 1. The start-up line ends with `scenario <name> seed <n>`. LIVE and REPLAY never start a simulator.
- **Operators are per database.** A rehearsal needs an operator in the test database: `python -m ppe_host.cli create-operator --name NAME --db data/ppe_test.db`. An operator made for `data/ppe.db` does not exist there.
- **Decisions to confirm.** (1) `rehearsal` with seed 1 as the default of `--mode SIMULATOR`. (2) The simulated base reports no `fw` and `abi`. (3) The scenario times above. (4) The simulator counts its own frames and handler errors (`SimulatorThread.counters`) but they are not added to the COUNTERS row.
- **Checked here (development sandbox, Linux).** `host/tests/test_simulator.py`: 46 tests, 3 runs in a row all passed. Frame encoder: all 17 OK vectors of `frames.json` rebuilt byte for byte, equal to the test packer on 200 field combinations, 20 seeds times 5 scenarios times 10 minutes of frames all verify OK. The scenarios were run through the real rule engine (times above). The real host in SIMULATOR mode for 45 s: 23, 22 and 22 OK frames for nodes 1 to 3, 45 `base_health` rows, one `co_threshold` WARNING at 28.4 s, one SIMULATOR session, only `ppe_test.db` created. The full host suite gave 1644 passed and 1 failed: `test_open_state.py::test_both_queries_use_their_indexes` (the SQLite here plans `SCAN episodes`; it fails the same way on the unchanged tree and is not touched by S7). ruff (E9, F) passed after the last edit.
- **Not here.** A Windows run. A browser run of the dashboard on a rehearsal (the TEST banner reads the session mode as before; not looked at on screen). A full four-minute rehearsal through the running host (the host run above was 45 s). The serial drain and `LIVE_FRAME_IN_TEST_MODE` (S7-2). REPLAY (S7-3).
- **Open, found while testing (not part of S7).** Ctrl+C leaves the session open. Reproduced here in SIMULATOR mode by sending SIGINT to a process that has Python's default handler (a console Ctrl+C does): the process exits with code -2 and a KeyboardInterrupt traceback ends in `asyncio.run`, `main()` never reaches `clean = True`, no `CLEAN_SHUTDOWN` row is written and `sessions.ended_ts` stays NULL. By the supervisor's rule a non-zero exit is respawned. A SIGINT sent to a shell background job (which starts with SIGINT ignored) ends with code 0 and a CLEAN_SHUTDOWN row, so that way of testing hides it. The same path runs in LIVE; it is not checked on Windows. Proposed as a small separate part, and worth a check on the field laptop.
