# ADR 0028: Start-up steps 1 to 5, lockfile and failure policy (P24-1)

Status: Proposed (decided in the P24-1 session; confirm at the next design review).
Design: Rev 3.45 is frozen. Nothing in the frame, the migration, `constants.json` or the settings keys changes.

- **Split of P24.** P24 is too big for one stage, so it is five: P24-1 (this: lockfile, steps 1 to 5, failure policy a to d), P24-2 (steps 6 to 10: session open or resume, HOST_START and RECOVERING_ENTER rows, INTEGRITY_FAIL and DB_RESTORED rows, threads, Uvicorn, 1 Hz tick), P24-3 (the real Source and Port behind the API: effect-to-row mapping, feeding AudioThread), P24-4 (`cli doctor`, `fw_version` and ABI check), P24-5 (`scripts/run_supervisor.py` and `cli ack --node N`). Session resume under 30 minutes and `close_session` are P25; P24-2 only opens a session.
- **Where.** `host/ppe_host/main.py` (design 14.5 names no other file). `startup()` takes an injected clock, process table and PID, so tests need no real second process. `main()` stops after step 5 for now and exits 0; P24-2 continues from there.
- **Exit codes.** 0 for a clean exit or a live lockfile (no respawn), 1 for an unexpected exception, 2 for a configuration or database failure. A bad `settings.json` or `settings.local.json` also exits 2 (the design lists only secrets; a host that cannot read its settings must not respawn in a tight loop either way, and exit 2 counts toward the crash-loop guard).
- **Lockfile.** `<PPE_HOME>/ppe_host.lock` (the design names no place), JSON `{"pid", "start"}`, created with O_EXCL. One file for LIVE, SIMULATOR and REPLAY. The start token is `GetProcessTimes` on Windows and `/proc/<pid>/stat` field 22 elsewhere. The Windows path is not run in chat; it is part of the second-PC check (design 13). Stale (PID gone, start time differs, or unreadable content): replaced and logged.
- **Quick check.** A missing file is created, not failed. Before the check the host keeps the bytes of `-wal` and `-shm`, because SQLite deletes an unusable one while opening; a failed check writes them back so the quarantine holds all three files: `<name>.corrupt-<UTC ts>`, `...-wal`, `...-shm`. LIVE restores the newest backup (by file time, any `*.db` in `backup_dir`, pre-migration ones included) that passes `verify_backup`; SIMULATOR and REPLAY restore nothing. The result is kept in `Startup.recovery`; **P24-2 writes the rows** (`INTEGRITY_FAIL`, and in LIVE `DB_RESTORED` with session_id NULL and the `host_gap` reason `db_restored`) because they need `event_seq` and the session.
- **Migration.** A failure after the online backup puts the backup back and exits 2; a database newer than the code exits 2 with no restore (nothing was applied). A failure on a new file leaves no backup to restore and exits 2.
- **Roster on a new file (decision).** Any database file created at start (first run, after a failed quick check with no good backup, or the test database) gets nodes 1 to 3 by `seed_roster`. The design requires it for the test database; without it a fresh LIVE file would reject every frame. An existing database is never touched.
- **Salt.** `server_salt` is checked after the migrations, because "operators exist" needs the database. With no operator it is created (P19b rule); with operators and no salt the host exits 2 and does not create one.
- **Not here.** Log file setup (`logs/ppe_host.log`), `--mode` from a settings key (there is none; the flag only), the supervisor and the exit-2 crash-loop counting (P24-5).
