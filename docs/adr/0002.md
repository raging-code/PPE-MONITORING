# ADR 0002: four firmware values the Technical Summary gives and constants.json does not hold

Status: Proposed (decided in the P15 session; confirm at the next design review).
Design: Rev 3.45 is frozen and `shared/constants.json` has no key for these four values, which the Technical Summary (section 7) states in prose.

Decision: four `#define`s in `firmware/components/rules_fw/man_down.h`, not new keys, so the frozen constants file stays unchanged.

- `MD_IMPACT_WINDOW_MS = 3000`: fall suspicion needs stillness or horizontal posture within 3 s of the impact.
- `MD_CANCEL_MOTION_MS = 10000`: a CANCEL answers a check-in only if chest RMS rises above STILL_G within 10 s of the press.
- `MD_BARE_MOTION_MS = 3000`: raw chest RMS above STILL_G for 3 s answers a stillness-started check-in.
- `MD_CLEAR_SECOND_MS = 5000`: the second clean jacket press of the latch clear must come within 5 s of the 3 s hold.

If the owner prefers real keys, add them to `constants.json`, regenerate, and delete the four defines.

Vector disagreements found in P15 (the vectors and the rules were not edited; `test_rules_fw.c` pins each one with `KNOWN()` so it fails when the disagreement is resolved):

- FW-01 at t=30000: the vector expects `mandown` 0 after exactly 30 s of stillness. The Technical Summary rule is "Stillness >= 30 s", so the node latches at 30000. The vector probably means "just before 30 s". Proposed fix: change the vector's check time to 29900 or its expectation to `mandown` 1.
- FW-02 at t=18200: the vector expects the check-in still pending and `mandown` 0. The rule is "fall-started check-in unanswered for 10 s -> MAN-DOWN", and FW-06 and the D2 row agree (a latch after the 10 s timeout), so the node latches at 10200. Proposed fix: expect `mandown` 1 at 18200, or end the scenario before 10200.
