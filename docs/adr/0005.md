# ADR 0005: WebSocket message fields that design 3.8 leaves open (P18a)

Status: Proposed (decided in the P18a session; confirm at the next design review).
Design: Rev 3.45 is frozen. Table 3.8 names the main fields of each message but not every type, value spelling or nullability. These readings are what `host/ppe_host/api/models.py` encodes; the tests pin them. Nothing in the frame, the migration or `constants.json` changes.

- **`type` collision (needs your confirmation):** every message carries `type`, and an `alert` message also lists an alert `type`. Both can not be one JSON key. The alert's own type is sent as `alert_type`, in the `alert` message and in `snapshot.open_alerts[]`. If you prefer another name, change `AlertBody` and the dashboard reads it.
- **No defaults:** `v` and `type` are required on every message in both directions, so a client message without `v` is rejected, not defaulted. The snapshot's `srv_seq` is the literal 0.
- **0 or 1 versus true or false:** flags that come from database integer columns (`scba`, `mandown`, `co_over_range`, `authenticated`, roster `active`) are 0 or 1, as in the 3.8 snapshot example. Banner flags and `recovering`, `monitoring_active` are booleans, also as in the example.
- **Never-heard node:** the snapshot lists every roster node; before its first verified frame the measurement fields, `level` and the status bytes are null and `link_state` is `not_connected`.
- **`link_state` values:** `not_connected`, `ok`, `weak_signal`, `signal_lost`, `link_lost`, `recovered` (3.8 lists the words with spaces and the example uses `ok`; snake_case follows `no_response` and `movement_detected`).
- **Operators:** `acknowledged_by` on an alert is the operator id; `operator` on an episode and on `scba_correction` is the display name.
- **Other types:** alert `reasons` is one string (the database column), reading `reasons` is a list; `rejected_frames` is one count; `host_power` is a free string (3.8 gives only `ac`); on a `system` message `banner` and `acknowledged_ts` are null except on a banner acknowledgement. The Tier 2 `ml` message is defined with guessed types (`early_warning` and `anomaly_unusual` booleans) and is never sent in Tier 1.
- **REST error envelope:** `retry_after_s` may be set only for `RECOVERING` and for the `UNAUTHENTICATED` answer to a login (the backoff); every other code must send null.
