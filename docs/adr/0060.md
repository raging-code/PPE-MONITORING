# ADR 0060: Ctrl+C and SIGTERM end the host cleanly (S7-4)

Status: Proposed (fixes the open item of ADR 0057; confirm at the next design review).
Design: Rev 3.45 stays frozen. No wire message, endpoint, setting, migration or constants.json change. Design 14.5 (shutdown) and ADR 0037 (CLEAN_SHUTDOWN) already say a stop by SIGINT or SIGTERM is a clean shutdown; this part makes the code do it.

- **Cause.** After Uvicorn has stopped on a signal it puts the old signal handlers back and sends the same signal again (`Server.capture_signals`, Uvicorn 0.54.0 in `requirements.lock`). With Python's default handler that is a `KeyboardInterrupt` out of `asyncio.run` (exit -2). With the system default for SIGTERM it ends the process at once (exit -15). Either way `main()` never reached `rt.stop(clean=True)`: no `CLEAN_SHUTDOWN` row, `sessions.ended_ts` stayed NULL, and the supervisor (exit code not 0) started the host again. Reproduced here with a real host and a real signal before the fix: SIGINT exit -2, SIGTERM exit -15, session 1 open.
- **Fix.** `main.stop_signals()`, a context manager around `asyncio.run` in `main()`. It replaces the handlers of SIGINT, SIGTERM and (where it exists) SIGBREAK with one that only records the signal, and puts the old ones back on exit. Uvicorn takes our handler as "the old one", so its second delivery does nothing. `asyncio.run` returns normally, `clean = True`, `rt.stop(clean=True)` writes `CLEAN_SHUTDOWN` and `main()` returns 0, so the supervisor does not respawn. The log line is `stopped by signal SIGINT`. Handlers are set only in the main thread.
- **Belt and braces.** A `KeyboardInterrupt` that still reaches `main()` is also a clean stop (log line `stopped by Ctrl+C`, exit 0). A crash is still exit 1 and a failed bind is still exit 2; both leave the session open as before.
- **Not changed.** The start-up steps 1 to 9 (a Ctrl+C there still raises and ends with a traceback and an open session, as before; the window is a few seconds and no alert can have been raised yet). The short moment between `asyncio.run` starting and Uvicorn installing its handlers: a signal in it is recorded and ignored, and the operator presses Ctrl+C again. LIVE, SIMULATOR and REPLAY take the same path.
- **Decisions to confirm.** (1) Ctrl+C and SIGTERM are the same clean stop (exit 0). (2) A signal in the few milliseconds before Uvicorn is ready is ignored rather than stopping the host. (3) The start-up window above is left alone.
- **Checked here (development sandbox, Linux).** `host/tests/test_clean_shutdown.py`: 14 tests, 3 runs in a row all passed; 10 of the 14 fail on the unchanged `main.py` (the two real-process ones, which end with exit -2 and -15, and the ones that need `stop_signals`); the other 4 pin behaviour that did not change (a server that returns by itself, a crash is 1, a failed bind is 2, the handlers are back after `main()`). Two of them start a real host with real Uvicorn on a free port, with Python's default SIGINT handler as a console gives it, send SIGINT and SIGTERM, and check exit 0, one `CLEAN_SHUTDOWN` row, no open session and no traceback. The rest of the host suite and ruff are in PROGRESS.
- **Not here.** Windows: a console Ctrl+C, Ctrl+Break (SIGBREAK) and the supervisor on a real console were not run; the two real-process tests are skipped on Windows because a child cannot be sent a console Ctrl+C that way. Please press Ctrl+C once on the field laptop (`python -m ppe_host.main --mode SIMULATOR`), expect `stopped by signal SIGINT` and exit code 0 (`echo $LASTEXITCODE`), and a `CLEAN_SHUTDOWN` row. The Pause control of REPLAY (the endpoint table is frozen; a design change) is still not built.
