# ADR 0024: Top strip and side panel (P22d-1)

Status: Proposed (decided in the P22d-1 session; confirm at the next design review).
Design: Rev 3.45 is frozen. Nothing in the frame, the migration, constants.json, alert_catalog.json, hotspots.json or ws.schema.json changes.

- **Split (guide G2):** P22d does not fit one stage. P22d-1 is the top strip and the side panel. P22d-2 is the event log with CSV and the rejected-frames count.
- **Side panel (3.1, 3.2):** `components/SidePanel.tsx` over `alerts/readings.ts` (pure). Exactly 8 rows: CO; temperature and humidity ("ambient"); chest motion and stillness; battery; SCBA; link and last seen; HR and COHb ("HR not fitted. COHb unavailable"); Details (collapsed: posture, RSSI, SNR). The advisory is one extra line under the rows, not a ninth row. The one CO chart sits in the panel's chart slot. Each part has its own error boundary, so a failed panel leaves the node cards, tray and Resolve working.
- **Thresholds:** battery warn and low, the CO display clamp and the stillness limit (`mandown_still_s`) come from the snapshot constants, with the generated constants as fallback. Nothing is typed in.
- **Stillness (3.2):** the timer shows "still N s of 30 s (backend estimate)" and only after a reading has arrived (the snapshot has no stillness). A latched man-down shows "MAN-DOWN latched" first; the node's own state always wins.
- **Unreliable CO (3.10 test row):** "low confidence: CO sensor out of range" is shown when the reason is `co_range`. For another reason (CO fault, timeout, SHT40 fault) the line is "low confidence: CO sensor unreliable (reason)", because "out of range" would be wrong. The design gives the first text only. A number is never shown for an unreliable CO. **Please confirm.**
- **Reading detail:** the snapshot's node record has no posture, RSSI, SNR or stillness, so `store/reducer.ts` keeps them from each `reading` message (`detail`). A new snapshot clears them, so after a reconnect Details says "no reading yet" until the next frame.
- **Last seen (3.10):** "N s ago" under 60 s (the design's 60), the Manila clock time from 60 s, from server time (`lastSrvTs`), never the browser clock. A clock step back shows "0 s ago".
- **Top strip (3.1):** the chips of minimized alerts are now the first thing in the header after the session row, above the banners, so the header scrolling from the top always shows them. The strip shows LIVE, or TEST for a simulator or replay session. `LiveScreen` still draws the chips itself when used without the Shell (`chipsInStrip` false), which keeps the P22 tests unchanged.
- **Responder switcher (Proposed, please confirm):** the node cards are the switcher: alias, level colour, battery, and now last seen. They stay in the readings area, not in the capped header, because three cards with badges in the header would take most of its 35% on a 768 px laptop. A new alert never switches the selected jacket (unchanged).
- **Layout:** from 1024 px wide the jacket grid and the side panel (24 rem) sit side by side; below that they stack. jsdom has no layout engine, so Playwright must check 1366x768 at 150% zoom (the panel is 24 rem wide, about 384 CSS px, so at 150% zoom the grid gets the rest).
- **Colour:** grey and warning rows in the panel use text colour, an icon and a word on white. No new colour pair is introduced, so the stale-text finding of ADR 0023 is unchanged.
- **Not here (P22d-2):** event log from `GET /api/events` (and the way it pages), CSV button, rejected-frames count with the "check key" message, diagnostics view. Hotspot highlight from a side-panel row and the 3D parts are not built.
