# ADR 0021: system banners, TEST or REPLAY bar, empty states and NOT READY (P22c-3)

Status: Proposed (decided in the P22c-3 session; confirm at the next design review).
Design: Rev 3.45 is frozen. Nothing in the frame, the migration, constants.json, alert_catalog.json, hotspots.json or ws.schema.json changes.

- **Banners (3.4, 3.7):** BASE OFFLINE, RECOVERING, LOGGING FAULT, HOST GAP, HOST POWER and AUDIO FAULT show from the snapshot and the `system` message, with the text of `alert_catalog.json` (`alerts/banners.ts`, pure). They are host state only: no alerts row, no sound in the browser (the host plays them, 3.12), and they never close or hide an alert. Order: level (DANGER first), then `badge_order`.
- **Acknowledge:** only `host_gap` and `logging_fault` get a button (the allowlist of 3.8). A `host_gap` banner is hidden once acknowledged. A LOGGING FAULT banner stays while the host says the fault lasts, even after Acknowledge, and shows "Acknowledged" (3.7: it stays until the cause clears and an operator acknowledges it). A 409 counts as acknowledged (another tab did it). A failed call keeps the banner and shows "The host did not answer. Try again." with no automatic retry.
- **HOST POWER value (open):** `ws.schema.json` types `host_power` as a plain string with no values. Proposed reading: empty, `ok`, `ac`, `mains`, `none` or `plugged` mean mains power and show nothing; any other text means on battery; a number in it is the battery percent. With a percent the banner is the WARNING text "HOST BATTERY n%: plug in"; without one it is the notice "HOST ON BATTERY". The dashboard keeps no battery threshold (the 30% belongs to the host). Please fix the real values in 3.8, or tell me they differ.
- **HOST GAP with `db_restored`:** the catalog text is followed by "Database restored from a backup." (wording Proposed).
- **TEST or REPLAY bar (3.7):** any mode other than LIVE shows a permanent dark neutral bar with no close button: "TEST: simulator data", or "REPLAY: <date and time>". The snapshot carries no replay position, so the time shown is the session start in Asia/Manila 24-hour time (Proposed; correct it if REPLAY should show the replayed data's time).
- **Empty states:** a rostered node with no entry or `last_rx_ts` null is a grey dashed "Not connected" card with no level, and it also says NOT READY while `monitoring_active` is false (my reading of "before the shift it flags NOT READY": before Start monitoring). An empty or all-inactive roster shows "No responders on the roster".
- **Layout:** the mode bar, banners and the P22c-2 audio bar stack in normal flow above the live screen. They are hidden while the red NO LIVE DATA screen covers the page. The 40% tray rule and 1366x768 behaviour with every banner active are P22c-5.
- **Not done here:** the audio_fault row of table 3.4 is still missing (known, expected failure); Playwright rows (banners map to catalog text in a real browser, `host_gap` acknowledge persisting across a reload, no alerts rows) need a real browser and host.
