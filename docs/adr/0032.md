# ADR 0032: The dashboard messages and the snapshot (P24-3b-2a) and the split of P24-3b-2

Status: Proposed (decided in the P24-3b-2 session; confirm at the next design review).
Design: Rev 3.45 is frozen. Nothing in the frame, the migration, `constants.json`, the settings keys or `api/models.py` changes.

- **Split of P24-3b-2 (decision).** **P24-3b-2a** (this one): `reading`, `alert` and `episode` messages and the snapshot. **P24-3b-2b**: `link`, `system` and `advisory` messages, whose sources (Health, the audio thread, the link monitor, `advisory_step`) are wired in P24-3c. P24-3c, P24-4, P24-5 are unchanged.
- **Where (decision, please confirm).** `host/ppe_host/wire.py`, top level next to `host_port.py` (design 14.5 lists no module). `Wire(port, hub).attach()` sets `Ingest.broadcast`, `HostPort.publish` and `HostPort.wire`; `HostPort.snapshot()` is the hub Source's `snapshot`. `Wire.tick()` is the 1 Hz driver for P24-3c (engine tick, held messages, unauth repeats).
- **Bodies come from committed rows.** After the commit wait an alert or episode message is read back from its row, so `alert_id` is the id the REST Acknowledge uses. The alert is found by `event_seq` (no index without `session_id`, ADR 0030 cost note), the episode by node (latest). `Ingested.ctx` carries the reading's inputs, captured under the lock.
- **OPEN, needs your decision: `unpersisted`.** Design 1 says an alert broadcast before its commit carries `unpersisted=1`, but the wire has no such field (3.8, `AlertBody`) and `alert_id` does not exist before the commit. Interim, until you decide: a unit not committed within `commit_wait_ms` is held in `Wire.pending` and its alert and episode messages go out after it commits (readings are not held, so the node card still shows its level); a row the writer rejected has no id, so no message is sent and its `event_seq` goes into `Wire.unpersisted`. The host alarm does not depend on either. Options: (a) add `unpersisted` to `AlertBody` and a provisional id (changes `models.py`, `ws.schema.json`, `ws.ts` and the dashboard; run `just gen`), (b) keep the interim rule. Not built because the generators could not be run in this session.
- **OPEN: Acknowledge of an episode and an already cleared linked alert.** 3.8 says one alert message per linked alert, also for a cleared one. The engine acknowledges only open rows, so only those get a message. Unchanged.
- **Readings.** Every verified frame gives one reading, a duplicate too (`seq_class` says so). `level` is the engine's displayed level, `posture` is `id_mode` bits 4 and 5, `stillness_s` is the host's shadow run (0.0 when none), `reasons` are the reason texts of the node's open alerts (CO rows have none, so the list can be empty).
- **unauth_alert repeats.** A repeat BAD_MAC frame has no effect and no broadcast, so `Wire.tick()` sends the alert again when `unauth_count` changed; the hub keeps its once-per-second limit.
- **Snapshot.** Nodes show the last committed verified non-duplicate frame; `link_state` is `not_connected` until the engine has heard the node since the host started (until P24-3c loads state), never `recovered`. `open_alerts` are the rows with `cleared_ts` NULL, so a reconnect drops a cleared alert that is still unacknowledged (the dashboard keeps those from messages only). `co_history_30m` comes from indexed frames, without duplicates and CO-fault frames. `host_gap` leaves the banners once acknowledged; `logging_fault` follows the writer. `base_offline`, `audio_fault` and `host_power` default to Health, false and `ac` until P24-3c passes the real sources.
