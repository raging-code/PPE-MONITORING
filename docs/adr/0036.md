# ADR 0036: The OS watchdog, the crash marker and the host health events (P24b)

Status: Proposed (decided in the P24b sessions; confirm at the next design review).
Design: Rev 3.45 is frozen (14.5 start-up step 8, section 1 stall timing, 3.8 banners, `s01-config.md` host health). Nothing in the frame, the migration, `constants.json`, `alert_catalog.json`, the settings keys or `api/models.py` changes: every event kind used here (`LIVENESS_RESTART`, `TICK_STALL`, `QUEUE_OVERFLOW`, `LOGGING_FAULT`, `DISK_LOW`, `HOST_BATTERY`) was already in migration 0001.

- **Split of P24b (done).** Part 0 check of the zip; Part 1 code (`io/os_watchdog.py`, the liveness stamps and the watchdog in `runtime.py`, `watchdog_exit` in `main.py`); Part 2 `host/tests/test_os_watchdog.py` (19 tests), four tests in `test_session_start.py` and the start-up side (`consume_marker` in `begin_session`); Part 3 `HostHealth` in `io/health.py`, its wiring and `host/tests/test_host_health.py` (13 tests); Part 4 this ADR. Parts 3 and 4 were delivered as `node patches/*.mjs` scripts (anchored replaces that write nothing when an anchor does not match, and are safe to run twice), not as zips.
- **The OS watchdog.** `OSWatchdogThread` is a daemon thread that checks monotonic liveness stamps every 250 ms (an asyncio coroutine cannot fire while the loop is blocked). Three parts stamp: `serial` (the SerialReader thread, through its `on_alive` hook), `loop` (`serve.loop_beat`, a coroutine that stamps every 250 ms) and `tick` (the last step of `Runtime.tick()`, stamped even when another part of the tick failed, because it says the timer is alive). A part is judged only after its first stamp, so a part that is not running (no serial port in SIMULATOR or REPLAY, no server during start-up) is never a stall. If any stamp is older than `task_stall_s` (3 s) the thread writes the crash marker and calls `os._exit(1)`; the non-zero code makes the user-session supervisor restart the host.
- **The crash marker.** `<PPE_HOME>/logs/crash_marker.json`, written first and atomically (temporary file, fsync, rename). Body: `v`, `kind: "stall"`, `ts`, `pid`, `limit_ms`, `stalled` (the oldest stamp), `age_ms`, `stale` (every stamp over the limit) and `ages`. A failed write never prevents the exit. The next start moves the file to `crash_marker.last.json` (`consume_marker`), so the supervisor's error window can still read it and a second start in a row logs nothing more. A damaged file becomes `{"kind": "unreadable"}`.
- **Start-up side.** `begin_session` reads the marker right after `RECOVERING_ENTER`, in the same transaction, and logs `LIVENESS_RESTART` (detail: the marker as JSON) and, when `tick` was among the stale parts, `TICK_STALL` (detail: `{"age_ms": ...}`). A start with no marker logs neither.
- **Shutdown is not a stall.** `Runtime.stop()` stops the watchdog first, because draining the writer takes seconds; `run_server` retires the `loop` and `tick` stamps when it ends. `Runtime(..., watchdog_exit=None)` builds no watchdog thread (most tests); `main()` passes `os._exit` through `main.watchdog_exit`, which `tests/conftest.py` replaces with a recorder so a test can never kill pytest.
- **Marker path (bug found and fixed).** `log_dir` in `settings.json` is the relative string `logs/`. Part 1 built the marker path as `Path(s['log_dir'])`, which resolves against the working directory; it is now `s.path('log_dir')` (resolved against `PPE_HOME`) at both call sites.
- **`Hub.on_tick` stays unused.** ADR 0035 expected P24b to use it for the liveness stamp. The stamp comes from `loop_beat` and `Runtime.tick()` instead, which proves the loop and the timer separately and needs no change to the Hub. The `on_tick` parameter can be removed in a later clean-up.
- **Host health (`HostHealth`, once a second from `Runtime.tick()`, after `Health.tick`).** `QUEUE_OVERFLOW`: when the writer's `queue_overflow` counter has grown, one event per minute (the event itself goes through the same queue), with the growth and the total. Once a minute the battery and the free disk are read: `HOST_BATTERY` when the laptop goes on battery and again when it falls to `host_bat_warn_pct` (30) or below; `DISK_LOW` when free space is under `host_disk_min_gb` (1.0). Each is logged once at onset and again only after the condition has cleared. The schema has no "back" kind; the banner simply stops. A reader that fails or returns nothing is "unknown" and never an alarm.
- **`host_power` string.** `HostHealth.host_power()` feeds `Wire` (`serve.build_app`): `ac` on mains, `battery` on battery, `battery 22%` only at or below the threshold, because the dashboard (`parseHostPower`) shows the warning whenever a number is present and the notice otherwise. No dashboard change.
- **HOST BATTERY sound (ADR 0035, open item 2: done).** `Runtime.audio_items()` adds `host_power`: level `WARNING` (the beep, rank 5, from `alert_catalog.json`) at or below the threshold, level `NONE` (silent) while only on battery. It is not acknowledgeable; it ends when the laptop is plugged in.
- **`LOGGING_FAULT`.** `DBWriter.on_logging_fault` was complete (one call per distinct SQLite message per minute) but nothing passed a callback. `Runtime` now writes the system event with detail `{"error": ..., "table": ...}`. The banner flag and the sound were already wired (`HostPort.banner_state`).
- **`CLIENT_DROPPED`** was already written by `host_port.py`; nothing to do.
- **Open, please confirm.**
  1. **psutil.** The standard library cannot read a battery. `default_battery()` uses `psutil` only if it is installed; without it the battery is unknown (never "on battery") and HOST BATTERY never fires. `psutil` is not in `pyproject.toml`. Decide whether to add it (the operator laptop needs it for the check to work) or to read the battery with `ctypes` (`GetSystemPowerStatus`) instead. Disk uses `shutil.disk_usage`, stdlib.
  2. **DISK_LOW has no banner.** The design text mentions a warning banner for low disk, but `alert_catalog.json` and the dashboard have no `disk_low` entry. It is a logged event only. A banner needs a catalog entry and a dashboard change, which are outside P24b.
  3. **The thresholds are provisional** (`s01-config.md`: "Values are provisional"). The poll interval (60 s) and the overflow log interval (60 s) are constructor defaults, not settings.
  4. **No supervisor yet.** `os._exit(1)` relies on the user-session supervisor of the design to restart the host within 5 s; that supervisor is a later part. Until then a stall ends the process and nothing restarts it.
- **Tests.** `test_os_watchdog.py`: stamps, healthy and never-stamped parts, a stall writes the marker before `exit_fn`, the worst of several stale parts, a failed marker write still exits, `run`/`stop`, and the marker round trip, damaged and double-consume cases. `test_session_start.py`: `LIVENESS_RESTART` with the body, `TICK_STALL` only when `tick` was stale, an unreadable marker, consumed once. `test_host_health.py`: the `host_power` string, the once-a-minute reads, battery levels and re-arming, `DISK_LOW`, unknown readings, `QUEUE_OVERFLOW` rate limit, custom thresholds, the Runtime wiring, the audio items, the beep rank and the `LOGGING_FAULT` event. `test_serve.py` stubs gained the `host_health` part. `test_adr0036.py`: this file exists, is Proposed, and the docs point to it.

## Review decision (2026-11-28)

Decided by the project owner (design-review preparation): (1) The poll interval and the overflow log interval (60 s each) are **accepted for the trial**; they only drive logging, not alarms. (2) For the battery, **read it with `ctypes` and `GetSystemPowerStatus` instead of adding `psutil`**: the host is Windows-only (it uses `winsound`), so this adds no dependency to the lock files or the release folder. Without `psutil` the HOST BATTERY warning never fires, which is a worse failure than a missing feature. Not built; check the code first for whether a later part already changed this. (3) DISK_LOW stays a logged event with no banner for the trial. Status stays Proposed until the design review.

Built in ADR 0069.
