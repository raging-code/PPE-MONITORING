# ADR 0011: SCBA correction and banner acknowledgement (P19c-2)

Status: Proposed (decided in the P19c-2 session; confirm at the next design review).
Design: Rev 3.45 is frozen. Nothing in the frame, the migration or `constants.json` changes.

- **Two new Port methods** (the routes stay free of engine work; P24 builds them): `set_scba_correction(node_id, note, operator_id)` keeps the live correction and returns `(recorded_ts, operator name)`, or None when the node is not in the roster (404). `ack_banner(kind, operator_id)` returns `(kind, acknowledged_ts)`. The routes write the audit rows through `port.audit`, as in ADR 0007.
- **What the real port must do.** SCBA correction: `recorded_ts` must be the `ts` of the `SCBA_CORRECTION` audit row, because the replay below reads that row; the live state and the audit row must succeed or fail together; the commit uses `synchronous=FULL` (2.10). The correction is display state only: the rule engine has no input for it, so it cannot clear `scba_expired` or suppress an ambient CO alert (by construction, not by a test; P24 must keep it that way). Banner ack: acknowledging an active banner again returns the first `acknowledged_ts`; the host sends the `system` WebSocket message with the kind and time (P20).
- **Banner answers (3.8 gives the codes, not the cases):** `host_gap` and `logging_fault` are acknowledgeable; the other five banners of `alert_catalog.json` (`no_live_data`, `base_offline`, `recovering`, `host_power`, `audio_fault`) give 400 BAD_REQUEST; any other kind gives 404 NOT_FOUND; a banner that is not active gives 409 STATE_CONFLICT (proposal: nothing to acknowledge). The seven names are listed in `api_rest.BANNER_KINDS` and a test compares them with the catalog. A repeat acknowledgement is audited again, as `ACK_ALERT` is. The `BANNER_ACK` row carries the kind in `reason`.
- **SCBA audit row:** node in `node_id`, the note in `reason`, so the replay needs no other column.
- **Replay from `audit_events`:** `io/db_writer.load_scba_corrections(conn)` returns `{node_id: (recorded_ts, operator)}`: the latest `SCBA_CORRECTION` of each node from any session (so End shift and a restart keep it), dropped once a later verified frame of that node shows a different SCBA bit (`id_mode` bit 3) or `scba_expired` bit (`status3` bit 3) than the node had at the time of the correction. That baseline is the last frame at or before the correction, or the first frame after it when none exists (proposal; 2.10 is silent). Only frames with `verify = 'OK'` and `seq_class` fresh or reboot count, because a duplicate or suspect frame must never lower state. A change that later changes back does not bring the correction back. P25 calls it at restart; P24 uses it for the snapshot field `scba_correction`.
- **Not decided by the design, left open:** a limit on the length of `note` (no number exists, so none is enforced; the audit `reason` column is unbounded) and whether `node_id` outside 1 to 3 should be 422 instead of 404 (3.8 lists 404 only).
