# ADR 0020: Test sound, Start monitoring gate, Web Lock owner and screen state (P22c-2)

Status: Proposed (decided in the P22c-2 session; confirm at the next design review).
Design: Rev 3.45 is frozen. Nothing in the frame, the migration, constants.json, alert_catalog.json, hotspots.json or ws.schema.json changes.

- **Gate (3.9, 3.12):** Start monitoring stays disabled until the Test sound tone has played. Test sound creates the `AudioContext` inside the click, resumes it and plays one 0.4 s, 880 Hz tone (module constants `TEST_TONE_S` and `TEST_TONE_HZ`: no design value, same approach as ADR 0001). A test tone alone unlocks nothing.
- **Unlock before the host answers:** Start monitoring first resumes audio, takes the Web Lock and asks for the wake lock, then sends `POST /api/session/start`. A host that does not answer leaves audio unlocked and shows "The host did not accept the start yet. The host alarm still sounds. Click Start monitoring again." because the browser siren exists for the day the host is dead. The REST call is idempotent (3.8), so a second click is safe. The host alarm is never gated (3.12).
- **Reload:** the page forgets the audio unlock, so after a reload the bar shows the gate again even if the host says `monitoring_active` is true. One Test sound and one Start monitoring click return it; the host records no second START_MONITORING row.
- **Audio owner (3.3):** the tab that clicks Start monitoring takes the Web Lock `ppe-siren-owner` (`ifAvailable`). Another tab that clicks gets none, shows "Sound in another tab" and plays nothing. It queues a second request; when the owner closes, that request is granted, the tab shows "SIREN OFF: click to enable", and one click takes over (a browser needs the gesture). Tabs that never clicked Start monitoring ask for no lock. No Web Locks API: one tab is assumed.
- **Unlocked means playing:** `audioStore.unlocked` is true only while this tab owns the siren and the audio clock is `running`, so the P22c-1 siren cannot play from two tabs or from a suspended context.
- **SIREN OFF (3.9):** `gate.check()` runs on every 1 Hz tick that arrives on the data socket (not a page timer). A suspended or interrupted context shows "SIREN OFF: click to enable" (a silent `resume()` is tried first); one click resumes it. "Siren ON" shows while it plays.
- **Wake lock (3.7):** requested at Start monitoring, re-requested every time the tab becomes visible, and "Screen may sleep" shows while it is lost, refused or unsupported (a browser releases it when a tab is hidden, so the badge appears while hidden and clears on return).
- **Hidden tab (3.7):** "Dashboard was hidden: alarms may have been delayed" shows on return after any hidden period (the design gives no minimum length) and stays until the operator clicks Dismiss (Proposed). It creates no `alerts` row.
- **Where it shows:** a bar above the live screen, and inside the red NO LIVE DATA screen (a reload with the host down must still be able to unlock the siren). Never on Login. The bar is in normal flow; the 40% tray rule and 1366x768 layout are P22c-5.
- **Not done here:** SIREN OFF while the page is closed is not detectable; real `AudioContext`, Web Locks and wake lock behaviour were tested only with fakes and belong to Playwright (D8: Start monitoring unlocks audio, two tabs, hidden tab, wake lock re-acquired). The system banners (BASE OFFLINE, AUDIO FAULT and the rest) are P22c-3.
