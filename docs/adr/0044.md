# ADR 0044: requirement traceability (P27b-2)

Status: Proposed (decided in the P27b sessions; confirm at the next design review).
Design: Rev 3.45 is frozen (8.1: `requirements/requirements.yaml`, test names carry REQ ids, CI fails on an unknown id; 7: hazards H1 to H22 map to REQ ids). No host behaviour, frame, migration, constant, setting or REST route changes. P27b is split in three: P27b-1 (ADR 0043, done), this part (P27b-2: the file, the hazard map, the check for unknown ids) and P27b-3 (REQ ids in test names, and the "Spec item has no test" check). P27b-3 is not started.

- **Id scheme.** `REQ-<AREA>-<nnn>`: an area of two or three capitals and three digits. The design gives no REQ ids, so these are new. 12 areas: API, AUD, DB, FW, ING, ML, OPS, REC, RUL, SEC, SES, UI (listed with their meaning at the top of the file). **An id is permanent once it exists.** A new requirement takes the next number in its area; a number is never reused or renumbered, because a test will name it.
- **One requirement per row of the design 8 test table.** There are 74 rows, so 74 requirements, in table order, numbered per area. Each carries the row's name as `title`, `source` (`8, test table row n`) and the D-tests the row names. A test table row is the one place where the design states a pass condition, so it is the unit "a statement a test covers" can be tied to without me inventing statements. A finer split (one id per sentence of a row) is possible later, by appending ids; it would not renumber anything.
- **Status.** Every requirement is `Proposed`: design 8 is headed "(Proposed)" and no row says otherwise. The check accepts `Spec`, `Proposed` and `Decided`. Promoting a requirement to `Spec` or `Decided` is a design-review decision and is not made by code. **Until one is promoted, P27b-3's "Spec item has no test" check has nothing to check**, which is the honest state: the design has not marked these rows Spec.
- **Hazards.** H1 to H22 are in the file with the title of design 7, each mapped to 1 to 6 requirements. The mapping is my reading of the mitigation column of design 7 against the rows of design 8 and the D-tests named; it is Proposed like design 7's own host mapping. Thin spots, stated plainly: H9 maps to one row (battery latch), H15 to one (origin and token), H1 to two (golden vectors, battery latch), because design 8 has no row for the link-state tracker as such, and D9 and D11 (soak and hardware tests) are not host tests. A hazard whose only tests are D9 or D11 cannot be covered by this repository's tests alone.
- **The check (`tools/check_requirements.py`).** Exit 1 with one line per problem when: an id is not `REQ-<AREA>-<nnn>`, its area is not listed, an id is duplicated, a status is not one of the three, a title or source is missing, a `dtests` entry is not `D<n>` or `D-FW`; a hazard H1 to H22 is missing, maps to nothing, lists a requirement twice or names one that does not exist, or the file has a hazard outside H1 to H22; or a test file names an id that is not in the file. Test files are `host/tests/*.py`, `dashboard/tests/*.ts(x)` and `e2e/tests/*.ts`. Any token shaped like `REQ-letters-digits` counts, so a typo (`REQ-API-12`, a lower-case area) is reported instead of ignored. `--report` lists the requirements and hazards that no test names yet (information; there are none today). Needs pyyaml, which is in `requirements-dev.lock`.
- **Wiring.** `just lint` and the CI host job run it after the import rule and before ruff and pytest. `host/tests/test_requirements.py` (25 tests): the real file passes; it holds exactly the rows of `docs/design/s08.md` with their titles and D-tests; ids run from 001 without gaps per area; the hazard titles equal the ones in `docs/design/s07.md`; an unknown id in a Python, Vitest or Playwright file is reported with file and line; a typo is reported; other folders and `node_modules` are not scanned; 12 kinds of malformed file are each reported; the tool exits 1 on a bad tree; `just lint` and the CI job run it in order. The test file builds its fixture ids from pieces, so it never contains an id-shaped token itself.
- **Not done here (P27b-3).** Adding ids to the names or docstrings of the existing tests, and failing when a `Spec` requirement has no test. Today no test names an id, so the unknown-id check passes because there is nothing to compare, and the tests prove it catches a planted one.
- **Checked here (development sandbox, Linux).** The new tool and `doc_lint.py` and the import rule pass on the patched tree; the 25 new tests and the 40 tests of `test_ci_config.py` pass. The sandbox had no network, so pytest, ruff, FastAPI and Pydantic were not installed: those tests ran under a minimal local stand-in for pytest, and **the full pytest suite, ruff and Biome were not run** after this change. Both mutation checks fail as they should (a planted unknown id in a test file; hazard H22 removed). **Not checked:** Windows, GitHub Actions.
- **Open, please confirm.** (1) One requirement per design 8 row. (2) The hazard mapping, especially the thin ones above. (3) All 74 stay Proposed until a design review promotes some. (4) Ids are permanent and never renumbered. (5) Only test folders are scanned for ids, not the design or other docs.
