# ADR 0063: The host leaves with the exit code main() chose (S7-6)

Status: Proposed (follows ADR 0060; confirm at the next design review). No wire message, endpoint, setting, migration or constants change.

- **Found.** The first Windows run of S7-4 (Windows PowerShell, Python 3.12, Uvicorn 0.54.0) showed the data side of ADR 0060 working: the log said `stopped by signal SIGINT`, `sessions.end_kind` was `CLEAN_SHUTDOWN` with an end time, and the last system events were `CLEAN_SHUTDOWN` and `INTEGRITY_OK`. But `$LASTEXITCODE` was `-1073741510` (0xC000013A, STATUS_CONTROL_C_EXIT) after a single Ctrl+C, in two runs (SIMULATOR and REPLAY). A supervisor reads a non-zero code as a crash and restarts the host, which is what ADR 0060 was meant to stop. The CLEAN_SHUTDOWN row is written inside `rt.stop()`, so the process was ended by Windows after the work was done, between the end of `main()` and the end of the interpreter.
- **Cause.** Not proven. It could not be reproduced in the Linux development sandbox. The working explanation is that Windows reports an unhandled console control event for the process while it winds down (the first run also logged the signal twice, `SIGINT, SIGINT`, where Linux logs it once).
- **Fix.** `main.finish(code)` is the last step of `python -m ppe_host.main` (`finish(main())`, was `sys.exit(main())`). It sets SIGINT and SIGBREAK to ignore (the work is done), logs `host stopped, exit code N`, flushes the log and the standard streams, and leaves with `os._exit(code)`. `os._exit` skips only the interpreter's own teardown; the runtime, the writer and the database were already closed by `main()`. Exit codes are unchanged: 0 clean, 1 crash, 2 configuration or bind. `main()` itself, `stop_signals()` and everything the tests call are unchanged.
- **If it is not enough.** The log line `host stopped, exit code 0` is the check: if it is printed and the code is still -1073741510, the event arrives before `finish()` runs and the next step is to find where; if it is not printed, the process ended earlier than `finish()`. Either way the next run says which.
- **Not changed.** The `CancelledError` traceback that Uvicorn printed in the first Windows run (lifespan task cancelled at shutdown). It did not appear in the second run, so it is not understood yet and may depend on timing or on what is connected.
- **Also in this part.** A fix to my own S7-5b test: `test_e2e_config.py` named REQ-API-007 in a function docstring, and `test_requirements.py` requires the ids to be in the module docstring. The S7-5b patch passed the files I ran, but I had not run the whole suite; this part's run did. The id moved to the module docstring.
- **Checked here (development sandbox, Linux, Uvicorn 0.54.0 from the lock file).** `test_clean_shutdown.py`: 18 tests (14 from S7-4 and 4 new: `finish` ignores Ctrl+C, flushes and passes the code on, passes 1 and 2 through, and is what the module entry point calls), 3 runs in a row all passed; 6 of the 18 fail on the unpatched `main.py`; the two real-host tests (real Uvicorn, real SIGINT and SIGTERM) now also check the new log line. Full host suite: 1765 passed, 3 xfailed. ruff, check_requirements pass.
- **Not here.** Windows. Please run the host once on the laptop, press Ctrl+C once, and then run `echo $LASTEXITCODE`: expect 0 and the line `host stopped, exit code 0`.
