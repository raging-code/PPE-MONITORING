# ADR 0058: serial drain and LIVE_FRAME_IN_TEST_MODE (S7-2)

Status: Proposed (implements design 3.10 and design 1, Operating mode isolation; confirm at the next design review).
Design: Rev 3.45 stays frozen. No wire message, endpoint, setting, migration or constants.json change. `LIVE_FRAME_IN_TEST_MODE` has been a seeded `system_event_types` kind since migration 0001.

The design line: in SIMULATOR or REPLAY, incoming serial frames are drained only to detect accidental live hardware traffic, raising LIVE_FRAME_IN_TEST_MODE if valid MAC-verified frames arrive, and are never ingested.

- **Module.** `host/ppe_host/services/serial_drain.py`: `LiveTrafficDetector(clock, emit, key, sys_id, every_s=60)`. Its `on_item(kind, payload)` is the callback of a second `SerialReader`. It imports only `core.crypto_abi`; it opens nothing.
- **Valid means the host says so.** A frame counts only if `crypto_abi.verify_frame(raw, cmac_key, sys_id) == 'OK'` (23 bytes, CRC-8, AES-CMAC of this host's key and sys_id). The base's own `base_verify` is not trusted. A frame of another system (other key or sys_id), a short or damaged frame is counted in `drain_frames` and ignored. Heartbeats are counted and ignored (a base with no node in range still sends them, and that is not node traffic).
- **One row, not a flood.** The first valid frame writes a `LIVE_FRAME_IN_TEST_MODE` row at once (`Ingest.system_event`, not droppable) and an ERROR log line. After that at most one row per 60 s of the injected Clock's mono time. Detail JSON: `{"base_id", "node_id", "seq", "valid_frames"}`, where `valid_frames` counts the valid frames since the previous row. A clock that goes backwards does not silence the event.
- **Runtime.** `Runtime(..., drain=True)` builds the detector and a `SerialReader` named `SerialDrainThread`, started after the writer and stopped before the simulator, CLEAN_SHUTDOWN and the writer. `drain=True` in LIVE raises ValueError before anything is built. The default is False, so tests that do not care open no port. `main()` passes `drain=st.mode != 'LIVE'`, so SIMULATOR and REPLAY drain and LIVE does not.
- **Nothing is ingested.** Drain items never reach the pre-replay gate, Ingest.frame, `Health.seen()` (so a live base cannot hide BASE OFFLINE of a test session), the rule engine or the frames and base_health tables. Nothing is written to the port: no SerialWriter and no host_tick in test modes.
- **Port trouble is quiet.** A missing or busy port (the normal case on a laptop with no base) is retried every `serial_retry_s` and logged as one warning per outage. It writes no SERIAL_LOST or SERIAL_BACK row, because those rows are about the live link. The port is opened as in LIVE (`open_serial`: DTR and RTS False before open, so the base is not reset).
- **Liveness.** The drain stamps its own name `drain` for the OS watchdog, not `serial`, so a stalled simulator is still seen when the drain is alive.
- **Tests never open a real port.** `tests/conftest.py` gains an autouse fixture that makes `runtime.open_serial` raise OSError (a developer's machine may have a base on COM4).
- **Decisions to confirm.** (1) Valid = host-verified, not `base_verify`. (2) At most one row per 60 s, with a count, instead of one row per frame or one per run. (3) The event is a `system_events` row and a log line only: no banner, no alert, no audio, no wire change (the catalog has no entry for it). (4) The drain's counters (`drain_frames`, `drain_valid`, `drain_events`) are not added to the COUNTERS row. (5) A busy or missing port is silent in the database. (6) A live base wired to a test host is not stopped or refused; the operator sees the row after the fact.
- **Checked here (development sandbox, Linux).** `host/tests/test_serial_drain.py`: 24 tests (detector, runtime in SIMULATOR and REPLAY, missing port, cable pulled, thread names and liveness, LIVE refusal, main in all three modes, this ADR). Results are in docs/PROGRESS.md.
- **Not here.** A real base on a real COM port and Windows. REPLAY itself (S7-3). The Ctrl+C clean-shutdown fix (open since ADR 0057).
