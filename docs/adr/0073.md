# ADR 0073: export the readings of each firefighter (S8-4a host, S8-4b dashboard)

Status: Proposed (decided with the operator on 2026-11-28; confirm at the next design review).

Design: Rev 3.45 stays frozen. This ADR adds one endpoint to the REST list of design 3.8 (19 to 20). No migration, no new audit action, no wire message, no setting and no new error code. The frozen CSV of design 2.5 (v_full_log) is not changed.

## Why

ADR 0070 to 0072 store who wears which jacket, with history, and the jacket check asks the operator to confirm it before Start monitoring. A stored reading belongs to a person only through that history (node and time). Nothing yet gave the readings back with the person next to them, which is what the forecasting work and any per-firefighter review need.

## Decisions

- **A. A separate file, the frozen CSV stays as it is.** `GET /api/firefighters/readings.csv` (optional `?session_id=`; omitted = every session in one file) streams text/csv. The full export (`/api/export.csv`, v_full_log) keeps its columns, so no frozen design item changes.
- **B. One row per reading.** The rows of `v_readings` (a verified frame that is not a duplicate), ordered by session_id and event_seq. Columns: `session_id, event_seq, rx_ts, firefighter, node_id, co_ppm, temp_c, hum_pct, hr, motion_g, bat_pct, scba_on, mandown, final_level, reasons`. The values are decoded the same way as in v_full_log; `hr` is the stored heart-rate value of the frame. No raw_hex.
- **C. The join is by node and time.** A frame gets the firefighter whose assignment on that node has `start_ts <= rx_ts` and (`end_ts` open or `rx_ts < end_ts`). At the hand-over instant the reading goes to the new wearer. If a clock step ever made two assignments overlap, the one that started last wins, so every reading has exactly one row. A reading from a time when nobody was assigned to the node has an empty `firefighter` field: it is kept and never guessed.
- **D. Alias only.** The column holds FFR-NN. The name, the age, the weight and every other profile field are not in the file (ADR 0071 D: the name is on the Settings screen only). A person set inactive keeps their old readings under the same alias, and the readings after the change are empty.
- **E. Audit.** The existing action `CSV_EXPORT` is written before the first byte, with the reason `firefighter readings, all` or `firefighter readings, session N`, so the log tells the two files apart without a new action (and without Migration 0008). A refused request (401, 403, 422) writes no export row.
- **F. Same file rules as the full export.** Formula protection (a leading apostrophe for =, +, -, @, tab and CR), numbers as plain numbers, an empty field for a missing value, a read-only connection, 500 rows per fetch, one chunk per fetch, `Cache-Control: no-store`. File name `firefighter_readings_all_<UTC stamp>.csv` or `firefighter_readings_session_<N>_<UTC stamp>.csv`.
- **G. Dashboard.** Settings has a button 'Download readings by firefighter' under the firefighter list. It uses the same authenticated fetch, blob and object URL as the other CSV downloads (never a plain link, which carries no Authorization header) and shows one sentence of result.

## Not here (open points)

- **No profile numbers in the file.** Age, weight, resting heart rate and the other profile values are what a forecasting model needs next to the readings, but they identify a person more easily in a small unit. Adding them (as an option, or as a second file) is a decision for the data-governance owner; the alias already lets the analyst join them under the owner's rules.
- **A reading is linked to a person only as well as the assignment is right.** End shift still keeps the assignments (ADR 0072), and the jacket check runs once per page load, so a second shift run from the same page is not asked again.
- Editing a profile and withdrawing consent have no route yet. A person who withdraws consent would have to be removed from this export; that rule is not defined.
- Any logged-in operator may download the file, like every other export; an admin role is a question for the data-governance owner.
- No Python or CLI command for the same file; the REST route is the only way.
