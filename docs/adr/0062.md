# ADR 0062: The Pause control of a REPLAY dashboard (S7-5b)

Status: Proposed (confirm at the next design review). Dashboard side of ADR 0061; no host, wire, endpoint or migration change.
Design: Rev 3.45 stays frozen. The dashboard words are added to the REPLAY pause addendum at the end of `docs/design/s03-8.md`. The look follows 3.7 (the TEST or REPLAY bar is dark and neutral, never a level colour).

- **What.** A bar under the mode bar, `ReplayBar` (`data-testid="replay-bar"`), shown only when `session.mode` is `REPLAY` and the host sent the `replay` block (an older host sends none: no bar, the mode bar stays). It has one status line and one button. Status: `Replay running, ×16`, `Replay paused, ×16` (with a pause icon) or `Replay finished`. Button: `Pause replay` or `Resume replay`, at least 44 px high like every other button. The bar cannot be dismissed.
- **State is the host's.** The store has a new `replay: ReplayInfo | null`, set by the snapshot and replaced by every system message (a message without the field sets `null`, so a host that stops being REPLAY loses the bar). The button asks for the opposite of what the host last said: `POST /api/replay/pause {paused: !current}`. On 200 the store takes `{paused, finished}` from the answer at once; the host's own system message says the same to every other screen, and a reload reads it from the snapshot. A refusal or a failure changes nothing in the store.
- **Presses.** Disabled while a press is on its way (a double click sends one request), while the host is recovering (the host would answer 409 RECOVERING) and once the replay has finished (the host would answer 409 STATE_CONFLICT). One sentence under the status for every refusal: not started yet, finished, not signed in, host did not answer, not accepted. The next press clears it.
- **Not shown** on the red NO LIVE DATA screen (the header is not drawn there, as for every other bar).
- **Files.** `src/alerts/replay.ts` (pure words), `src/store/replay.ts` (`setReplayPaused`), `src/components/ReplayBar.tsx`, `postReplayPause` in `src/api/actions.ts`, `replay` in `src/store/reducer.ts`, one line in `Shell.tsx`. The pause icon is two drawn bars: the character U+23F8 has no glyph in the bundled Inter (the browser showed a small square), and no font is added.
- **Mock host.** `e2e/mock_host.mjs` gains `/__ctl {"replay": true|false, "replay_finished": true}` and `POST /api/replay/pause` with the host's answers (200, 401, 409 STATE_CONFLICT, 422), a system message to every signed-in data socket on a change and none for a repeat, `replayPauses` in `/__state`, and `--print-replay` (a snapshot and a system message with a replay block). `test_e2e_config.py` checks those two messages against the host's Pydantic models.
- **Decisions to confirm.** (1) Running also has a status line (`Replay running, ×16`), not only paused. (2) The button is disabled while the host is recovering rather than sending a request that is refused. (3) No speed control (ADR 0061 decision D stands).
- **Checked here (development sandbox, Linux, Chromium).** Dashboard: `tsc --noEmit`, `biome lint` and Vitest pass (328 passed, 1 expected failure that was there before; 29 new tests in `replay_logic.test.ts` and `replay_ui.test.tsx`; both files fail against the unpatched source). Browser: `e2e/tests/replay_pause.spec.ts`, 4 tests against the built dashboard and the mock host (no bar for a simulator host; Pause and Resume reach the host and the words follow; a second screen and a reload show the host's state; a finished replay disables the button), and the other 15 browser tests still pass. A screenshot at 1366 px showed the bar under the mode bar.
- **Not here.** A run against the real host (the mock answers like it, the real route is covered by `test_replay_pause.py`, but no browser was pointed at a real REPLAY host). Windows and a real laptop screen. A touch-screen run. A speed control.
