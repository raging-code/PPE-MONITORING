### 3.12 Alarm model: host is primary

- The host plays priority-ordered WAV alarms through the OS audio API (MAYDAY above man-down above DANGER above WARNING). Acknowledge over REST stops the sound for that card only; Resolve and clearing follow the existing rules. The host alarm runs in AudioThread (Section 14.5 thread map) in the user desktop session, with stdlib winsound.

- The browser shows visual alerts only, plus the NO LIVE DATA siren, which is the only browser-primary alarm because it must work when the host is dead.

- Removed from Tier 1: the audio_unlocked heartbeat, the rule "play local laptop alarm when zero tabs report audio_unlocked", the ALARMS SILENT banner, the periodic sound-check chime and strip. Playwright tests for these are deleted. Added tests: host alarm starts within 300 ms of broadcast (mocked audio sink); Acknowledge stops it; a second DANGER during an acknowledged one restarts the sound; NO LIVE DATA siren plays in the browser when the WebSocket is down for more than the existing threshold.

- Host audio self-check (replaces the removed browser sound check). (a) Every host_chime_interval_min = 15 minutes, while no safety alert is unacknowledged, the host plays a two-note ascending chime that differs from every alarm sound. (b) Every audio_check_interval_s = 60 the host verifies the audio path: a playback call that raises (no device, device removed) writes system_events AUDIO_FAULT once and shows an AUDIO FAULT banner; the next successful playback writes AUDIO_OK and clears the banner. (c) Optional, Proposed: if the Windows endpoint can be read (pycaw/comtypes, a Windows-only dependency recorded in the lock file), a muted endpoint or a volume below host_volume_min_pct = 30 also counts as AUDIO FAULT. If that dependency is rejected, the chime in (a) and the shift-start check are the only mute detection, because the operator must hear them. (d) AUDIO FAULT is a non-acknowledgeable system banner: add one entry to alert_catalog.json (banners 6 to 7, total 32 entries) and the two kinds to system_event_types (done in Migration 0001). audio_check_interval_s, host_chime_interval_min and host_volume_min_pct are host-only keys in settings.json.

- Browser audio: only the NO LIVE DATA siren remains. It still needs a user gesture, so the existing Test sound before Start monitoring gate stays and is the only browser audio step. One tab owns the siren (Web Lock); if the owner closes, another tab shows SIREN OFF: click to enable. A hidden or throttled tab cannot be relied on, so the siren is secondary and the host alarm plays regardless. Tests replaced in Section 8 (D8): host alarm starts within 300 ms of broadcast (mocked sink); AUDIO_FAULT then AUDIO_OK on a failing then working sink; the 15 minute chime is suppressed while a safety alert is open; the siren gate blocks Start monitoring until the test tone has played; the NO LIVE DATA siren plays when the WebSocket is down. Sound files (Rev 3.28, Proposed): the host plays WAV files, not generated tones. tools/gen_sounds.py generates siren.wav, beep.wav, one_beep.wav, chime.wav (Tier 2 advisory) and host_chime.wav (the two-note 15 minute check, different from every alarm) at fixed relative volumes (chime about a quarter of beep, beep quieter than siren, as in 3.4). The files are committed in host/sounds/ with a SHA-256 manifest. At start-up the host checks every file against the manifest, and a missing or altered file raises AUDIO_FAULT. The names in sound_by_level map to files one to one; siren_60s_silence is the browser siren and has no WAV. A test fails if any sound name used in alert_catalog.json (other than none and siren_60s_silence) has no file. Host-side stop with no browser open (Rev 3.28): the CLI command python -m ppe_host.cli ack --node N calls the same REST Acknowledge with an operator token, so it is audited as ACK_ALERT and follows the same rules (it silences that card only, and never closes a safety alert). No timed silence of the host alarm is added, because a silenced and unacknowledged safety alarm would be a new hazard; Acknowledge is the one audited way to stop it. Audio probe (Proposed, verify at the bench): winsound SND_ASYNC may not report a device failure, so while no alarm is sounding the 60 s self-check plays a 100 ms silent WAV synchronously and treats a RuntimeError as AUDIO_FAULT; while an alarm is sounding, a failed play call counts as the fault. Start monitoring does not gate the host alarm (Rev 3.29, Proposed; confirm with the adviser): the host stores frames from host start (2.3), so it also plays the alarm for any verified safety alert from host start. Start monitoring only unlocks browser audio and the wake lock, records the operator and starts the monitoring_active flag. A test in Section 8 sends a man-down frame before Start monitoring and expects the host alarm on the mocked sink.

- The manual speaker check stays in the pre-trial checklist: at the start of each shift the operator plays the host test alarm from the CLI, and the result is recorded in the shift record.
