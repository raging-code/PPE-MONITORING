### 3.11 Decisions (23 Nov 2026)

- Several alerts at once: shown together in one tray, none overlapping (decided).

- 3D view failure: readings and alerts never depend on the 3D view (decided rule).

- Trend: one small CO chart per responder (decided).

- Look: green, yellow and red for normal, warning and danger, with few widgets and little text (decided).

- Platform: laptop only in Tier 1. Tablets and TLS are Tier 2 (Proposed).

- Roles: none in Tier 1. Every operator can Acknowledge and Resolve, and each action is logged by name. Fewer rules means nobody is blocked in an emergency (Proposed).

- Login token: no expiry in Tier 1 (Rev 3.27, 4.1). A token is replaced only by the CLI rotate-token between shifts or when an operator is removed. A failed attempt adds a short delay that grows to 5 s, with no lockout (Proposed). A disabled operator is always rejected on login, REST calls and WebSocket auth.

- CSV export: the full log only. The base heartbeat counters stay in the database and are not in the CSV (Proposed).

- Event log: shows alerts, state changes, operator actions and system events. Rejected frames (bad signature, length or CRC) show as one count with the "check key" message and an optional diagnostics view, off by default. All rows stay in the database (Proposed). The log is filled after a reload or reconnect from GET /api/events (3.8) and then follows the live messages (Rev 3.40, Proposed).

- Model status panel: Tier 2 only, collapsed by default, because Tier 1 runs no models (Proposed).

- Acknowledged man-down: no reminder tone (decided). Silent escalation by sight and hazard H11 cover the risk (Proposed).

- Latch cleared while an episode is open: the dashboard waits for an operator to Resolve (decided).

- End shift: never blocked while an alert is active; it carries open items into a new session (decided).

- Episodes: the backend never opens one itself; only the node's latch does (Proposed, 2.3).

- Database sync: synchronous=FULL (Proposed, 2.1).

- Left to the design (Proposed): pop-up wording and sounds (3.4), advisory display (3.5), look and accessibility (3.6), empty states (3.7), interface technology (3.8), alarm reliability (3.9), fault map, time and sessions (3.10), tests (section 8).
