### 2.10 Durability and the commit path

- One bounded, ordered writer queue replaces the writer queue plus RAM retry buffer. A failed commit retries the head item in place and nothing overtakes it, so FK order is preserved without a separate drain step. The commit_wait_ms = 120 ms bound and the unpersisted=1 fallback remain, as a flag on the queue item. [Rev 3.27: replaced by one bounded ordered writer queue, 2.10] Rev 3.36: retrying in place applies to transient errors only (busy, locked, disk I/O, disk full); a constraint or binding error is never retried in place and never blocks the queue (deterministic-failure rule in the commit paragraph of Section 1).

- The 130,000-frame benchmark of Section 9 now also records p50/p99 commit time for synchronous=FULL on the target laptop with its antivirus running. Rule: keep FULL if p99 is 50 ms or less. If it is above 50 ms, use WAL with synchronous=NORMAL. A power cut can then lose the last committed transactions but cannot corrupt the database, and node latches are resent every 2 s so a safety state is re-raised after restart. Operator actions (Acknowledge, Resolve, End shift, SCBA correction) are always committed with synchronous=FULL (set the pragma on the writer connection before BEGIN, then set it back), so only frame, advisory and routine rows are exposed to loss. The accepted loss is the last few seconds of frames and routine rows, and it is recorded in the as-built record.

- Watermark checkpoints (SHA-256, about 1.3 KB) are not built in Tier 1. Restart recovery rebuilds from open alerts and episodes plus the last 30 minutes of frames (the fallback path that must exist anyway). Checkpoints are added only if the benchmark shows chunked recovery above 3 s. Section 5 RECOVERING stays 3 s. Operator-supplied state that frames cannot rebuild (SCBA_CORRECTION) is re-applied from audit_events, not from the last 30 minutes of frames: the latest SCBA_CORRECTION of each node, from any session, applies until a later frame shows that node's SCBA bit (id_mode bit 3) or scba_expired bit (status3 bit 3) changed, so End shift and a restart do not lose it (Rev 3.40). The checkpoints table stays in Migration 0001 but is dormant: nothing writes it, and the checkpoint tests in Section 8 run only if checkpoints are enabled.
