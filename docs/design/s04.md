## 4. Operators, keys and security

| Item | Rule | Status |
|---|---|---|
| Add an operator | A script on the laptop creates the operator, generates a random token, shows it once and stores only its hash in operators. Written to audit_events (OPERATOR_ADDED). | Proposed |
| Rotate or remove | Rotating replaces the hash. Removing sets active to 0. Neither deletes audit history. TOKEN_ROTATED and OPERATOR_DISABLED go to audit_events. | Proposed |
| Token lifetime | Generated with Python secrets.token_urlsafe(24) (192 bits entropy) and stored as the hex HMAC-SHA256 of the token, keyed with server_salt, in operators.token_hash (HMAC only, never a plain SHA-256). server_salt is 32 random bytes (64-char hex) generated once at first run, by whichever of the host or the create-operator CLI starts first, and kept in config/secrets.json; it is never in settings, the database, logs or CSV. If operators exist and server_salt is missing, the host refuses to start instead of generating a new one, because a new salt invalidates every stored token and every operator would then need rotate-token. Login compares hashes with hmac.compare_digest. Tier 1 tokens do not expire (Rev 3.26, 4.1): they are replaced only by the CLI rotate-token between shifts or when an operator is removed, and are NEVER auto-rotated at End shift so active tabs are never locked out mid-incident. Stored in browser sessionStorage (main thread posts token to the Web Worker via postMessage). The Rev 3.25 expiry, 30-minute warning banner and expired_incident exception are REMOVED (4.1); token_grace_h is deleted from the settings. Hashing, the Origin/Host check and the audit trail are unchanged. | Proposed (lifetime), Spec (token on every channel) |
| Failed logins | A missing or invalid token is rejected on the dashboard, WebSocket and CSV export. Logging each rejection is Proposed. Do not lock the only active operator out during a shift, because a lockout could blind the incident commander. Use a short delay between attempts instead (for the PIN form of 4.2 the delay grows per operator and a lock clears itself after 15 minutes; the operator token is never locked, ADR 0056). | Spec (rejection, D8), Proposed (logging, delay) |
| PIN login | (ADR 0056, Proposed) Display name + a PIN of 6 to 12 digits. The PIN is stored only as a salted scrypt hash in operators.pin_hash; never in the browser, logs, CSV or audit rows. The operator token keeps working as the admin and break-glass login. | Proposed |
| Login session | (ADR 0056, Proposed) A correct PIN returns a random session token (secrets.token_urlsafe(24)), stored as its HMAC-SHA256 in login_sessions with an expiry (default 12 h). Log out, disabling the operator, rotating the token and setting a new PIN revoke it. | Proposed |
| System key | One random 16-byte key shared by every node, the base and the host, with a 1-byte sys_id and a unique sync word per crew. It lives in an untracked secrets header provisioned at flash time, not in NVS. The host reads it from its own untracked secrets file, kept apart from the settings file. Never in source control, logs, the database or CSV. Changing the key means reflashing every node and the base. | Spec (header, never logged), Proposed (host secrets file) |
| Flash encryption | Development mode while prototyping. Release mode only on the final build, after the reflash plan is tested, because it is hard to undo. If release mode is not used before the defense, state the readable key as a limitation. | Spec |
| Key copy | Keep one copy offline, outside the laptop and the repository | Proposed |
| Local API origin | Bind to 127.0.0.1:8420 (configurable bind_port). Check Origin and Host headers on every WebSocket and REST call against exact allowlist {'http://localhost:8420', 'http://127.0.0.1:8420'}. Token goes in Authorization header or first WS auth frame, never a cookie. Rejections write ORIGIN_REJECTED to audit_events. | Proposed (Tier 1 serves localhost only, Spec) |
| Slow or hung client | A per-connection send queue with a 1 s timeout; a client that falls behind is dropped and logged (section 1) | Proposed |
| CSV text | Fields starting with =, +, - or @ get a leading apostrophe (2.5) | Proposed |

### 4.1 Tokens

Tier 1 tokens have no expiry. Removed: token_grace_h, the shift plus 4 h lifetime, the 30-minute warning banner and the expired_incident exception. Kept: HMAC-SHA256 storage with server_salt, hmac.compare_digest, WebSocket and REST token on every channel, Origin/Host checks and the audit trail. rotate-token is the CLI path; a removed operator's token must stop working immediately (operators.active already exists in Section 2.3 and Migration 0001; every REST call and every WebSocket authentication checks active = 1, and the disabled-operator test of Section 8 covers it). Rationale: localhost and single laptop; the expiry rules interacted in three ways and added a lock-out risk during an incident.

### 4.2 PIN login and login sessions (ADR 0056, Proposed)

Tier 1 operator tokens still have no expiry (4.1). A login session is different: it is made by a correct PIN and ends at its expiry (session_hours, default 12), at Log out, or when its operator is disabled, gets a new token or a new PIN.

- Login: display name + PIN (digits, 6 to 12). Unknown name, wrong PIN, no PIN set and disabled operator all answer the same 401.
- Failed PINs: the answer carries retry_after_s (1 s doubling to a cap of 5 s). After 5 consecutive failures the operator's PIN login is locked for 15 minutes (LOGIN_LOCKED, once). The lock clears itself. The operator token is never locked, so a lock cannot blind the incident commander (4, Failed logins).
- Remember me: off by default. Ticked, the browser keeps the session token in localStorage; otherwise in sessionStorage as before. The expiry is the same.
- Shared station: whoever uses a browser with a remembered session acts as that operator. Log out at shift change.
- Set a PIN: CLI only (set-pin), written to audit_events as PIN_SET. There is no PIN reset from the dashboard.
