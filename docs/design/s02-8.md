### 2.8 Retention and privacy

- Define consent, access, retention, export and deletion before collecting responder data (Spec). Deletion is per session and permitted ONLY when no shift is actively monitoring (via offline maintenance CLI) so VACUUM cannot contend with live WAL writes: delete child rows in strict foreign-key order—ml_outputs (Tier 2), alerts, episodes, frames, audit_events, system_events, base_health, advisory_summaries, checkpoints—followed by the sessions row in one transaction with PRAGMA secure_delete=ON, then execute PRAGMA wal_checkpoint(TRUNCATE); and VACUUM; immediately after commit so deleted pages do not linger in the -wal file. Backup deletion & maintenance CLI (Proposed): run python -m ppe_host.cli purge-session --session-id <id> --db data/ppe.db --export-dir exports/ (refuses if host PID lockfile is active) to purge ppe.db, sweep all local backups/ and external USB backup copies, delete matching exports/session_<id>_*.csv files, and record an offline admin audit row (session_id=NULL, action SESSION_PURGED, reason = the purged session_id). Companion CLI commands: backup-verify --file <backup.db>, seed-roster --db data/ppe.db, create-operator --name <display_name>, rotate-token --operator-id <id>, and disable-operator --operator-id <id>.

- Aliases only. The operators table holds dashboard user names, not responder names. Handle both under RA 10173.

- Human-participant tests need ethics and safety clearance, or the fallback record (summary section 9).
