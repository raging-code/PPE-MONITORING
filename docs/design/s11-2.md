### 11.2 Firmware design

Decision (Proposed, confirm at first bench bring-up): ESP-IDF 5.x with RadioLib for the SX126x/SX127x radios. Arduino is not used. The pinned ESP-IDF commit goes in build_manifest.json (Section 13). The cross-chip radio test of 11.1 still gates the choice of RadioLib settings.

Component layout (firmware/ in the repo): components/abi (generated header, 12.1), components/frame (pack, CRC-8, AES-CMAC, pure C, no ESP-IDF includes), components/rules_fw (man-down, SCBA, MAYDAY state machines, pure C), components/nvs_latch (latch persisted across reset), components/radio (RadioLib wrapper, LBT, ACK/resend), components/sensors (CO, SHT40, IMU, battery), components/ui (LED, buzzer, button), main (task creation only). Base firmware adds components/serial_bridge and components/base_panel.

Rule: every state machine is a pure C function step(state, event, now_ms) returning the new state and an action bitmask. It does no I/O. A PC build compiles components/frame and components/rules_fw with gcc and runs them against the same frame vectors and scenario vectors as the host tests (test group D-FW, defined in Section 8 in Rev 3.30). Hardware tasks only translate hardware events into step() calls and actions into hardware calls.

Task table (initial values are PROPOSED; tune on the bench, then record final values in this table). The node is the classic dual-core ESP32-WROOM-32 (Technical Summary pin map) and this table follows the frozen core pinning of Section 11 and the Summary: deterministic sensor and alarm tasks on core 1, radio and flash work on core 0. Core 1: imu_task (priority medium-high, 4 KB stack, 200 Hz with vTaskDelayUntil, 400-sample / 2 s ring buffer); button_task (medium-high, 2 KB, buttons and the wrist connector-sense ADC at 100 Hz); fsm_task (high, 3 KB, 10 Hz with vTaskDelayUntil; runs step() on events and on each 100 ms tick and drives buzzer, LED and haptic from RAM state through components/ui; it never waits on the radio or on flash). Core 0: radio_task (high within core 0, 4 KB, RadioLib with the DIO1 interrupt, event-driven plus the LBT timer); sensor_task (medium, 4 KB, CO, SHT40 and battery at routine_period_s, SHT40 on the second I2C controller with a bounded-timeout mutex); nvs_task (low, 3 KB, the NVS persistence queue worker, so the 10 to 50 ms sector erases never stall core 1). The base firmware (classic ESP32 with SX1276) is Proposed to use radio_task on core 0 and serial_bridge and base_panel tasks on core 1. Rule: only radio_task touches the radio, only fsm_task touches the state, and tasks communicate by queues. There is no separate ui_task: components/ui is called by fsm_task. OPEN: the stack high-water marks are measured at the bench and each stack is set to measured peak plus 50%. [Rev 3.28: core numbers corrected to match Section 11 and the Technical Summary]

Firmware values currently missing from the constants file are added in 12.1: SCBA timers (300 s, 120 s, 20 s), RESEND_WAIT, the event stagger, the beacon period and the LBT backoff.

Firmware design notes added in Rev 3.27 (Proposed; complete each as a short note before the first bench build, using the Technical Summary and Section 4): (1) key storage: the per-system AES key lives in an NVS partition written once by a USB provisioning script together with node_id, never in the repo; enable ESP-IDF flash and NVS encryption for the trial build if the adviser requires it. (2) Watchdog and brownout: task watchdog on fsm_task and radio_task, brownout reset enabled, and the existing watchdog_recovery flag (status3 bit 4) reports a watchdog reset. (3) NVS latch writes only on latch set or clear, never periodically, to limit flash wear. (4) fw_version and the ABI version are reported and checked against abi.json at host start (sessions.fw_version exists). (5) The node MCU is confirmed in the Technical Summary as the classic ESP32-WROOM-32 (dual-core) with an SX1262/XL1262 radio, and the base as a classic ESP32 DevKit with an SX1276/XL1276, so the core numbers of the task table apply; the exact board and silkscreen are still checked at bring-up (Summary hardware-identity item).
