Stall, watchdog & deduplication timing (Spec + Rev 3.2/3.17 Fix). Because an asyncio coroutine cannot fire when the event loop is blocked, a dedicated OS watchdog thread (threading.Thread, daemon=True) checks monotonic heartbeat stamps updated by the serial-reader thread, asyncio processing loop, and 1 Hz tick timer every 250 ms; if any stamp lags >3 s (task_stall_s = 3 s), the watchdog writes a crash marker file and calls os._exit(1) so the user-session supervisor restarts the process within 5 s. Other '5 s' values are distinct and named explicitly: base offline after 5 s without heartbeat; no host tick for 5 s shows LAPTOP OFFLINE on the base panel; byte-identical (node_id, boot_ctr, seq) copies within 5 s are deduplicated.

Lifecycle.

1. Logging starts at host start and never waits for an operator.

2. Start monitoring unlocks audio and screen wake lock. Until then the browser siren is locked and the page shows "Browser siren off: click Start monitoring"; the host alarm is already active, because it does not depend on Start monitoring (3.12, Rev 3.29).

3. A session closes on a clean host shutdown or when an operator ends the shift (Proposed). A backup follows (section 2). End shift never pauses monitoring: the host opens a new session at once and carries open alerts and episodes over (3.7).

Host configuration.

- One settings file (config/settings.json, committed defaults, no secrets): serial_port (e.g. 'COM4'), db_path ('data/ppe.db'), test_db_path ('data/ppe_test.db', opened instead of db_path in SIMULATOR and REPLAY, see Operating mode isolation), backup_dir ('backups/'), bind_host ('127.0.0.1'), bind_port (8420), sys_id (1, matching firmware SYS_ID), base_id (1), log_dir ('logs/'), and the host-only settings in the table below (timeouts, queue sizes and chunk sizes). Secrets (the 16-byte shared CMAC key as 32-char hex, and server_salt for token hashing, see section 4) live exclusively in config/secrets.json (gitignored, ACL-restricted to current Windows user), never in settings, DB, logs, or CSV. Host log file (Proposed): logs/ppe_host.log at INFO level, rotating 5 files of 10 MB, UTC ms timestamps; it never records tokens or keys. Portable layout (Rev 3.43, Proposed): the host resolves every relative path (db_path, test_db_path, backup_dir, log_dir, config/secrets.json) against one data root, the environment variable PPE_HOME, which defaults to the repository folder in development and is set to the data folder (for example C:\PPE\data) in a deployed release, so the application folder can be replaced without touching responder data. Machine-specific values go in config/settings.local.json (gitignored), whose keys override config/settings.json; settings_hash is computed over the merged result with the same exclusions as above, so no hash rule changes and no settings key is added. serial_port may be the value auto, which selects the base by USB vendor and product ID; if it finds none or more than one matching device the host does not guess, it treats this as a missing port (the existing SERIAL_LOST handling) and logs the candidates. serial_port stays excluded from settings_hash.

- Tier 1 listens on 127.0.0.1:8420 (documented dashboard URL http://127.0.0.1:8420, one origin so the token in sessionStorage is not split between localhost and 127.0.0.1 and no IPv6 lookup delay occurs; http://localhost:8420 stays in the allowlist; configurable bind_port; avoids Windows port-80 HTTP.sys/IIS conflicts and requires no admin elevation) and serves both the built static React SPA bundle (dist/) and the FastAPI REST/WebSocket endpoints from one origin so Origin and Host validation is exact (http://localhost:8420 and http://127.0.0.1:8420). TLS and tablet clients are Tier 2. The host adds Content-Security-Policy (default-src 'self'; connect-src 'self' ws://localhost:8420 ws://127.0.0.1:8420; worker-src 'self' blob:; style-src 'self' 'unsafe-inline'; img-src 'self' data:), X-Content-Type-Options: nosniff and Referrer-Policy: no-referrer to the static bundle (Proposed; loosen a directive only if the Playwright run shows a blocked resource).

- Thresholds and timing values come from the generated constants file, the single source. Before computing SHA-256 for constants_hash and settings_hash in sessions, both files are serialized as canonical sorted-key compact UTF-8 JSON (json.dumps(obj, sort_keys=True, separators=(',', ':'))) so formatting or key-order differences never end a session. constants_hash covers the whole of shared/constants.json. settings_hash covers every key of config/settings.json except the connection and path keys serial_port, db_path, test_db_path, backup_dir, log_dir, bind_host and bind_port (Rev 3.41, Proposed), so a COM port that re-enumerates after a USB re-plug, or a moved folder, never ends a shift, and except the nine rows marked 'Not in settings_hash' in the host-only table below (budgets, targets, banner thresholds and dormant checkpoint keys; Rev 3.42, Proposed), because they change only what a test checks or when a warning shows, never what the host accepts, stores or decides; sys_id and base_id stay in the hash because they change what the host accepts. serial_baud is not a host setting: it is defined once, in shared/constants.json (115200), and the host and the base read it from there (Rev 3.42).

- The 4 s dashboard stale limit and 5 s base-offline limit are in the summary’s constants table (Spec). The 3 s task-stall limit is not, so add it as task_stall_s = 3 s (the key name in constants.json), with the 5 s supervisor-restart target, in the Technical Summary’s constants table before Rev 3 closes (Proposed, tracked in section 10).

- Windows packaging, user-session supervisor & browser freeze prevention (Proposed + Rev 3.5/3.17 Fix): do NOT use Windows Task Scheduler (minimum 1-minute restart interval violates the <=5 s restart target) or NSSM / Windows Services (Session 0 isolation blocks interactive desktop audio playback on Windows 10/11). Instead, launch the host inside the logged-in operator desktop session via a lightweight Python/PowerShell supervisor loop (scripts/run_supervisor.py, started at user login via Startup folder shortcut) that spawns python -m ppe_host.main and respawns it within 500 ms whenever exit_code != 0 (clean shutdown exits with code 0 and does not respawn). Crash-loop guard (Rev 3.25): after 5 non-zero exits within 60 s the supervisor waits 5 s between respawns, shows a local error window with the last crash marker, plays the local laptop alarm and keeps trying (the base panel shows LAPTOP OFFLINE after 5 s without a host tick). OS sleep, hibernation, and automatic Windows updates are disabled; Windows host checklist (Rev 3.25): the lid-close action is Do nothing, USB selective suspend is off, the High-performance power plan is used on AC power, and the host starts at operator login (auto-login or a documented manual start; the pre-shift check is that the base OLED shows the host tick); pyserial opens the base port with dtr=False, rts=False (paired with the hardware DTR/RTS-to-EN trace cut on the Base DevKit). Browser freeze protection: add http://localhost:8420 to Edge/Chrome never-sleep site exclusions, keep the dashboard unoccluded in the foreground, and run a non-blocking host-side audio watchdog thread (using stdlib winsound async playback (SND_ASYNC) in the user desktop session, so no audio package is added): the host is the primary alarm (3.12): while monitoring_active=true and any unacknowledged DANGER/WARNING alert or open episode exists, the audio thread plays the priority WAV for the highest open item. The 1 kHz 400 ms pulse every 2 s is the fallback when a WAV file is missing or cannot be decoded, and it also sounds if zero authenticated dashboard /ws sockets are connected for >10 s while monitoring_active=true. Release bundle and doctor (Rev 3.43, Proposed): a release is one folder holding a pinned embedded Python 3.12 runtime, the host package and the prebuilt dashboard (the npm run build output, copied to dashboard/dist/ inside the release folder and served by the host from there), so the operator laptop needs neither Node nor a network install; the Startup-folder shortcut runs a launcher .bat that starts scripts/run_supervisor.py from that folder, and nothing above changes. The command python -m ppe_host.cli doctor prints pass or fail for the release version, the base serial device, the audio device, free disk (host_disk_min_gb), port 8420, the prebuilt dashboard (dashboard/dist/index.html present), secrets.json, PRAGMA quick_check and the lockfile, and changes nothing; it is part of the pre-shift check. Moving to another laptop means copying the data folder, provisioning the CMAC key into secrets.json and running doctor; the resume rules of section 1 apply unchanged. Run the release on a second PC before the trial. Docker is for development and CI only, not the operator laptop (audio and USB serial passthrough on Windows).

- Disk encryption (Rev 3.27, 13.2): BitLocker (Windows Pro) or Device Encryption is on for the laptop drive, and every USB backup drive is BitLocker To Go encrypted (or an encrypted VeraCrypt volume if neither is available). Backups and CSV exports go only to encrypted locations. docs/data-governance.md is filled in (alias-to-person map holder, who may run purge-session, retention period, RA 10173 contact).

- Host health (Proposed): the host reads laptop battery and free disk once a minute. On battery it shows HOST ON BATTERY, at 30% or less or under 1 GB free disk a warning banner. Values are provisional.

Operating mode isolation & Clock abstraction (Proposed + Rev 3.17 Fix): LIVE, SIMULATOR, and REPLAY are mutually exclusive startup modes selected via CLI flag (--mode LIVE|SIMULATOR|REPLAY) or settings file and locked for the process lifetime. All host timers (15 s / 60 s link loss, 30 s stillness, 10 s CO hysteresis, 120 s heat) read from an injected Clock interface (wall_ms(), mono_ms()) scaled by replay speed (1x, 4x, 16x) in REPLAY mode. In SIMULATOR or REPLAY mode, incoming serial frames are drained only to detect accidental live hardware traffic—raising LIVE_FRAME_IN_TEST_MODE if valid MAC-verified frames arrive—and are never ingested into telemetry. Rev 3.40: SIMULATOR and REPLAY never open db_path. They open test_db_path, created with the same migrations and the same seeded roster, so their sessions, alerts and episodes cannot collide with the global open-alert and open-episode indexes or with live open items, and they never appear in a LIVE export or a LIVE purge. REPLAY reads the source session from db_path through a separate read-only connection and writes only to test_db_path.

Firmware Core Pinning & GPIO2 Safety (Rev 3.2): To prevent SPI flash cache stalls during NVS writes (10–50 ms sector erases) from jittering the 200 Hz IMU or 10 Hz alarm loop on the classic ESP32, pin all deterministic sensor/alarm tasks (Chest IMU 200 Hz, Buttons/ADC 100 Hz, Alarm/State Machine 10 Hz) to Core 1 using vTaskDelayUntil, and pin RadioLib LoRa RX/TX (DIO1 ISR-driven) plus the low-priority NVS persistence queue worker to Core 0. Keep GPIO2 permanently pulled down via 10 kOhm (even when wired to the active-HIGH Blue LED) so boot strapping is safe; if DIO2 antenna switching fails and GPIO2 becomes RF TXEN, fall back to a distinct double 150 ms haptic pulse on link_ok 1->0.

Button Stuck-at-Boot Guard & Dropout-Safe SOC Mapping (Rev 3.2): A button shorted to GND at cold boot or held >10 s sets btn_stuck and must never trigger clear_armed at t=3 s. Require a verified clean HIGH release (>=40 ms) after boot or after any btn_stuck condition before a button press can arm a 3 s latch clear or increment the 3-press MAYDAY window. Transitioning btn_stuck 0->1 immediately resets clear_armed = 0. Battery SOC 0% maps to 6.5 V under load (above the MP1584E ~6.2 V 5 V-rail dropout and 5.6 V 2S BMS cutoff), with 10% WARNING at 6.75 V and 20% bat_low at 6.95 V, verified in POWER GATE.
