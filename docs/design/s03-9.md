### 3.9 Alarm reliability (Proposed)

[Rev 3.27] PRIMARY ALARM CHANGED (3.12): the host laptop plays the alarm and this subsection is rewritten to match. The browser keeps visual alerts and the NO LIVE DATA siren only.

- Host audio check (Rev 3.27): the host plays a two-note ascending chime (distinct from every alarm sound) every host_chime_interval_min = 15 minutes while no safety alert is unacknowledged, and checks the audio path every audio_check_interval_s = 60 s (3.12). A failed playback shows an AUDIO FAULT banner and writes AUDIO_FAULT to system_events; the next successful playback writes AUDIO_OK. The host can detect a missing audio device and, if the optional pycaw check is accepted, a muted or very quiet endpoint; the operator must still hear the chime (Proposed). It is covered by pytest with a mocked audio sink, not by Playwright.

- Browser siren (Rev 3.27): only the NO LIVE DATA siren plays in the browser. The page checks the audio state every second, driven by the worker tick. If the browser has suspended or blocked audio, a banner "SIREN OFF: click to enable" shows and one click re-enables it. This matters only when the host is dead, because the host alarm does not depend on the browser. The "Test sound before Start monitoring" click gate stays, because it is what unlocks browser audio.

- Dashboard latency: from the message arriving to the pop-up visible, 500 ms or less (provisional, frozen with the adviser and safety reviewer like every criterion). It is measured with performance marks (receive, render) in the browser tests, and it is the dashboard's share of the man-down path in section 5. The host's share (frame received to broadcast) has its own provisional budget of 200 ms (section 5). The host alarm start is measured separately (Section 5), and one manual check with the camera or a microphone stays in the D8 run.

- Acknowledge and Resolve are kept apart: different buttons, Resolve needs a reason, and End shift warns while an episode is unresolved. Acknowledge never closes a safety alert; only an unauth_alert closes on Acknowledge (14.1b).
