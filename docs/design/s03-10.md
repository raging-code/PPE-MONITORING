### 3.10 Fault map, time and sessions (Proposed)

Each hotspot changes only for the frame bits below (bit names are from the summary's status table). The table also generates hotspots.json, so the code and this document cannot drift. The host cannot see the buzzer line itself, so that hotspot shows the node level.

| Hotspot | Fault or state from the frame | Display |
|---|---|---|
| CO sensor | status2 bit 4 (CO fault), bit 5 (IMU fault), bit 6 (temperature fault) as in the summary's status table (confirm once against the firmware ABI header); flags bit 3 (fault) is also set for IMU, temperature and wrist faults, so it alone never turns this hotspot grey; flags bit 4 (CO saturated); status3 bit 2 (warm-up) | Grey "CO unknown"; "500+ ppm"; "warming up" |
| SHT40 temperature and humidity | The temperature fault bit; the ambient-heat alert | Grey "temperature unknown"; level colour for heat |
| Chest IMU | The IMU fault bit; flags bits 5 to 6 (activity); flags bit 2 (man-down) | Grey; activity word; red for man-down |
| Wrist module and connector | status4 bit 0 (connector open, quiet); status2 bit 1 = 0 with the connector mated (wrist lost) | Marker "disconnected"; WARNING |
| SCBA coupling | id_mode bit 3 (SCBA ON); status3 bit 3 (SCBA expired) | ON, OFF or EXPIRED |
| Battery | status2 bit 2 (20% or less); bat at 10% or less | Percent; WARNING at 10% or less |
| Radio node | id_mode bit 6 (link_ok); id_mode bit 7 (unsent event); link state | Link word and last seen; MISSED EVENT badge |
| Buzzer and amber LED | flags bits 0 to 1 (node level) | Shows the node level |
| CANCEL button | status3 bit 0 (stuck); status3 bit 1 (clear armed); status2 bit 7 (cancel_ack) | STUCK; CLEAR ARMED; CANCEL SEEN |
| Not mapped to a hotspot | flags bit 7 (check-in, shown as a card, 3.4); status3 bits 4 (restored), 5 to 6 (reset cause) and 7 (still_now); status4 bit 1 (latch restored) and bit 4 (MAYDAY); status3 bit 0 (stuck) can come from either button, and a stuck wrist CANCEL shows as wrist lost (WARNING); reserved bits | Event log line or badge; a set reserved bit marks the frame suspect |

- Time: Asia/Manila (UTC+8, no daylight saving), 24-hour clock, with server timestamps as the authority. "Last seen" shows relative time ("4 s ago") under 60 s and the clock time after that. The event log always shows clock time. In Tier 1 the browser and the host are the same laptop, so no clock-difference notice is needed; with Tier 2 tablets a notice shows when the clocks differ by more than 2 s. Host code that formats Manila time must not rely on the Windows time-zone database: Python's zoneinfo needs the tzdata package on Windows, so tzdata is pinned in requirements.lock (Rev 3.40); stored timestamps stay UTC ms.

- Sessions: a Sessions list opens from the top strip, not the main screen: date, length, mode, alert count. After End shift a one-screen summary shows duration, highest level per responder, alerts raised, unresolved episodes, the backup result and a CSV button.

- Simulator and replay: SIMULATOR is a host option that makes seeded frames for 3 nodes from scripted scenarios (CO ramp, man-down, link loss) for rehearsal and dashboard tests. REPLAY feeds the stored frames of a chosen session through the normal pipeline at 1x, 4x or 16x with Pause, into a new session labelled REPLAY in test_db_path (Operating mode isolation, section 1), and never writes to the original database. Both show the TEST banner and stay out of LIVE exports.
