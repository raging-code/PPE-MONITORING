11.1 Radio PHY profile and cross-chip rule (Rev 3.24, Proposed; firmware and base configuration, not host settings, so they stay out of shared/constants.json). The node uses an SX1262 and the base an SX1276/XL1276, which talk to each other only if both are configured identically. (1) One radio configuration per permitted band (868 MHz or 915 MHz, chosen by the NTC answer; this is separate from the duty-cycle timing profiles A and B of the Technical Summary) is generated for both chips: BW 125 kHz, CR 4/5, explicit header, PHY CRC on, 8-symbol preamble, standard IQ, the same SF, and the same frequency and sync-word byte. (2) Sync word: pass one byte S to the SX1276 (RadioLib setSyncWord(S)) and pass the same S to the SX1262 with control bits 0x44 (setSyncWord(S, 0x44)), which is how 0x12 on the SX1276 maps to 0x1424 on the SX1262. Never use 0x34 (the LoRaWAN public word). The sync word is stripped by the radio PHY and is not part of raw_hex. (3) Low-data-rate optimisation must be set the same way on both chips for the chosen SF and BW. (4) RSSI is read through the library on each chip and is never compared raw between chips; the listen-before-talk threshold is stored per chip in the profile and set from the D9 bench log. (5) Gate: before any other D9 run, a cross-chip loopback must show 100 valid frames in each direction (node to base and base beacon to node) with matching CRC, MAC and beacon decode, at the lowest and highest TX power in the profile.
