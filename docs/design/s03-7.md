### 3.7 System states, empty states and fallback (Spec unless marked)

- Login token required for the dashboard, WebSocket and CSV export. Tier 1 serves the dashboard to a browser on the host laptop at http://127.0.0.1:8420 (http://localhost:8420 is also in the origin allowlist, section 4). TLS and tablet clients are Tier 2.

- Start monitoring unlocks audio and screen wake lock. Until then the browser siren is locked and the page shows "Browser siren off: click Start monitoring"; the host alarm is already active, because it does not depend on Start monitoring (3.12, Rev 3.29). End shift (decided: never blocked) works at any time. The confirmation lists every open alert, open episode and latched node, and the operator types END. It never silences or hides anything: the host closes the session, runs the backup and opens a new session at once, so frames, alerts and sound continue, audio stays unlocked, and open alerts and episodes carry over and can still be acknowledged and resolved. END_SHIFT is audited with the open-item list. Start and End are buttons only: logging runs from host start either way (decided).

- No tick for 4 s shows a full-screen red "NO LIVE DATA: responders are NOT being monitored" with a repeating tone. A Web Worker with its own authenticated socket judges this from server timestamps. It also fires if the data socket closes or delivers nothing for 4 s.

- A tab that was hidden shows "Dashboard was hidden: alarms may have been delayed" on return. Stale values stay grey with timestamps. A reconnect sends a full snapshot before increments.

- No base heartbeat for 5 s shows one banner: "BASE OFFLINE: no node is being monitored".

- 3D view fallback (decided rule): readings, pop-ups, sound, NO LIVE DATA and Resolve never depend on the 3D view. The jacket loads separately inside an error boundary and attaches a webglcontextlost listener on the <Canvas> element (disposing BufferGeometry and Material on unmount) so a GPU driver reset or context cap over a 24 h shift immediately switches to a flat grid of the same components (value and state per row) with the line "Jacket view unavailable", and the rest of the screen is unchanged. The jacket renders on demand (only when the view or a state changes), with the pixel ratio capped and rendering paused while the tab is hidden, and it loads after the readings, so the 3D view cannot starve the alarm timers.

- Logging fault (Proposed): a queue overflow, database write error, free disk under 1 GB or failed integrity check shows a LOGGING FAULT banner. Alerts and readings still show from memory, and the banner stays until the cause clears and an operator acknowledges it.

- Display and browser (Proposed): supported browsers are current Chrome and Edge on the host laptop; the layout is tested at 1366 x 768 and at 150% zoom. The tray is at most 40% of the window height and scrolls inside itself, danger cards first, so stacked banners (TEST, SIREN OFF, AUDIO FAULT, BASE OFFLINE, hidden tab, LOGGING FAULT) cannot push the readings off screen. The wake lock is re-acquired each time the tab becomes visible, and a "Screen may sleep" badge shows if it is lost.

- Empty states (Proposed): a rostered node never heard is a grey "Not connected" card with no level (Spec), and before the shift it flags NOT READY (Spec). An empty roster shows "No responders on the roster". The login screen is one token field and a Sign in button, with "Token not accepted" and the delay in section 4.

- Any session mode other than LIVE shows a permanent TEST banner (Spec). It is a dark neutral bar ("TEST: simulator data" or "REPLAY: date and time"), never a level colour. Alerts and sounds work as in LIVE so operators can rehearse (Proposed).

- A read-only Model status panel shows model name and version, data hash, ship-rule verdict (passed, failed, not run) and whether badges are on. It never trains (Proposed).
