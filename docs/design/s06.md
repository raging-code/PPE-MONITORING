## 6. ML and DL

Tier 2 models only annotate. They never set, delay or clear an alert, and a model failure leaves every deterministic alert unchanged. They run in a separate worker process with a timeout on a 2 s grid. A missing result shows "unavailable" and never delays the host loop (Spec). No ML runs on the jacket node in this thesis. The deterministic man-down and CO rules stay authoritative.

### 6.1 Models

| Model | Type | Input | Output | How it works | Tier |
|---|---|---|---|---|---|
| CO forecast | Gradient-boosted trees (scikit-learn HistGradientBoostingRegressor) | Past data only: current CO; mean, min, max over 30, 60 and 300 s; CO slope over 30, 60 and 120 s; time since CO last above 35 ppm; SHT40 temperature and its 60 s slope | Sensor CO in ppm, 5 minutes ahead (not COHb) | Builds small trees in sequence, each correcting the errors of the previous ones | 2 |
| Early-warning rule | A rule on the forecast, not a trained model | The forecast | Advisory badge when the forecast is 150 ppm or more within 5 minutes while current CO is below 200 ppm and SCBA is OFF | Fixed comparison. Lead time is measured from first warning to CO reaching 150 ppm. | 2 |
| Anomaly score | Isolation Forest | The same windowed features | How unusual the recent data is (spikes, stuck values, step jumps) | Random trees isolate odd points in fewer splits. The score is mapped to a percentile fitted on training sessions. Trained on clean windows only. Unusual = percentile 0.99 or more for five consecutive windows. | 2 |
| Fall / motion classifier | Decision tree baseline, then 1D-CNN | Short windows of chest IMU motion | Fall or no fall | The CNN slides filters along time to learn motion patterns. The tree on hand-made features is the baseline it must beat. | 3, future work |
| Early-warning classifier | Machine learning | At least 30 real CO-rise events | CO rise yes or no | Not possible without real data | 3, future work |

The two forecast baselines are persistence (predict the current value) and linear (least squares over the last 60 s, extended 5 minutes, clipped 0 to 500 ppm). Badges read as model estimates, say they are simulated or bench-trained and not field-validated, and show "unavailable" when the model is off or data are insufficient (Spec). A classifier that runs on the node is Tier 3. Training one on the laptop (6.5) is preparation only.

### 6.2 Training the Tier 2 models

1. Make the data (Spec). Seeded simulated sessions: clean with noise, ramp, step, pulse and decay, repeated pulse, rising temperature, with first-order sensor lag (up to 60 s) and noise. Let ramps go above the 500 ppm clamp so the trees are not handicapped against the linear baseline. Add bench sessions recorded in a ventilated lab with a reference CO monitor. Proposed minimum: 300 simulated and 10 bench sessions.

2. Label the source (Spec). Every row says simulated or bench. Simulation is never called field data. No fireground or firefighter data is used.

3. Cut windows (Spec). Past data only, on a 2 s grid. Skip windows with a gap over 10 s or fewer than 80% of samples.

4. Split by session, not by row (Spec). About 60/20/20 train, validation, test. Also hold out each scenario family in turn, and evaluate bench sessions leave-one-session-out.

5. Fit on training sessions only (Spec). Scalers and the anomaly percentile map are fitted there. Tune with grouped cross-validation by session. The Isolation Forest is fitted on clean windows only. Use the test set once.

6. Train and compare (Spec). Train the forecast and the Isolation Forest, then score both baselines on the same data.

7. Report (Spec). MAE overall and for CO at or above 35 ppm, lead time, missed events, false alarms per hour, and anomaly detection on injected faults, each with bootstrap 95% intervals.

8. Apply the ship rule (Spec, test D12). Enable the forecast only if its MAE beats both baselines, with the bootstrap interval of the per-session MAE difference excluding zero, on held-out sessions, on leave-one-family-out and on a majority of bench sessions. The early-warning and anomaly criteria (proposed: median lead of at least 60 s and at most 1 false alarm per hour) are fixed before the test set is run. Otherwise the dashboard shows the baseline or "unavailable" and the negative result is reported as a finding. The Isolation Forest is judged separately by the same rule.

9. Save the evidence (Spec). Model file, seed, pinned library versions, data hash, split manifest and baseline scores go into the evidence package.

10. Deploy as a file (Spec). The Tier 2 worker loads the saved model file. Retraining is out of scope for the thesis.

### 6.3 Training code (Proposed)

Layout, one command per step, seed fixed so a result can be reproduced. The worker loads the model file copied into the host's models folder.

```
ml/
  gen_sim.py          seeded scenario generator (simulate)
  export.py           pulls bench sessions from ppe.db, aligns the reference-monitor
                      file by timestamp, records the clock offset (export)
  features.py         windowing and features, past data only, 2 s grid
  train.py            fits the forecast and the Isolation Forest (train)
  evaluate.py         baselines, metrics, bootstrap intervals, ship-rule verdict (evaluate)
  package.py          model file plus manifest: seed, data hash, versions (package)
  train_motion.py     Tier 3 motion classifier (6.5)
  evaluate_motion.py  Tier 3 evaluation against the stillness and impact rule
  models/             saved model files and manifests
  data/               simulated, bench and motion sessions, each with a source label
```

Core of train.py:

```
from sklearn.ensemble import HistGradientBoostingRegressor, IsolationForest
from sklearn.model_selection import GroupKFold, cross_val_score

cv = GroupKFold(n_splits=5)  # groups = session id, never rows
forecast = HistGradientBoostingRegressor(random_state=SEED, early_stopping=False)
cv_mae = -cross_val_score(forecast, X_train, y_train, groups=sess_train,
                          cv=cv, scoring="neg_mean_absolute_error")
forecast.fit(X_train, y_train)  # y = CO ppm 5 min ahead

anomaly = IsolationForest(random_state=SEED).fit(X_train_clean)  # clean windows only
train_scores = -anomaly.score_samples(X_train_clean)  # percentile map: training sessions only
```

Set early_stopping=False and choose max_iter by the grouped cross-validation. With more than 10,000 windows scikit-learn's automatic early stopping takes a random row-level validation split, which mixes windows of the same session. With only 10 bench sessions the rule "a majority of bench sessions" has little power, so a negative result is likely and is reported as a finding.

### 6.4 Where training lives

| Option | Verdict | Reason |
|---|---|---|
| Training section inside the dashboard | No | The dashboard is the safety display. Training uses heavy CPU and could slow the host, and a train button adds a way to change a model during a shift. |
| Separate training website | Not needed | It adds a second server, login and set of dependencies for a job done a few times before the trial. |
| Offline scripts or a notebook on the laptop (ml/) | Recommended | Runs before the trial, never during a shift. Reproducible from a seed. Produces a model file and a report. |
| Read-only Model status panel in the dashboard | Proposed | Shows results and never trains (section 3). |

If a point-and-click tool is wanted later, make it a separate local page that runs only on the laptop when no shift is active (a notebook is cheapest), outside the host process and the dashboard build.

### 6.5 Motion classifier (Tier 3, future work, Proposed)

Follows the split and reporting rules of 6.2.

1. Record labeled raw motion. The chest IMU samples at 200 Hz but the 23-byte frame carries one motion RMS value, so the host never gets the raw signal. Recording needs a separate test firmware build that streams raw IMU samples over USB to the laptop, leaving the frozen 23-byte frame and 13-byte beacon unchanged. Recordings go to ml/data/motion, not ppe.db, so the Tier 1 schema stays frozen (open decision).

2. Script the activities from the summary's calibration list: table, lying still, standing, kneeling with a hose, crouched or listening, crawling with pauses, leaning, mat falls, bumps, sits and kneels, vibrating surfaces (generator, fan, pump, engine, vehicle floor). Label each FALL, STILL_AFTER_FALL or the activity name.

3. Cut short windows of a few seconds. Choose the length on validation sessions, not the test set.

4. Decision tree first. Features per window: motion RMS, peak g, stillness against STILL_G, change in body orientation. scikit-learn DecisionTreeClassifier: trains in seconds and shows why it decided.

5. 1D-CNN second. Takes the raw axes of a window. Framework not chosen. Keep it small enough to run on the ESP32 later.

6. Split by recording session or person, never by window, because neighbouring windows leak the answer. Handle rare falls with class weights or by oversampling training sessions only.

7. Report missed falls, false alarms per hour on normal work and detection delay, with confidence intervals. Not plain accuracy.

8. Ship rule. It must beat the deterministic stillness and impact rule on the same recordings, otherwise the rule stays and the result is a finding. STILL_G starts at 0.05 g and is set above the chest RMS recorded lying still (summary section 7 calibration data). The comparison uses the calibrated value.

9. Data and ethics. Human motion recordings need ethics and safety clearance. If clearance is late, use a mannequin or rigid-mount rig, or replayed traces from an approved recording or public dataset labelled as such. Wording: "bench-verified with simulated or replayed inputs".

With only a few dozen falls the tree may beat the CNN, which is a valid result.
