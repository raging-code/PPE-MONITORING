14.5 Runtime Architecture, Module Layout & Startup Sequence (Tier 1 Monolith on 127.0.0.1:8420):  
• Repo Layout: host/ppe_host/ (main.py, cli.py, settings.py, clock.py; core/: crypto_abi.py, seq_classifier.py, rule_engine.py, advisory.py; io/: serial_reader.py, serial_writer.py, db_writer.py, audio_watchdog.py, backup.py; services/: recovery.py, checkpoint.py, csv_export.py, simulator.py, replay.py; api/: api_rest.py, ws_hub.py, models.py), host/migrations/ (0001.sql, 0002.sql), host/tests/ (pytest: DDL, golden vectors, frames.json codec vectors, parser fuzz), shared/ (constants.json, alert_catalog.json, hotspots.json, vectors/frames.json), dashboard/ (src/, tests/ for Vitest, public/jacket_model.stl), e2e/ (Playwright), scripts/run_supervisor.py, tools/ (test_vectors.py, doc_lint.py), justfile (one command per task: setup, dev, test, gen, lint, build, package), docs/ (Markdown sections and adr/NNNN.md, when the split of 13.1 is made). Grouping (Rev 3.43, Proposed): core/ imports nothing from io/, services/ or api/ and does no file, serial, network or audio I/O, checked in CI by an import rule; module file names are unchanged, only their folders. Roles (Rev 3.21): seq_classifier.py is the classifier of section 1; advisory.py the 14.3 table; checkpoint.py the checkpoint writer, dormant and not called in Tier 1 (2.10); backup.py the online backup and integrity checks (2.5, 2.6); csv_export.py the v_full_log export (2.5); models.py the Pydantic wire models (3.8); simulator.py and replay.py the SIMULATOR and REPLAY modes (3.10); serial_writer.py the host_tick writer thread (section 1).  
• Thread & Task Map: (1) Supervisor parent process (user desktop session, respawns child on non-zero exit <500 ms, with the crash-loop guard of section 1); (2) SerialReaderThread (pyserial blocking readline(513) -> asyncio.Queue); (3) DBWriterThread (single SQLite WAL writer with one bounded ordered writer queue; the priority/low-priority lanes and the RAM retry buffer are removed, 2.10); (4) AudioThread (plays the host alarm WAVs for open alerts, the 15 min chime and the audio self-check, 3.12); (5) OSWatchdogThread (checks 250 ms liveness stamps -> os._exit(1) at >3 s stall); (6) Asyncio Event Loop (FastAPI REST, /ws & /ws/tick per-client sender tasks, rule engine, 1 Hz host_tick build & banner timers); (7) SerialWriterThread (writes the 1 Hz host_tick to the base with a write timeout, never from the event loop; section 1).  
• Deterministic Startup Sequence (Rev 3.22; the server and host_tick run during recovery): (1) resolve PPE_HOME, load config/settings.json, apply the config/settings.local.json override if that file exists, load config/secrets.json, and choose the database file (db_path in LIVE, test_db_path in SIMULATOR and REPLAY), with db_path, test_db_path, backup_dir, log_dir and config/secrets.json resolved against PPE_HOME (section 1); (2) acquire the PID lockfile; (3) run PRAGMA quick_check; (4) apply pending migrations after an online backup; (5) initialize event_seq = 1 + the maximum over all six event_seq columns of the whole database (2.1); (6) resume a valid <30 min same-mode, same-hash session, or close_session('ABANDONED') and open a new one; (7) log HOST_START + RECOVERING_ENTER and set recovering=true; (8) start the OS watchdog, DBWriterThread, SerialReaderThread (its frames go to the bounded pre-replay queue), SerialWriterThread (host_tick with recovering=1, so the Base OLED shows HOST RECOVERING) and AudioThread (3.12); (9) load open alerts and open episodes by indexed SQL (section 1, step b); (10) start Uvicorn on 127.0.0.1:8420 and the 1 Hz host_tick, so the first snapshot carries recovering=true and the open alerts, and POST /api/session/end returns HTTP 409; (11) run the chunked async recovery (rebuild from open alerts, episodes and the last 30 minutes of frames, with a checkpoint restore only if checkpoints are enabled, 2.10; CO chart, rejected_frames totals) on the event loop, touching the liveness stamps on every yield; (12) log RECOVERING_EXIT + HOST_GAP and set recovering=false; (13) drain the pre-replay queue in arrival order through the normal pipeline, then accept live frames directly. No rule runs and no alert is raised from a queued frame before step 13; the queue is bounded by pre_replay_queue_max with the drop rule of section 1.  
• Start-up failure policy (Rev 3.25, Proposed): (a) The lockfile holds the PID and the process start time; it is stale if that PID is not running or its start time differs (PID reuse). A stale file is replaced and logged; a live one makes the new process log it and exit with code 0, so the supervisor does not respawn it. SIMULATOR and REPLAY use the same lockfile, so neither can start while a live host runs and a live host cannot start while either runs (Rev 3.41). (b) If PRAGMA quick_check fails (step 3), the selected database file (db_path in LIVE, test_db_path in SIMULATOR and REPLAY) with its -wal and -shm files is renamed to <name>.corrupt-<UTC ts> and never resumed; in LIVE the newest backup that passes backup-verify (integrity_check) is restored into db_path, or a fresh database is created if none passes, and in SIMULATOR and REPLAY no backup is restored and a fresh test database is created; migrations then run, step 6 opens a new session, and in that session the host logs INTEGRITY_FAIL (detail names the quarantined file and the backup used), and in LIVE writes audit_events DB_RESTORED (session_id NULL) and shows the host_gap banner with reason db_restored until acknowledged (POST /api/system-banners/host_gap/ack, 3.8); the dashboard adds the line DATABASE RESTORED FROM BACKUP: records after the backup may be missing. The gap since the backup is shown by HOST_GAP. (c) A failed migration restores the pre-migration backup of step 4 and exits with code 2. (d) A missing or unreadable secrets.json, or a missing server_salt while operators exist, exits with code 2 and a clear message; the host never runs without the CMAC key. Exit code 2 counts toward the supervisor crash-loop guard of section 1.
