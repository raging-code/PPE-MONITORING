### 2.2 Tables

Tier 1 tables and views (v_readings, v_full_log) are created by migration 0001; Tier 2 tables (ml_outputs) are created by migration 0002 (see Section 11 for complete DDL), so Tier 1 carries no unused columns.

| Table | Purpose | Tier | Status |
|---|---|---|---|
| schema_version | Applied migrations | 1 | Spec |
| operators | Named dashboard users mapped to login tokens | 1 | Spec |
| roster | Node ID to alias mapping (IDs 1 to 3) | 1 | Spec |
| sessions | One row per monitoring run. A host restart resumes the open session. | 1 | Proposed |
| frames | Every received frame, verified or not. The summary's readings are the rows with verify = OK. | 1 | Spec |
| alerts | Alert and state-change records | 1 | Spec |
| episodes | One row per incident that can be acknowledged and resolved | 1 | Spec |
| audit_events | Acknowledge, Resolve, CANCEL and SCBA corrections, login, export | 1 | Spec |
| base_health | 1 Hz base heartbeat with receive error counters | 1 | Spec |
| system_events | Host start, RECOVERING, serial reconnect, queue overflow, integrity check | 1 | Proposed |
| advisory_summaries | Advisory output and its source (fixed table in Tier 1) | 1 | Spec |
| ml_outputs | CO forecast, COHb, anomaly score, early-warning flag, model version | 2 | Spec |
| checkpoints | Dormant in Tier 1: the table exists but is not written (2.10). RECOVERING rebuilds node state from open alerts and episodes plus the last 30 minutes of frames; a snapshot is added only if the benchmark shows recovery above 3 s | 1 | Proposed |
