## 3. Dashboard

Spec = summary. Proposed = suggestion. Decided = your answer. The look is clean, light, modern and premium, with few widgets and little text (decided). Colour appears only for a real state: normal green, warning yellow, danger red, and grey for stale or unreliable data (decided). Colour is never decoration, so a colour on a card or on the jacket always means a real state.

### 3.1 Main screen and wireframes (Proposed)

| Area | Content |
|---|---|
| Centre | The 3D jacket of the selected firefighter. The 3D model already exists and is supplied by the team (.stl, geometry only, so no named parts). The dashboard only loads it. Hotspots on the jacket show the PPE components. |
| Hotspots | CO sensor, SHT40 temperature and humidity, chest IMU, wrist module and connector, SCBA coupling, battery, radio node, buzzer and amber LED, CANCEL button. Hotspots are neutral dots: one takes the level colour only while its component is raising an alert, and goes grey when its reading is unreliable. Hovering or clicking a hotspot highlights its row in the side panel. HR is not fitted in Tier 1. |
| Hotspot setup | A one-time placement mode, opened only by a developer flag and never during a shift: click the jacket, pick the component name, repeat. It saves hotspots.json (component, position, surface direction), committed with the build. It needs the .stl file, the confirmed component list above, and which way is up and front (open). hotspots.json also stores the .stl file hash, scale and orientation. If the hash differs, the flat grid shows instead of misplaced dots. |
| Side panel | Readings for the selected responder and one small CO chart (3.2). |
| Top strip | Responder switcher for the 3 nodes (alias, level colour, battery, last seen), session mode (LIVE or TEST), Start monitoring and End shift, and the chips for minimized alerts (3.3). |
| Bottom | Event log and CSV export. |
| Detail view | No separate page: the main screen is the detail view of the selected responder. |
