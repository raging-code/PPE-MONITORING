Sequence classifier (Proposed, Rev 3.21). The rule is the Technical Summary's frame sequence check, restated here so the host and its tests need no second document. It runs per node on every frame with verify = OK, after deduplication, against that node's baseline (the last accepted seq and boot_ctr). Tier 1 compares only seq (u16) and boot_ctr (u8); Tier 2 adds the uptime check as in the Technical Summary (du is taken modulo 65536 because uptime_s wraps after about 18.2 h; Tier 1 ignores uptime_s). Let ds = (seq - seq_prev) mod 65536: ds 1 to 32767 is forward and ds - 1 frames were lost; ds = 0 is a repeat; ds 32768 to 65535 is backward. A wrap is therefore not a fault: seq 65535 followed by seq 0 gives ds = 1.

| Class | Rule and handling |
|---|---|
| fresh | Same boot_ctr and a forward seq (ds 1 to 32767). frames_lost = ds - 1, counted on fresh frames only. The rules of section 14 run. |
| reboot | boot_ctr advances by 1 to 127 modulo 256. The baseline resets to the new boot_ctr and seq, frames_lost = 0 (silence before a reboot is a gap, not packet loss), the node shows NODE REBOOTED and its link-loss state clears. The rules run. |
| duplicate | A byte-identical copy of an earlier (node_id, boot_ctr, seq) frame inside dedup_window_s = 5 s. Stored and flagged, never counted as lost, never evaluated, and excluded from v_readings. |
| suspect | Any other valid-MAC pattern: a backward seq (ds 32768 to 65535), a repeated seq that is not an in-window copy (ds = 0), boot_ctr moving backward (a step of 128 to 255), or a boot frame with an unchanged boot_ctr. Stored, shown grey and labelled suspect, frames_lost = 0, baseline unchanged. It cannot clear a latch, a level or link loss and cannot reset the shadow timer. Rev 3.22: the rules DO run on it in raise-only mode (14.1): its instantaneous triggers may open or escalate an alert, an episode or the displayed level, but it never clears, lowers, starts or advances a timer, or moves the baseline. |
| re-baseline | After rebaseline_clean_frames = 3 consecutive suspect frames that are mutually continuous (same boot_ctr, each a forward step of 1 to 32767 from the one before), the third is accepted as fresh with frames_lost = 0, the baseline moves to it, and "baseline re-established" is written to the host log. |

Classification changes how a frame is labelled and what it may clear, never whether it is stored or shown, and a suspect frame is never ignored: it is evaluated raise-only (14.1), so a valid-MAC node whose seq or boot_ctr regressed (for example when boot_ctr did not advance after a reboot because the NVS counter was unreadable) is not blind to a new alarm. The first verified frame ever seen from a node has no baseline: it is fresh, frames_lost = 0, and it sets the baseline. Frames with verify other than OK are not classified: they are stored with seq_class = suspect (GV-04) and never touch a baseline. Golden vectors GV-11 (wrap), GV-12 (reboot) and GV-13 (backward frames and re-baseline) are in 14.4.
