### 12.1 Shared contracts and generators

- shared/abi.json is the single machine-readable frame and beacon layout: field names, byte offsets, bit positions, lengths, enums. A generator writes components/abi/abi.h, host/ppe/abi.py and dashboard/src/gen/abi.ts. frames.json stays as the cross-check test vectors. The "confirm bit positions" item stays open until firmware, host and Summary table all pass the vectors against abi.json.

- The constants file is split into shared/constants.json (values used by more than one layer, including the firmware values of 11.2) and host/config/settings.json (host-only values such as commit_wait_ms). token_grace_h is deleted (4.1). The browser snapshot carries the whole of shared/constants.json after the split (the host-only keys of the move list are not in it), so the dashboard hard-codes no threshold or time.

- Normative key move list (Rev 3.27), applied by the generator. Host-only, moved to settings.json: commit_wait_ms, checkpoint_max_bytes, host_budget_ms, dashboard_budget_ms, recovering_target_s, session_resume_max_min, host_bat_warn_pct, host_disk_min_gb, task_stall_s, supervisor_restart_target_s, advisory_heartbeat_s, audio_check_interval_s, host_chime_interval_min, host_volume_min_pct, host_alarm_budget_ms, counters_interval_s. Deleted: shift_duration_h (no remaining use after tokens lost their expiry, Rev 3.28), retry_buffer_max, token_grace_h, token_expiry_warn_min, sound_check_interval_min, sound_check_amber_min (and the settings keys no_audio_alarm_s and, Rev 3.30, zero_socket_alarm_s). Added to shared/constants.json from the firmware (names fixed in Rev 3.40, values in the Section 12 block above, taken from the Technical Summary for Profile A): scba_confirm_s (300), scba_confirm_high_co_s (120), scba_response_s (20), resend_wait_ms (1650), node_min_send_gap_ms (500), evt_slot_ms (80), evt_jit_ms (10), beacon_period_s (4), lbt_backoff_min_ms (10) and lbt_backoff_max_ms (40); and for the dashboard unresolved_pulse_s (120) and unresolved_label_s (300), the times of the H11 chip. beacon_period_s, resend_wait_ms and the other derived times follow the same Profile A and B rule as the next paragraph. The generator test checks that every key above exists. The Section 12 JSON block is shown unsplit (before the move list is applied) and the move list above is normative; the generator test checks the real key counts of both files, so no count is quoted here.

- tools/gen_constants writes constants.h, constants.py and constants.ts. Derived times (link loss, silence, 5.5 s window) are computed from routine_period_s per profile (A, B = NTC duty-cycle). The generator must reproduce the current literals (15, 60, 5.5) exactly for Profile A, and a CI test enforces this. Profile B values are produced by the same formulas and reviewed once.

- CI check: regenerate everything and fail if git diff is not empty. The old statement "82 keys" is replaced by a test that the generated key count equals the file. Hashing for constants_hash/settings_hash still uses the canonical serialization of Section 1, over the two new files.
