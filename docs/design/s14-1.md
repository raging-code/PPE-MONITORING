## 14. Deterministic Rule Engine, Validity Classes, Advisory Table & Runtime Architecture (Rev 3.17)

14.1 Alert Lifecycle & Deterministic Rule State Table: Every rule runs on fresh verified frames (verify == 'OK' and seq_class in {'fresh', 'reboot'}) using the injected Clock(wall_ms, mono_ms). Raise-only rule (Rev 3.22): a frame with verify == 'OK' and seq_class == 'suspect' (flags level not 3) is also evaluated, but only for instantaneous triggers that raise or escalate: man_down and mayday (open or upgrade), co_threshold and scba_expired (open or escalate), sensor_fault (open or escalate), node_danger (open), battery_low (open) and checkin (open). A suspect frame never clears, lowers or de-escalates an alert, episode or level; never starts, advances or resets a duration or hysteresis timer (the clear timers, the heat timers, the co_range timer, the 15 s and 60 s silence timers and the shadow estimator); never counts toward link recovery; and never moves the baseline. The displayed node level is the maximum of the current level and the level the suspect frame produces. Frames with verify other than 'OK' and frames whose flags level is 3 are never evaluated (unauth_alert, GV-04, is the one exception). Level-escalating alerts (co_threshold, scba_expired and sensor_fault; sensor_fault is never lowered in place and clears when its fault bits clear) mutate their open alert row's level in place (resetting acknowledged_ts = NULL when escalating WARNING -> DANGER so the siren sounds) rather than creating duplicate cards (idx_alerts_one_open_per_node_type enforces one open row per node and type across all sessions, Section 11). De-escalation (Rev 3.20, Proposed) uses the same row: when the DANGER clear condition has held, the level is lowered to WARNING in place (acknowledged_ts is kept, so no new siren and no new card); when the WARNING clear condition has held, the alert is cleared (cleared_ts set), also directly from DANGER; a later re-escalation resets acknowledged_ts = NULL. The 10 s hysteresis timers count on fresh valid frames only and restart when the value rises back above the clear level. signal_lost (15 s silent after non-adverse frame) clears automatically when link_lost triggers at 60 s or when a fresh frame arrives.

14.1b Notice, badge and Tier 2 types (Proposed; triggers come from the Spec rows of 3.4 and bits of 3.10). All are level NONE: they never change a node level or open an episode. Unless stated, each is evaluated on fresh verified frames only and ends when its condition is false on the next such frame; the log line stays. Raise-once rule (Rev 3.32): a notice is raised on the frame where its condition becomes true and is not raised again while it stays true. wrist_open, button_stuck, missed_event and co_warmup are persistent: each holds at most one open alerts row per node (cleared_ts IS NULL), enforced by idx_alerts_one_open_per_node_type, and the row is cleared when the condition ends. After a restart or End shift the engine finds the open row by cleared_ts IS NULL and does not insert a second one. latch_restored, watchdog_recovery, node_reboot and suspect_frame are one-shot: raised once per event and not repeated while the same condition persists. A one-shot row is inserted with cleared_ts equal to raised_ts (cleared_event_seq may stay NULL, and v_full_log then uses event_seq), so it is never open and never appears in the open-alert lookups of recovery and End shift. The dashboard shows the one-shot badge from the alert message and the log line stays (Proposed: the dashboard does not depend on an open row).  
• wrist_open / wrist_close: status4 bit 0 (connector open) held for wrist_open_ms (200 ms) or more raises wrist_open; when the bit returns to 0 and is verified within wrist_close_confirm_s (2 s), wrist_close is logged and wrist_open ends. Hotspot marker and log only.  
• unauth_alert: a frame with verify == BAD_MAC whose flags claim an alert (GV-04). It is the one type raised from a non-OK frame; it shows as a dashed card until acknowledged and never changes the node level. Coalescing (Rev 3.20, Proposed): at most one open unauth_alert (cleared_ts IS NULL) per claimed node_id across ALL sessions (Rev 3.28). The type is outside the global open-alert index, so the rule engine enforces this: after End shift or a restart it finds the open card by cleared_ts IS NULL and does not insert a second one. While it is open, later qualifying frames insert no alert row; each is still stored as a diagnostic frame within the 20 per minute limit (frames over the limit are not stored and do not update the card). The host keeps an in-memory unauth_count and last_seen_ts that the alert WebSocket message carries, and the beep repeats every 10 s until Acknowledge. Acknowledge sets acknowledged_ts and cleared_ts together; the next qualifying frame then opens a new card (GV-10).  
• node_reboot: seq_class == reboot (boot_ctr changed). One-shot badge; if the node has an open MAN_DOWN episode it adds NODE REBOOTED WHILE MAN-DOWN to that card.  
• button_stuck: status3 bit 0 == 1 (button held over btn_stuck_s = 10 s); ends when the bit returns to 0.  
• missed_event: id_mode bit 7 (evt_unsent) == 1; ends when the bit returns to 0.  
• suspect_frame: seq_class == suspect on a frame with verify == OK, or a reserved status bit set. A frame with verify other than OK never raises it.  
• co_warmup: status3 bit 2 == 1 (co_warmup_s = 210 s); ends when the bit returns to 0.  
• co_rising: not implemented in Tier 1. The Spec gives the tag but no window or slope; it stays disabled until the adviser supplies them (Section 9, item 10), and even then only when co_rising_enabled is true in settings.json (default false).  
• latch_restored: status4 bit 1 == 1 only (the man-down latch was restored from storage and stays set until the jacket latch clear). One-shot badge when the bit goes 0 to 1.  
• watchdog_recovery: status3 bit 4 going 0 to 1 (restored after a watchdog, brown-out or unclean reset, for 60 s; status3 bits 5 to 6 give the cause) or id_mode bit 7 (evt_unsent) going 1 to 0 (uplink outage recovered). One-shot badge.  
• weak_signal: rssi or snr below the range-test floors; stays disabled until those floors are recorded (Section 9, item 10), and even then only when weak_signal_enabled is true in settings.json (default false).  
• estimate: Tier 2 only; forecast_5min_ppm of 150 or more within 5 min while CO is below 200 ppm and SCBA is OFF. Advisory only.
