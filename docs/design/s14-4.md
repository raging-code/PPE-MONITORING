Byte-level inputs (Rev 3.22). id_mode = node_id (bits 0 to 2, 1 to 7; 0 is invalid) + 0x08 if scba_on + posture x 0x10 + 0x40 if link_ok + 0x80 if evt_unsent. Node 1 with link_ok=1, SCBA OFF and upright posture is 0x41 and Node 2 is 0x42; 0x40 is node ID 0, which is not in the roster (node_id 1 to 3), so the host rejects and counts it and does not store it (F-20). The file shared/vectors/frames.json holds the complete 23-byte frames and 13-byte beacons below, built with the TEST key 000102030405060708090a0b0c0d0e0f and sys_id 0x5A (never provision them). Frame fields not named by a GV row are temp_x100=2500, hum=50, hr=0, motion=0, bat=80, status2=status3=status4=0, uptime_s=100, boot_ctr=7. temp_x100 is a signed 16-bit little-endian value (i16, degrees C x100, as in the Technical Summary frame table); every other multi-byte field is unsigned. -5.00 C is -500, bytes 0c fe, and a decoder that reads it as unsigned gets 65036 (F-24). CRC-8 is poly 0x07, init 0; mac4 is the first 4 bytes of AES-128-CMAC(key, sys_id + bytes 0 to 17); a beacon mac4 is CMAC(key, bytes 0 to 7). The firmware C tests and the host pytest read the same file and must agree on every entry (D1). Hex is lowercase, as in raw_hex. Schema (frames.json schema_version 2): every frame entry has id, gv, desc, hex and expect = {result, node_id, decoded}. result is one of OK, BAD_LEN, BAD_CRC, BAD_MAC (the frames.verify values) or REJECT_ROSTER (a valid frame from a node ID not in the roster, never stored); node_id is id_mode bits 0 to 2, or null for a wrong length; decoded holds every field of the 23-byte layout as integers (seq, co_x10, temp_x100, hum, hr, motion_x100, bat, status2, flags, id_mode, uptime_s, status3, status4, boot_ctr, scba_on, link_ok, evt_unsent), or null for a wrong length. Beacon entries have id, desc, hex and expect = {result, abi_ver}, with result OK, BAD_CRC, BAD_MAC or IGNORE_ABI.
