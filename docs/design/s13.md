### 13.1 Spec freeze and build plan

Spec freeze: Rev 3.45 is the last design revision before code (Rev 3.27 to 3.45 closed review findings, merged the Rev 3.26 overlay, in Rev 3.43 set the portable packaging rules and, in Rev 3.45, fixed the signedness of temp_x100; no new full revision is planned). After this, a design change needs a failing test or a bench finding as evidence (the audit-pass cycle of Rev 3.18 to 3.25 had diminishing returns). Changes go in a short ADR list (docs/adr/NNNN.md), not in new full revisions.

Build order (vertical slices; each ends with a runnable, tested result):

- S1 Repo, CI, generators (12.1) and the frame/beacon codec in C and Python, passing all 28 frame and beacon test vectors.

- S1b Node firmware (11.2): components/rules_fw (man-down, SCBA and MAYDAY state machines) and components/nvs_latch as pure C, tested on a PC with gcc in CI against frames.json and the D-FW scenario vectors; the first task of this slice is to write those scenario vectors as shared/vectors/fw_scenarios.json (same JSON style as frames.json; the file does not exist yet, frames.json does); then components/radio, sensors and ui on the bench, with task priorities, stack sizes and RadioLib settings tuned and recorded in 11.2. It ends with the D-FW tests passing in CI and a bench node whose frames pass the S1 codec; the end-to-end link is tested in S2. If the node firmware is already written elsewhere, record its repository and commit here and keep only the D-FW tests in this slice.

- S2 Base firmware to host serial ingest to SQLite (frames, verify, event_seq).

- S3 Pure rule engine (14.6) with the 27 golden vectors converted to pytest (GV-01 to GV-20 byte-level, GV-21 to GV-27 field-level and added in Rev 3.30). These vectors are hand-derived and unproven, so this is the first real test of them.

- S4 FastAPI, WebSocket and a minimal dashboard: node cards, alert tray, Acknowledge/Resolve, NO LIVE DATA.

- S5 Host alarm audio (3.12), supervisor, restart recovery, sessions.

- S6 CSV export, backup, purge-session.

- S7 Flat component grid is the shipped jacket view (3.13). Then REPLAY, 3D jacket and Tier 2, only if time remains.

- Cut line: S1, S1b and S2 to S5 are the Tier 1 trial minimum. S6 is required before real responder data is stored. S7 is optional.

### 13.2 Privacy and Windows checklist additions

- Disk encryption is required for the laptop and for every backup drive: BitLocker (Windows Pro) or Device Encryption; if neither is available, an encrypted VeraCrypt volume. Backups and CSV exports are written only to encrypted locations. Add these to Section 13.

- A one-page data-governance note (docs/data-governance.md) is required before real responder data is used. It names who holds the alias-to-person map, who may run purge-session, the retention period (the adviser's value from Section 9 item 3) and the RA 10173 contact. It is filled in during the pre-trial sign-off.
