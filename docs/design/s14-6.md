### 14.6 Rule engine as a pure core

The engine of 14.1 to 14.5 is implemented as step(state, event, now) returning (state, effects). It has no database, socket, clock or audio access. An outer shell reads frames and timers, calls step(), then applies the effects (insert rows, broadcast, play sound). Golden vectors, REPLAY and restart recovery all call the same step(). Property tests (Hypothesis) check: a suspect frame never clears or lowers an alert; at most one open alert per node and type; event_seq is strictly increasing; replaying the same frame list gives the same effects. Rebuild mode (Rev 3.40): the shell calls step() with a flag that makes it return the new state and an empty effects list, so recovery (section 1) cannot write, broadcast or sound anything; a property test checks that a rebuild over any frame list returns no effects and the same state as live processing of that list.
