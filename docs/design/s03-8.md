### 3.8 Host and dashboard interface (Proposed)

The summary leaves the backend and WebSocket framework open (implementation boundaries). These choices keep one language and one source of truth on each side:

| Layer | Choice | Why |
|---|---|---|
| Host API | FastAPI on Uvicorn | Runs on the host's asyncio loop (Spec: one Python asyncio process). Built-in WebSocket, and Pydantic models define every message once. |
| Live link | One JSON WebSocket for data (/ws), a second tick-only WebSocket for the Web Worker (/ws/tick, Spec), and REST for actions | Matches the summary's authenticated WebSocket and API. No broker: MQTT is only for several consumers (Tier 3, Spec). |
| Shared types | openapi-typescript builds the dashboard's TypeScript types from the host's OpenAPI | Dashboard and host cannot drift apart. The build fails if the generated types change unnoticed. |
| Dashboard | React, Vite, TypeScript, Tailwind, shadcn/ui, a Zustand store fed by the socket, Recharts, Three.js through React Three Fiber with the STL loader, Web Audio API, Web Worker | One stack. The first four come from Software Design 3.1 (not re-checked). The rest are added for state, the chart, the jacket, sound and the watchdog. |
| Tests | pytest (host), Vitest with Testing Library (dashboard units), Playwright (browser end-to-end) | One tool per layer. Playwright also drives the hidden-tab and blocked-socket cases of D8. |
| Rejected | Socket.IO, Flask, server-sent events alone | Socket.IO adds its own protocol and client. Flask is not async-native. Server-sent events are one-way and still need REST. |

Every message carries v (schema version = 1), type, srv_seq (per-connection monotonic counter assigned by that socket's sender task, starting at 0 on snapshot) and srv_ts (UTC ms). Field names follow the database columns, with units in the name (co_ppm = raw un-clamped ppm in DB/CSV; dashboard clamps display at co_clamp_max_ppm = 500.0). Origin and token rules are in section 4. Level values are uppercase on the wire and in the database: a node level is NORMAL, WARNING or DANGER and an alert level is NONE, WARNING or DANGER, so one TypeScript union per field serves both.

| Message | Direction | When | Main fields |
|---|---|---|---|
| auth | dashboard to host | First message on connect. Nothing is sent back until the token checks out; an invalid token closes the socket. | token |
| snapshot | host to dashboard | On connect and every reconnect, before any increment (Spec) | epoch, srv_seq=0, srv_ts, recovering, monitoring_active, session{session_id,started_ts,mode,session_label}, roster[], nodes[{node_id,alias,last_rx_ts,co_ppm,temp_c,hum_pct,motion_g,bat_pct,scba,mandown,level,link_state,status2,flags,id_mode,status3,status4,co_validity,co_reason,scba_correction}], open_alerts[], open_episodes[] (each with man_down_motion_state), co_history_30m{node_id:[[ts,ppm]]}, banners{base_offline,logging_fault,host_gap,host_power,audio_fault}, constants{the whole constants.json object: the dashboard reads every threshold and timing from here and hard-codes none} |
| reading | host to dashboard | Each verified frame | node_id, alias, rx_ts, co_ppm, co_over_range, co_validity, co_reason, temp_c, hum_pct, motion_g, posture, stillness_s, bat_pct, scba, mandown, level, reasons[], seq_class, rssi, snr, status2, flags, id_mode, status3, status4 (raw status bytes included so 3.10 hotspot fault mapping runs directly from reading) |
| alert | host to dashboard | Each raise, each clear, each in-place level change, each Acknowledge (of an alert, or of an episode, which sends one message per linked alert, also for an alert that already cleared), and each coalesced unauth_alert repeat (at most once per second) | alert_id, node_id (null for base-wide), type, level, reasons, authenticated, episode_id, raised_ts, cleared_ts, acknowledged_ts, acknowledged_by, unauth_count and last_seen_ts (unauth_alert only) |
| episode | host to dashboard | Opened, acknowledged, resolved, or MAN_DOWN motion-state change | episode_id, node_id, kind, state, man_down_motion_state, resolve_reason, operator |
| link | host to dashboard | Link state change | node_id, state (not connected, weak signal, signal lost, link lost, recovered), since_ts, last_state |
| system | host to dashboard | Base, recovery or session change, or a banner acknowledgement (BANNER_ACK) | base (ok or offline), recovering, session_id, session_mode, rejected_frames; logging_fault, host_gap (null, or {gap_s, reason} where reason is null or db_restored), host_power, audio_fault; on a banner acknowledgement: the banner kind and acknowledged_ts |
| advisory | host to dashboard | Each advisory | node_id, risk, reasons, action, quality, source |
| ml (Tier 2) | host to dashboard | Each scored frame | node_id, forecast_5min_ppm, early_warning, anomaly_unusual, cohb_low and cohb_high (null until the CFK gate closes) |
| tick | host to dashboard | 1 Hz, on both sockets | srv_ts (plus standard envelope v, type, srv_seq) |

Actions use REST with Authorization: Bearer <token> on every call (except POST /api/login), and every accepted or rejected action is written to audit_events. Because a Web Worker cannot access sessionStorage directly, the main thread passes {type:'INIT_AUTH', token, ws_tick_url} to the Web Worker via postMessage on login/reload; CSV export is triggered via authenticated fetch('/api/export.csv', {headers:{Authorization:'Bearer '+token}}) -> response.blob() -> URL.createObjectURL() rather than a plain <a href> link. Frozen Tier 1 REST Endpoints & Status Codes:  
• POST /api/login — Req: {token: str} -> 200 {operator_id, display_name, session_id} (logs LOGIN_OK) (ADR 0056 adds a name + PIN form; see the PIN login addendum at the end of this file) | 401 (logs LOGIN_REJECTED with exponential backoff up to 5 s) | 403 (logs ORIGIN_REJECTED).  
• POST /api/session/start — Req: {session_label?: str} -> 200 {session_id, started_ts, mode, monitoring_active: true} (sets operator_id if NULL, records monitoring_active=true, logs START_MONITORING; if monitoring_active is already true it returns the same 200 body and changes nothing: no second START_MONITORING row, and operator_id and session_label are kept, so a second tab can call it safely) | 401/403.  
• POST /api/session/end — Req: {confirm_text: 'END', session_id: int} -> 200 {closed_session_id, new_session_id, backup_ok} (calls atomic close_session('ENDED'): closes the old sessions row and opens the new one, carries monitoring_active; open alerts and episodes are untouched and keep their ids, so the dashboard keeps its cards without re-chiming, runs off-loop backup, logs END_SHIFT) | 400 | 409 (recovering=true, or STATE_CONFLICT when session_id is not the current open session, so a second tab pressing End shift changes nothing).  
• POST /api/alerts/{alert_id}/ack — Req: {} -> 200 {alert_id, acknowledged_ts, acknowledged_by} (succeeds even if cleared_ts IS NOT NULL; idempotent 200; logs ACK_ALERT) | 404.  
• POST /api/episodes/{episode_id}/ack — Req: {} -> 200 {episode_id, state: 'ACKNOWLEDGED', acknowledged_ts, acknowledged_by} (acknowledges episode and linked open alerts; logs ACK_EPISODE) | 404.  
• POST /api/episodes/{episode_id}/resolve — Req: {reason: 'rescued'|'false_alarm'|'device_removed'} -> 200 {episode_id, state: 'RESOLVED', resolved_ts, resolve_reason, resolved_by, latch_still_set: bool} (logs RESOLVE_EPISODE) | 400/422 | 404 | 409.  
• POST /api/system-banners/{kind}/ack — Req: {} (allowlist: 'host_gap' | 'logging_fault'; non-acknowledgeable banners return 400; unknown kinds return 404) -> 200 {kind, acknowledged_ts} (logs BANNER_ACK) | 400 | 404 | 409.  
• POST /api/scba-correction — Req: {node_id: int, note?: str} -> 200 {recorded_ts, operator} (logs SCBA_CORRECTION; is kept in live host state and re-applied after a restart from audit_events (2.10) without clearing node scba_expired or suppressing ambient CO alerts) | 404.  
• POST /api/dashboard-outage — Req: {started_ts: int, ended_ts: int, duration_s: float} -> 200 {logged: true} (the server checks ended_ts >= started_ts, neither time in the future, duration_s within 1 s of the difference and at most 86400, otherwise 422 VALIDATION_ERROR; logs DASHBOARD_OUTAGE).  
• GET /api/sessions — Query: ?limit=<int> (default 50) -> 200 [{session_id, started_ts, ended_ts, duration_s, mode, session_label, end_kind, alert_count, unresolved_episodes, highest_level_by_node}].  
• GET /api/events — Query: ?after_seq=<int> (default 0)&limit=<int> (default 200, at most 1000) -> 200 {events: [{event_seq, log_ts, record_type, node_id, level, code, detail, operator_id}], last_seq} (the rows of v_events (v_full_log without its frame branch, Section 11) with event_seq greater than after_seq, in event_seq order (the query adds ORDER BY event_seq, log_ts), without the frame measurement columns and raw_hex, and never a frame row, because the dashboard gets frames from reading messages and v_events avoids a scan of the whole frames table on every reload (Rev 3.41); a page never splits rows that share one event_seq, so it may hold a few more rows than limit; read-only connection in the thread pool; no audit row; it fills the dashboard event log after a reload) | 401/403 | 422.  
• GET /api/export.csv — Query: ?session_id=<int> (optional; omitted = every session in one file) -> 200 text/csv streaming v_full_log (logs CSV_EXPORT).

• Frozen WS Close Codes & REST Error Envelope: 4401 (unauthenticated/auth timeout -> clear sessionStorage & show Login), 4403 (Origin/Host rejected), 4408 (slow client >1 s send timeout -> auto-reconnect & reload snapshot), 1000 (clean shutdown); all 4xx/5xx REST responses return {"error_code":"<UPPER_SNAKE>","detail":"<message>","retry_after_s":<float|null>}.  
• REST error codes (Proposed; a test fails if a response carries a code outside this list): 400 BAD_REQUEST (wrong or missing confirm_text; banner kind that cannot be acknowledged); 401 UNAUTHENTICATED (missing, invalid or disabled-operator token; on POST /api/login retry_after_s is the current backoff delay); 403 ORIGIN_REJECTED; 404 NOT_FOUND (unknown alert, episode, banner kind or node); 409 RECOVERING (POST /api/session/end while recovering=true; retry_after_s = recovering_target_s) or STATE_CONFLICT (End shift for a session that is not the open session; resolve or banner acknowledge on an item that is already in the target state); 422 VALIDATION_ERROR (body fails the schema, for example a resolve reason outside the three allowed values); 500 INTERNAL_ERROR. retry_after_s is null for every other code.

PIN login addendum (ADR 0056, Proposed; Rev 3.45 itself is unchanged)
• PIN form of the login call (POST /api/login) — Req: {display_name: str, pin: str, remember: bool} -> 200 {operator_id, display_name, session_id, session_token, expires_ts} (logs LOGIN_OK, reason pin). The {token} form keeps its answer and returns no session_token. 401 UNAUTHENTICATED for an unknown name, a wrong PIN, an operator without a PIN and a disabled operator, with retry_after_s (1 s doubling to a cap of 5 s); after 5 consecutive failures the PIN form is locked for 15 minutes (logs LOGIN_LOCKED once). The token form is never locked. 403 as before.
• POST /api/logout — Req: none -> 200 {logged_out: bool} | 401 | 403. Revokes the login session of the bearer token (logs LOGOUT, reason session) and answers logged_out true. With an operator token there is nothing to revoke: the answer is still 200 with logged_out false (reason operator token). The call is the thirteenth endpoint of the list (ADR 0056).
• The session token travels where a token travels: Authorization: Bearer on REST and the first auth frame on /ws and /ws/tick. A session that is expired or revoked, or whose operator is disabled, gives 401 on REST and close 4401 on the sockets, and the dashboard clears sessionStorage and localStorage and shows Login.
• The dashboard keeps the session token in sessionStorage, or in localStorage when "remember me" is ticked (off by default). INIT_AUTH to the Web Worker is unchanged.
• No new error code and no new WebSocket message.

REPLAY pause addendum (ADR 0061, Proposed; Rev 3.45 itself is unchanged)
• POST /api/replay/pause — Req: {paused: bool} -> 200 {paused, finished} (sets the state, it does not toggle: asking for the state the replay already has changes nothing and writes no row; the first change logs REPLAY_PAUSE or REPLAY_RESUME; any logged-in operator may call it; pausing stops the scaled clock, so every timer of the host stops with the replay) | 401/403 | 409 (RECOVERING before the replay has started, retry_after_s = recovering_target_s; or STATE_CONFLICT on a host that is not in mode REPLAY and on a replay that has finished) | 422 (a body without a boolean paused). The call is the fourteenth endpoint of the list.
• The snapshot and the system message carry replay: {speed: int, paused: bool, finished: bool}, or null when the host is not in mode REPLAY. A change of paused or finished sends a system message (at once for a pause or resume; with the next 1 Hz tick for the end of the data). The field is optional for a client: a message without it means a host that is not replaying.
• No new error code and no new WebSocket message. Migration 0004 adds the two audit actions (audit_actions has 23 rows).

REPLAY speed addendum (ADR 0064, Proposed; Rev 3.45 itself is unchanged)
• POST /api/replay/speed — Req: {speed: 1|4|16} -> 200 {speed, paused, finished} (sets the speed, it does not step: asking for the speed the replay already has changes nothing and writes no row; a change logs REPLAY_SPEED with the reason '1x to 4x'; any logged-in operator may call it, also while the replay is paused, when the new speed counts from the resume; the scaled clock is re-based, so source time does not jump and every timer of the host goes on from where it was) | 401/403 | 409 (RECOVERING before the replay has started, retry_after_s = recovering_target_s; or STATE_CONFLICT on a host that is not in mode REPLAY and on a replay that has finished) | 422 (a body whose speed is not the whole number 1, 4 or 16). The call is the fifteenth endpoint of the list.
• The replay block of the snapshot and the system message already carries speed; a change of speed sends a system message at once. No new error code and no new WebSocket message. Migration 0005 adds one audit action (audit_actions has 24 rows).
• Dashboard (ADR 0062, S7-5b): while session.mode is REPLAY and the snapshot or system message carries replay, a dark neutral bar under the mode bar shows 'Replay running, ×N', 'Replay paused, ×N' or 'Replay finished' and one button, 'Pause replay' or 'Resume replay' (44 px or more), which posts the opposite of the state the host last reported. The button is disabled while a request is on its way, while the host is recovering and after the end of the data. The words follow the host's system messages, so every open screen agrees; a refusal is one sentence under the status.
